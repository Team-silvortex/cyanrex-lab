# SDK 稳定性政策

`@cyanrex/sdk-js` 是尚未达到 1.0 的内部包。兼容规则明确列出，使内部使用者能够安全升级，
并为未来独立发布做准备。

## 受保护的接口

以下接口受兼容性保护：

- `compatibility/public-surface.json` 记录的公开 `CyanrexClient` 根方法和面向任务的命名空间路径；
- OpenAPI 兼容基线表示的浏览器 operation ID、请求输入、成功响应和访问层级；
- 生成的 operation 输入／响应类型，以及 `/openapi` 和 `/operations` 包导出；
- `CyanrexApiError` 的状态、详情、方法、URL 和消息行为。

命名空间基线保护成员存在性和嵌套关系。OpenAPI 检查保护线上协议，编译时夹具保护具有代表性的
生成 operation 调用形式。

## 变更规则

1.0 之前每个次版本系列的补丁发布（包括 `0.4.x`）只能扩展受保护接口。可以增加可选字段、
operation、命名空间或方法；未经明确评审的破坏性发布，不得移除／重命名成员、将可选输入变为
必填、缩小可接受输入、削弱成功响应，或提高访问层级。

废弃受保护 SDK 成员时：

1. 在声明中标记 `@deprecated`，并在更新日志中说明替代接口；
2. 至少保留至完整的下一个次版本系列结束；
3. 仅在更晚的次版本发布中移除，并提供迁移说明和有意进行的基线更新。

例如，在 `0.4.x` 期间废弃的成员，须在整个 `0.4.x` 和完整 `0.5.x` 系列中可调用，最早可在
`0.6.0` 移除。严重安全问题可缩短窗口，但发布必须明确说明影响和安全迁移方法。

## 有意更新基线

常规质量门禁不会重写兼容基线。新增公开 SDK 成员经接受后，用下列命令将其加入后续移除保护：

```bash
node ../scripts/sdk-surface-compatibility.mjs --write-baseline
```

接受移除的基线更新只能属于已评审并记录迁移的破坏性发布。OpenAPI 基线替换使用
[SDK 使用说明](README.zh-CN.md)中的独立兼容命令。

## 尚未保证的范围

私有实现细节、内部请求的准确顺序、未文档化错误文本和五个签名 Runner Agent 协议操作，
不属于公开 SDK 兼容接口。注册表发布、长期支持责任和 1.0 标准仍是独立发布决策；
在这些条件明确之前，包保持私有。
