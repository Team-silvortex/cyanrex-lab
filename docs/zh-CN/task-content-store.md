源码版本 **0.5.5**（**2026-10-11**）已收录这些跟进；分日期的 `Unreleased`/未发布标记保留
当时实施阶段、源码版本和验证范围。源码收录不代表准备层 API 已挂载、浏览器保存已接通、
在线认证已切换、存储已迁移或运行实例已经验收。

状态：**0.5.0 收录的 C2-L 内部准备层**。决策日期：**2026-10-03**。
原切片将手工 Task 与[内容清单](task-content-manifest.md)一起持久化，支持受修订条件约束的编辑，
并原子记录对应事件。**这是可信内部存储，不是 Session 授权命令、已验证 Artifact 读取或浏览器保存流程。**

源码版本 0.5.4 上的 **2026-10-08 未发布跟进**为同一 Schema 3 内容存储增加显式目录定义准入。
原构造器仍只接受手工任务；不增加 Schema、迁移、评估器或公共保存端点。

## 独立的存储准入

`TaskContentStore` 从 `services::task_store` 导出，但与 `TaskStore` 是不同公开句柄。旧句柄固定
使用 Schema 2，新句柄要求 Schema 3；两者都需要显式指定专用命名空间，互不接管对方的记录。
安装器拒绝非空命名空间，不会给旧任务猜测默认清单。

两种存储复用有界事务、作用域和 Schema 检查，不复用内容读写逻辑。新句柄不暴露内部版本助手。
原有 Schema 2 Session 手工/输入/目录适配器仍构造 Schema 2 句柄，不能由此进入新内容存储。没有启动安装、
公共 API 改动、认证切换、自动迁移或降级。

新结构仍使用任务元数据、当前记录、outbox 三张表。每个内容任务和事件都有必填 manifest 列，
上限 64 KiB，与既有 Task 快照的 32 KiB 预算分开。核心 `TaskSnapshot` 和 `CoreSchemaVersion`
保持不变；存储 Schema 3 不代表产品版本 3。

## 内容与修订契约

`TaskContentSnapshot` 同时返回 `task` 和 `manifest`。创建时从一份经过校验的清单派生标题和有序
输入引用，以 Draft、修订 1 开始。手工创建不包含目录定义；显式目录创建则完整复制获准定义。
有标题的任务可以没有文本项；文件名和语言只是
元数据，不是路径、已安装工具、权限或执行指令。

| 操作 | 行为 |
|---|---|
| `create` | 仅手工句柄可用；显式稳定任务 ID 与可信所有者，重复 ID 返回冲突，不是成功重放 |
| `create_catalog` | 仅目录句柄可用；从冻结元数据选择准确定义引用，与清单一起保存 |
| `get` | 用有界只读可重复读快照读取任务与最新事件；不存在或属于他人的任务返回 none |
| `replace` | 要求预期任务修订与 Draft 状态，一次替换标题、标签和有序引用 |
| `transition` | 要求既有状态图允许转换且修订吻合，完整保留清单 |

只改标题、文件名或语言也会将**同一个 Task 修订增加一次**；内容重排、增加或移除项同理。完全相同
的清单作为无变化拒绝。过时修订、非法状态或修订溢出不能返回成功；定义、所有者、身份和创建时间
不在编辑范围内。

每次成功写入把任务和一条 outbox 事件原子提交，二者都保存完整 Task 与清单。事件区分
`cyanrex.task.created`、`cyanrex.task.content_updated`、`cyanrex.task.status_changed`，不把仅改
元数据误记为输入换版。旧事件不重写；outbox 记录仍不等于可靠投递、重放游标或通用历史恢复 API。

## 0.5.5 收录的目录内容准入

`TaskContentStore::from_definitions(pool, scope, &catalog)` 接收经过校验的 `TaskDefinitionCatalog`。
其 `create_catalog(id, owner, &definition_ref, manifest)` 从冻结目录选择元数据，不接收评估器
或调用方自报的定义正文。Task 标题、内容标签仍独立于定义的显示标题。存在的证据 Schema 与
评估策略版本继续作为元数据保留；本存储不执行规则，也不验证领域证据语义。

源码 0.5.4 上的 **2026-10-11 未发布多包跟进**允许同一构造器保留
`TaskDefinitionCatalog::compose` 的结果。不同包或版本的准确定义可共用一个显式内容工作区，
同包互不重叠的注册分片也可组合。组合拒绝所有完整引用重复，展平目录最多 256 个定义，嵌套输入
也受同一总上限约束。不合并存档、不升级定义，也不改变本存储的 Schema、模式检查或可信所有者
要求，详见[目录组合](task-domain-boundary.md)。

源码 0.5.4 上独立的 **2026-10-11 未发布评估绑定跟进**也接纳明确不绑定两项自动评估契约的
定义。两个 JSON 字段仍必须存在，缺少绑定用双 null 表示，不是漏字段或只绑定一项。
有绑定和无绑定定义可共用冻结目录；无绑定定义仍为 `Some(TaskDefinition)`，不改变手工/目录
模式隔离。完整定义检查将同编号下增加或移除绑定视为 `InvalidRecord`，即使任务头与事件相等
也拒绝。替换保留原绑定选择，不能升级或降级定义。

Schema 编号与旧已绑定 JSON 编码不变，不改写记录或迁移。新无绑定记录需要新读取器，旧二进制
会拒绝，不把它们当成手工工作。内部 Rust API 变化及不支持的降级边界见[定义契约](task-domain-boundary.md)。

`new(pool, scope)` 配合 `create` 仍只接纳没有定义的手工任务。对句柄调用错误的创建方法返回
`InvalidInput`；创建引用未知返回 `UnknownDefinition`。对当前所有者可见的存档，每个句柄都
要求匹配自己的模式：手工模式要求 `definition: None`，目录模式要求 `Some` 且与配置中的完整
准确定义相等。模式不符、定义条目缺失或同一编号下信息漂移，在读、编辑和状态转换时返回
`InvalidRecord`，即使任务头与 outbox 彼此一致也不接纳。不回退到最新版、不重新解释旧任务，
不将手工任务升级成目录任务，也不能通过内容编辑改变定义。

这是现有 Schema 上的句柄准入规则，不是 Schema 迁移。独立的[会话目录内容命令](session-task-content.md)
负责当前授权与文本校验；直接存储仍要求可信所有者，不读取 Artifact 字节。

## 校验与失败边界

读取核对命名空间、作用域、所有者、任务修订、清单结构、标题/引用准确对应，以及当前记录与最新
事件完整相等。写入先锁元数据，再锁任务行；等行锁后以独立语句读取事件。写入后重新核对完整预期
结果和 Schema。Task 与清单在从数据库取回超大文本之前就受限，不只依赖数据库约束。

这是链头一致性，不是全历史对账，也不能防御特权数据库操作者。一致不证明 Artifact 存在或正确：
形状合法的引用可以在没有正文时存入，直接调用方必须已经可信。该存储不执行 C2-K 文本字节检查，
不打开文件、不发布或删除 Artifact、不认证所有者，也不返回可复用授权凭据。

只有确认事务提交才发布成功。触发器抑制、读回失配或提交失败不能发布半次编辑。提交附近发生超时
或取消等待不证明已经回滚，不授权自动重试或清理独立发布的内容。

## 验证与下一步

独立默认测试及显式 PostgreSQL 测试覆盖接口边界、持久化、仅元数据修改、修订竞争及注入式存储
故障。CI runner 先核对每个精确用例名再执行。实际分日期结果和未覆盖项见[项目进度](project-status.md)，
不能由测试源码存在推断通过。

独立 [C2-M 会话适配器](session-task-content.md)现将存储操作借入认证源拥有的同一事务，核验
旧新 Artifact 文本并在提交前复核当前授权。直接存储仍是可信基础设施；[C2-N](task-content-http.md)
另加未挂载的 HTTP 适配，不提供 Session 签发或浏览器保存、重读、冲突处理。其既有手工工作区
及 C2-P–W 发布/观察路径不接受新的目录工作区。分享、Review 权限、执行和迁移仍是独立工作。

源码 0.5.4 上独立的 **2026-10-11 未发布 [C2-Y 适配](catalog-task-content-http.md)**显式将
HTTP 接到已有会话目录内容工作区。不把直接存储调用当成授权、不放宽完整定义相等，也不改
Schema 3。手动 HTTP 和 C2-P–W 仍只支持手动任务；目录路由同样未挂载，不签发 Session、
不自动合并、不接浏览器保存，也不迁移。
