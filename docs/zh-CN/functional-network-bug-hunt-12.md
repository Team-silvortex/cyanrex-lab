## 范围与发现

F36 设置 → 账号准入 → 发布屏障 → 策略/裁剪事务 → 缓存发布 → HTTP 确认，含 E59 历史、
E60 未读与溢出边界。真实 Axum 处理器使用合成会话和私有 Unix socket 上的一次性 PostgreSQL 16.15。
清除 `DATABASE_URL`；不使用部署数据、真实账号、在线 Engine，不操作 SSH/局域网/内核。

| 编号 | 证据 | 修复 |
|---|---|---|
| BH12-01 | 缺表、此前已降级、持久策略非法时，设置读取仍返回 `200`。 | HTTP 独立读取真实存储，不依赖运行时缓存。缺行仍是有效默认值；存储/解码/非法持久值返回通用 no-store `503`，不以缓存或默认值冒充成功。读取失败不锁定持久化、不发布默认缓存。 |
| BH12-02 | 发布屏障失败后仍保存成功；设置 SQL 错误返回 `400`，代码还会透传存储错误文本。 | 确认配置存储和屏障后，策略/裁剪在同一事务完成，再发布内存。未确认写入返回通用 `503`；明确 SQL 错误保留策略/历史/未读，可修复后重试。此前已降级不能静默保存或裁剪内存。 |
| BH12-03 | 保存等待本地缓存发布超出测试的 12 秒上界；成功 GET 缺少 no-store。 | 复用 10 秒服务等待与已交接 SQL 任务顺序；超时/取消不等于回滚。成功及处理器错误不缓存；JSON 语法、超大请求体、内容类型、字段/类型错误保留 400/413/415/422，统一通用 JSON。 |

旧公开设置帮助函数仍保留运行时缓存/尽力降级；两条保存路径共用事务和原子内存发布逻辑。
成功结构、50..50000 请求截断、会话所有权、CSRF 和 SDK 签名不变；未知请求字段继续忽略，不能
覆盖账号。没有新增数据库迁移、路由、权限层级，也没有修改前端产品源码。

## 限制与下一块

- `503`、取消或丢失响应表示**未确认，不是回滚**。测试刻意阻塞提交后的缓存发布，验证超时后
  仍可完成；另一测试在提交前阻塞 DELETE 并观察回滚，不能推广为所有超时都会回滚。
  必须先核实再手动重试，未新增自动重试。
- 10 秒仅限制服务层协作式等待，不包含认证/请求体提取/序列化、CPU 停滞或后台任务寿命。
  已交接任务等待缓存锁时仍持有账号准入。原有写任务/屏障/存储失败可能锁定降级，修复重启不对账。
- HTTP 读取不更新运行时策略缓存，也不保证外部 SQL 写入一致性；旧发布仍可使用缓存/默认策略。
  显式纯内存成功仍易失；只协调同 EventBus 克隆，不协调多 Engine；新对象重读不是进程崩溃恢复。
- 未运行在线浏览器到 Engine、远端 CI、可选浏览器套件、Rust 依赖审计、新 benchmark、
  部署/局域网/内核或发布包验收。
