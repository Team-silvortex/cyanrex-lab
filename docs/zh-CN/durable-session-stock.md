# 持久 Session 存量限制

于 **2026-10-15** 收录至 **0.6.0** 源码，见[发布验证](../../reports/releases/0.6.0/README.md)。
下列日期说明保留原实施范围，不是新的部署验收。

2026-10-13 的 0.5.9 之后未发布跟进，在[平台宿主提案 3](https://github.com/Team-silvortex/cyanrex-lab/issues/3)
下新增显式限制存量的登录准备入口。这是可信 Rust API，不是公开登录路由，也不启动宿主。
[Session 生命周期路由](platform-session-lifecycle.md)仍未挂载，只查询当前认证或确认精确退出。

## 显式配置

`SessionStockLimits::new(per_account, total)` 接受单账号 1–64、整个认证源 1–4096 的上限，
单账号上限不能高于总上限。非法配置返回 `DurableAuthError::InvalidInput`。
两个值均为 `u16`，只有只读 getter；策略没有默认值、请求反序列化、环境查询或安装副作用。

可信组合方将策略传给
`DurableAuthSource::login_with_session_limits(username, password, otp, limits)`。
原认证源、密码工作准入、尝试窗口、准确账号 incarnation、凭据核对、原子 OTP 消费、原
namespace／关系 pin 和确认提交均保留。不授予教学角色或可复用的资源权限。

原准备层 `login` 行为不变，不强制这一存量策略；现用教学 AuthService 也不变。
未来宿主必须显式使用受限入口，统一经审阅的策略并隔离其他写者。
这不是持久 Schema 配额，不约束直接 SQL 写者，也不是跨无关认证源或不同策略的进程总预算。

## 哪些记录占用名额

总存量统计**准确原认证源命名空间中全部持久 Session 行**，包括过期、孤立或畸形记录。
单账号按准确 `account_id` 统计，不按用户名、角色或给定快照统计。
计数不读取 token 摘要、密码、OTP secret 或时间戳正文，也不把过期／无效记录过滤掉。

每次 SQL 聚合只投影配置阈值加一条以内的计数。总数有界检查之后，账号谓词在原 Source
写者栅栏内搜索同一认证源。这限制计数投影及正常配合写者下的工作范围；不保证无关写者、
历史存量、表膨胀或不可信数据库操作者下的数据库大小或查询耗时。

满额在 OTP 消费或 Session 插入之前返回原 `RateLimited`。该错误也表示既有密码工作和
尝试准入限制，不是公开配额诊断。登录不删除旧设备，也不自动清理过期 Session。
容量只能通过显式确认退出或原可信有界维护操作释放；损坏的维护候选不被静默修复或丢弃。

## 事务防护

只有新受限入口在第二笔写者事务的任何读取之前显式设置 `READ COMMITTED`。
即使数据库默认 repeatable read，等待原 Source 栅栏后也不能沿用旧存量快照。
操作不将只读数据库角色或连接强行切换为可写。

核对当前凭据并准备 OTP 消费之后、原 compare-and-update 消费之前，先检查可用名额。
消费及插入之后，受限入口执行 `SET CONSTRAINTS ALL IMMEDIATE`，再核原 Source pin、
完整凭据、水位和准确新 Session。把已排队的延迟工作提前处理，不只依赖提交时效果；
这不防护特权触发器重设或其他写者。

最终总数和账号数均须等于原计数加一，并且不超过上限。意外净数量变化或越界返回
`StorageUnavailable`，不返回 token。最后一项 SQL 检查之后只执行原纯 OTP 复核和确认
COMMIT，不再插入 SQL。计数只证明该数量变化，不证明其他每行完整性，也不穷尽所有
特权数据库副作用。

超时、取消或丢失提交确认仍不证明回滚。没有自动重试、OTP 重置、token 收编、存储迁移
或隐藏清理回退。

## 验证与剩余工作

默认策略测试覆盖显式值、两类支持边界、非法上限及账号上限大于总上限。
一次性 SQL 回归使用真实准备层注册、原登录事务与私有测试时钟，覆盖满额不消费 OTP、
显式释放容量、持久无效／过期行、写后故障以及独立认证源竞争最后一个名额。
失败快照仅保存私有 SQL 摘要和计数。

显式配置一次性 `CYANREX_TEST_DATABASE_URL` 后运行独立 SQL 库存：

```bash
./scripts/test-durable-session-stock.sh
```

运行器核对每个精确测试选择器。CI 使用已有一次性 PostgreSQL 服务执行它及此前的
Session 生命周期 SQL 套件。两套测试都不得指向应用数据；测试不等于平台已挂载、公开
签发器已可用或局域网已部署。

入口／速率策略、时序披露、安全秘密交付、不确定提交处理、实际低权限宿主组合与传输
验收仍是公开登录之前的独立门槛。Schema 2、原准备层登录、现用教学认证、UI、SDK 和
OpenAPI 均不改变。
