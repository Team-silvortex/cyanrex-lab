# ADR-018 会话授权的私人制品

状态：**C2-F 已收录于源码版本 0.4.8**。决定日期：**2026-10-03**。

当前持久 Session 现在可以授权成员创建、修订和读取自己的 Artifact。来源事务核对身份/成员关系、
操作元数据与事件，再复核 Session，确认提交后才返回元数据或内容字节。私人工作授权不依赖教学角色、
任务类型或 Run；这不代表公共上传、共享、认证 Review、任务验收、在线认证切换或迁移已开放。
本切片收录于源码版本 0.4.8。

## 配置与操作

可信服务端组合调用 `DurableAuthSource::open_artifact_workspace(namespace, scope, root)`，按
[ArtifactStore 的文件规则](artifact-revision-store.md)打开已有 Unix 私有目录，不创建目录、改变
权限、查询数据库或安装 Schema。返回的 `SessionArtifactWorkspace` 字段私有且不可反序列化。
命名空间、Workspace 与已打开的目录必须来自服务器配置，不是请求中的路径或自报所有者。授权命令
只调用存储的借用事务方法，不从存储句柄自己的连接池获取连接。

来源账号/Session 和 C1 注册表仍在同一个私有 Schema，Artifact 元数据在同一数据库的另一显式
Schema；两者都必须提前初始化。操作使用来源连接，不自动认领、升级或修复任一命名空间。

| 来源命令 | Session 和配置以外的输入 | 确认提交后的结果 |
|---|---|---|
| `create_session_artifact` | 制品 ID、版本 ID、有界 `ArtifactDraft` | 首个不可变版本 |
| `revise_session_artifact` | 准确当前父版本、新版本 ID、草稿 | 新版本；旧字节保留 |
| `read_session_artifact` | 包含摘要的准确 `ArtifactRef` | 所属版本和校验后的字节，或空 |

所有者、摘要、序号、父版本和发布元数据均由服务器确定。知道他人的 ID 或摘要不能获得访问权；他人
文件丢失也不能把所有权拒绝变成文件错误。相同内容不通过全局去重扩大权限。草稿沿用单版本 1 MiB
及元数据上限，但这不是总磁盘配额。

## 共享私人工作授权

Task 与 Artifact 现在共用 crate 内部的 `private_work` 检查，保持 C2-E 的准确账号代次、经审计且
活跃的 Human、活跃 Workspace 和活跃成员策略。私人工作不要求教师角色或部署 Grant；这些角色也
不授予他人内容的访问权。未绑定、停用、退役、过期、退出或审计不一致均拒绝，同名重建不继承旧所有权。

共享检查保留命名空间名称/OID、来源关系校验，以及“来源 → 注册表元数据 → authority → 资源元数据/
头指针”的锁顺序。读取也持有 authority 锁，同一 authority 的这些命令会串行。资源操作完成后，核对
目标命名空间，恢复并核对来源，再查身份/成员，最后使用数据库的新鲜时间验证准确 Session。外层确认
提交后才返回待发布结果，不把单独 `validate_session` 得到的快照当成后续事务权限。

借用事务的 Artifact 读取先锁头指针再查询版本与事件。来源事务是 READ COMMITTED，若直接沿用独立
读取器的无锁方式，修订期间的多条语句可能混读新旧状态。直接可信存储读取仍使用原来的只读可重复读
快照。新版本提交后，准确的历史引用仍能读取旧字节；不存在浮动 `latest` 或缓存授权。读取等待期间
过期的 Session 不能收到已经准备好的内容。

## 文件与数据库发布

这**不是文件系统和数据库的原子事务**。新文件创建前先检查授权、作用域、已知所有者/类型/父版本
和 ID 唯一性。发布保留排他私有文件创建、同步、摘要及回读校验、元数据/outbox 检查与不可变历史，
之后才进行来源复核和提交。搜索路径修改限于事务，成功、失败或取消后不能遗留在来源连接池中。

文件写出后若事件、最终授权或延迟提交失败，可能留下没有已提交元数据的文件；读取不能接管它，也不能
绕过元数据和当前权限返回内容。取消后阻塞文件线程可能继续运行，10 秒异步时限不会终止它。数据库
失败不授权覆盖、删除、接管或重试这些文件；测试明确验证“元数据回滚、文件保留”，不伪称文件回滚。

超时、取消或丢失提交确认不证明回滚。当前没有命令回执、自动重试、垃圾回收、恢复、总配额、全局事件
交付或崩溃/磁盘耗尽保证。目录替换和内容损坏明确失败；这些检查不能防御同 UID/宿主特权操作者，
也不是完整数据库 Schema 或历史证明。

## 验证与下一边界

3 条默认测试覆盖显式配置、危险目录拒绝且不修复、来源不可用不写文件及禁止分离认证/在线组合。
18 条 PostgreSQL 用例覆盖准确历史、跨所有者/作用域/摘要隔离、并发修订与 ID 冲突、未绑定/退出/
退役/同名重建、Schema/审计拒绝、事件与延迟提交失败、写后权限变化、RLS/临时遮蔽、合法克隆
命名空间替换、目录/内容损坏、两种退出顺序、读写等待过期、取消、成员撤权、连接池恢复以及等待可信
修订的精确读取。

`scripts/test-session-artifact-storage.sh` 在显式一次性数据库上逐条核对测试名称后运行，CI 使用
同一脚本并检查完整清单。禁止对已部署数据故障注入。实际执行结果和未跑检查见[项目状态](project-status.md)。

直接可信的 ArtifactStore/TaskStore 写入仍未设置在线切换栅栏，既有事件不能证明全部操作都经过了
Session 授权。Task 命令仍拒绝 Artifact 输入和领域定义；ReviewStore 仍信任调用方来源，不校验证据
访问权。下一步在 Task/Review 事务中组合准确引用权限，并建立审阅者/来源权限与验收策略。先调用本次
读取 API、稍后另起事务写 Review，仍存在检查与使用分离的问题。跨用户协作、公共 HTTP/CSRF/UI、
离线迁移和保留策略是独立关口；C2 与 C-M2/C-M5 尚未整体验收。
