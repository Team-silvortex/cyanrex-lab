# 学生快速开始

## 1. 启动系统

在项目目录执行：

```bash
./start.sh start --mode auto
```

第一次启动需要下载镜像和依赖，时间会比后续启动长。启动完成后打开：

- 前端：`http://localhost:3000`
- Engine 健康检查：`http://localhost:8080/health`

登录信息由启动器随机生成并保存在 `docker/.env`。将其中的
`CYANREX_ADMIN_TOTP_SECRET` 作为 Base32 密钥导入认证器，然后使用当前六位动态码登录。
不要把该文件或密钥发送给别人。

## 2. 认识界面

- **Dashboard**：查看系统概况；
- **eBPF**：编写、检查、运行和卸载程序；
- **Environment Helper**：检查内核、BTF、bpftool 和挂载点；
- **Events**：查看内核事件与平台诊断；
- **Modules**：管理教学模块和 C 头文件；
- **Scripts**：eBPF 页面中的脚本保存区；
- **Account**：修改密码和管理账户。

桌面端侧栏在滚动时保持可用；窄屏点击“导航菜单”展开，按 Escape 关闭并将焦点返回菜单按钮。
导航仍按账号角色显示。键盘操作可通过“跳到主要内容”跳过导航链接。

学习中心优先显示实验进度与编辑器入口；顶部的分区链接可以直接跳到“我的实验记录”或
“学习资料”，无需逐张滚过卡片。

### 重要操作先确认

运行、卸载、删除脚本和替换草稿会先展示目标及影响。“取消”默认获得焦点；执行前按 Escape 可取消，
点击弹窗外部不会执行或关闭。切换模板、加载脚本、导入文件必须确认后才替换草稿（相同源码无需
再次替换）；保存脚本和展开信息仍可直接操作。运行确认独立于源码替换，展示后端、实验/模板和源码。
进入实验会保留草稿，需明确点击“加载实验模板”。切换页面也会丢弃之前已确认导入的过期文件读取结果，
避免其覆盖另一个实验的草稿。
切换远程编译 Agent 还会提示自动诊断将把当前源码及后续编辑发送给该节点；切回本地无需再次确认。

“全部卸载”需输入 `DETACH`，作用于执行时当前账号的全部挂载，不是显示清单的固定快照。
单项卸载缺少路径时绝不退化为全部卸载。删除事件需输入 `DELETE` 并核对完整筛选及绝对截止时间；
删除的是所有匹配记录，不限于页面显示的最近 200 条。请先导出重要事件。

执行中阻止重复提交和关闭弹窗；失败不会自动重试。请关闭错误提示、核对实际状态，再按需重新发起确认。
离开页面不能撤销已发出的工作。删除账号仍需账号密码、OTP 和 `DELETE` 校验，再进行最终确认。
这些 UI 保护不是授权边界，也不是撤销功能。

## 3. 编辑器能力

吸顶操作栏集中放置脚本标题、“导入文件”“保存脚本”和“编译并运行”。源码、诊断和结果放在
主列，宽屏右侧提供运行/编译设置与挂载清理；较小屏幕可用“运行配置”和“返回源码”快速往返，
点击“结果”直接到编辑器下方的输出区。长日志在限定高度的面板内滚动。
保存的脚本、内联元数据、注入头文件和断点详情按需展开，不会重建编辑器或替换草稿；
改变布局和展开这些分区都不会运行代码。

编辑器不只是高亮文本：

- 停止输入约 700ms 后执行真实 clang 检查；
- 红色波浪线表示错误，黄色表示警告；
- 输入 `ctx->` 可获得真实结构体字段补全；
- `Ctrl/Cmd + 单击`可跳转到当前文件中的函数定义；
- Quick Fix 可以补充常见头文件和 GPL license；
- Outline 可以查看 hook、函数和 Map。

clang 状态含义：

- `checking`：正在检查；
- `passed`：语法检查通过；
- `issues`：存在编译错误；
- `unavailable`：后端不可用或当前账户无权检查。

### 源码断点

点击编辑器行号左侧或按 `F9` 切换断点，然后点击“编译并运行”。内核中的 eBPF 程序不能像
普通用户态进程那样安全暂停，所以 Cyanrex 使用不会阻塞内核的 `bpf_printk` 跟踪探针模拟
源码断点。红点表示已请求的断点，黄色标记表示事件流最近命中的位置。

结果区会列出已插桩和被拒绝的行。注释、预处理指令、全局声明以及不安全的多行表达式位置
不会插桩；每次运行最多安装 16 个探针。源码需要提供 `bpf_printk`，通常应包含
`#include <bpf/bpf_helpers.h>`。如果插桩代码编译失败，系统会自动使用原始源码重试，并明确
报告断点未安装。

断点命中属于采样事件，并非执行次数的精确证明：热点行的实际执行次数可能高于界面显示，
程序没有挂载或触发时也不会产生命中。

## 4. 一次完整实验

1. 打开学习中心选择实验，卡片会显示未开始、进行中或已完成；
2. 点击“在编辑器中打开”，携带实验上下文但保留当前草稿；需要从指定模板开始时，点击
   “加载实验模板”并确认替换；
3. 打开环境助手执行检查，然后返回编辑器阅读源码并预测结果；
4. 等待 clang 状态变成 `passed`，点击“编译并运行”；
5. 分别检查 compile、load、attach 阶段，并阅读自动验收反馈；
6. 在事件中心观察输出，返回 eBPF 页面卸载程序并确认挂载列表为空；
7. 回到学习中心确认进度。

失败运行同样会记录为尝试，便于学生和教师观察改进过程。自动完成只验证运行部分，原理题
仍需课堂讨论或教师检查。

学习中心下方的“我的实验记录”会按时间倒序展示每次提交的运行阶段、自动反馈和原始源码，
如有教师评语，也会显示评语作者与修改时间。点击“刷新”查看新评语，或“加载更多记录”回看
较早的尝试。评语不会改变自动验收状态；学生只能读取自己的记录，不能写入或修改教师评语。

点击“从这次提交继续”，可以接着该次提交修改，而不是重新载入实验模板。编辑器按当前登录
账号读取原始源码和最新教师评语；链接只含实验和提交 ID，不含源码或用户名。先查看预览，如需
保留当前草稿请先保存，再明确点击“替换当前草稿并继续”。这会恢复源码及原实验/模板上下文，
清除旧运行结果与源码断点，但不改运行设置或已存在的挂载。

点击“保留当前草稿”、请求失败或链接无效/不匹配，都不会覆盖编辑器代码；临时失败后可以
“重试加载”。切换链接会取消并丢弃旧请求，刷新页面会重新要求确认。实验模板不会覆盖等待确认
或已载入的提交；模板已移除时会标明不可用，不会自动换成别的模板。载入不会执行、挂载、卸载
或新增尝试，也不会改教师评语；自动 Clang 诊断仍按原逻辑工作。检查并修改源码后，再手动点击
“编译并运行”，在原实验下新增尝试，旧记录保持不变。已停用的实验需要先选择当前支持的实验
上下文，才能成功运行。

## 5. 实验纪律

- 不要删除自己无法解释的 bpffs 文件；
- 不要把 Engine 端口暴露到公共网络；
- 不要无限提高采样率或事件保留量；
- 不要运行来源不明的 eBPF 程序；
- 每个实验结束都要卸载程序。

eBPF verifier 能阻止大量非法内存访问，但它不是允许随意运行未知内核代码的理由。
