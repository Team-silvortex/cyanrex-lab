  43 项公共工具回归，以及 Runner Agent 和分发工具检查。
- 生产 npm 依赖审计与 RustSec 审计通过，未报告漏洞。

本地快照没有启动特权 Engine，也没有运行会操作临时 Docker 栈的离线安装冒烟。注解 Tag 候选
流程现在会启用发行包中的真实 Aya 挂载、ring-buffer 事件与精确 detach 检查，并保留绑定候选
产物的报告；其结果属于环境级证据，不计入上面列出的本地通过项。发行包内验证器无需内核权限，
即可复查 v1/v2 模式、发行元数据绑定、事件身份和清理结果；仓库侧验证器还能在不解包的情况下
复验整个下载制品，并能在不调用 `tar`、不覆盖已有输出的前提下只写出验证过的普通文件。

## 事件性能与恢复增量（2026-09-08，收录于 0.3.4）

- 使用 FIFO 双端队列避免满历史头部搬移，有限快照先筛选引用再复制结果，并增加隔离的 release
  基准。历史基准保留采集时的源码/版本指纹，不随 patch 升版重写，也不作为发行制品验收证据。
- WebSocket lag 改为显式关闭，阻塞发送超时回收；两个浏览器消费者支持有界快照、旧请求作废、
  自动重连及持续可见的缺口提示，恢复范围仅限仍保留的最近历史。
- 携带会话的 WebSocket 握手也检查 Origin/Referer，原生客户端需提供允许的来源。
  兼容要求和限制见[事件流恢复](event-stream.md)。
- 另行通过九轮真实回环压力测试，以及使用模拟 HTTP/WebSocket 的 Chromium 生产页面冒烟。
  全局广播分发优化和持久化游标重放仍待后续推进。
- 修复 Docker 构建输入遗漏及 npm 审计瞬态失败的有限重试处理。

## 主动保留的边界

- 特权 Engine 面向可信自部署教学环境，不面向公网多租户。
- 本地执行共享同一个 Linux 内核；配额是资源控制，不等于学生隔离。
- Engine 仍是单进程。Agent 注册、远程作业、挂载和模块生命周期尚无多副本协调模型。
- Aya 当前覆盖已支持的 tracepoint 路径，bpftool 仍是兼容性最广的路径。
- 远程 Agent 只编译和诊断，`/ebpf/run` 仍在本地执行。

## 下一阶段决策点

1. 在把仅状态控制的模块目录扩展为进程或动态库插件前，先定义签名、真实隔离、可执行适配器与
   持久化所有权模型。
2. 在将 SDK 作为稳定、独立消费的软件包发布前，明确 Registry 发布、支持责任与 1.0 就绪标准。
3. 按桌面/局域网隔离目标补齐完整运行边界、持久化环境归属和 VM 恢复，再开启远程 eBPF 执行或
   Engine 多副本。
4. 在明确发布信任链与密钥归属后，对已验收候选产物签名并自动发布。
5. 收集首个注解 Tag 的真实内核验收证据，再决定是否需要在 GitHub 托管的特权 Docker 环境之外
   增加专用、自托管的多内核版本矩阵。

`engine/Cargo.toml` 是正式版本的唯一基准；`scripts/check-version-sync.sh` 会阻止前端、SDK、
OpenAPI 文档、锁文件和面向发布的文档再次漂移。
