本文是 Cyanrex Lab 的能力级进度基线，用来说明目前可用的内容、主动保留的限制，以及下一阶段需要

测试、16 条 SDK 测试，以及前端生产构建、TypeScript 和 SDK 类型/打包检查。前端生产依赖审计
报告 1 项 DOMPurify 低危告警（GHSA-p98j-92pf-mc4p），没有中危/高危/严重项；SDK 无告警。

  旧意见不变，也不推进 Task 状态。归属仍是可信输入，不是认证或已验证证据。
- [ADR-017 / C2-E](session-task-commands.md)将当前 Session、经审计的活跃成员与私人手工 Task/事件
  组合为同一来源事务。所有者由服务器解析，不依赖教师或部署角色，也不授权访问他人任务；退出、
  过期、退役及同名重建均受检查。
- [ADR-018 / C2-F](session-artifact-commands.md)增加当前 Session 授权的私人 Artifact 创建、
  修订和精确读取，与 Task 共用授权检查，读取锁住版本头，最终复核与确认提交后才返回字节。数据库
  发布失败可能保留私有文件，不自动清理或接管。Task 引用/Review 授权、旧写入栅栏、验收、公共工作流、
  保留策略及迁移仍待完成，没有切换在线认证或迁移真实数据。
- 2026-10-03 发布验收通过上文完整本地质量门禁；默认 Rust 执行不包含 324 条 opt-in 用例。
  另有 18 条会话制品、17 条会话任务、17 条 Review、17 条 Artifact 和 15 条 Task 数据库用例
  在一次性 PostgreSQL 16 上按 CI 精确脚本通过；14 条认证源与 16 条会话协作命令也按对应 CI
  步骤脚本体通过，共 114 条数据库用例。C2-F 新增 3 条默认、18 条数据库及 1 条 CI 清单回归。
  本轮未重跑其余 opt-in 数据库/真实内核测试、远程 CI、崩溃/磁盘耗尽恢复或部署实例检查；数据库

## 学习记录流式提交增量（2026-09-08，收录于 0.3.5）

## 用户级事件分发增量（2026-09-08，收录于 0.3.5）

- `/ws/events` 按已认证会话用户建立有界实时队列，他人的突发流量不能挤掉本人排队事件；

  并发重连时旧连接误删新队列的竞态。
- 新增 10 项回归，完整安全门禁通过。最终完成 30 轮 release 实验：24 轮当前分发路径对比、
  6 轮无订阅者二进制前后对照。在匹配输出一致时，单用户服务/数据帧构造吞吐提升约 24%–64%，
  8 用户提升约 40%–56%；另有 9 轮真实回环检查确认交付、显式过载和约 5 秒的慢连接清理。

- 以上是本机合成基准，不代表局域网/内核或发行验收。容量按活跃用户计算，队列和 JSON 缓存

## 主动保留的边界

- 特权 Engine 面向可信自部署教学环境，不面向公网多租户。
- 本地执行共享同一个 Linux 内核；配额是资源控制，不等于学生隔离。
- Engine 仍是单进程。Agent 注册、远程作业、挂载和模块生命周期尚无多副本协调模型。
- Aya 当前覆盖已支持的 tracepoint 路径，bpftool 仍是兼容性最广的路径。
- 远程 Agent 只编译和诊断，`/ebpf/run` 仍在本地执行。

## 下一阶段决策点

1. 在把仅状态控制的模块目录扩展为进程或动态库插件前，先定义签名、真实隔离、可执行适配器与
   持久化所有权模型。
2. 在将 SDK 作为稳定、独立消费的软件包发布前，明确 Registry 发布、支持责任与 1.0 就绪标准。
3. 按桌面/局域网隔离目标补齐完整运行边界、持久化环境归属和 VM 恢复，再开启远程 eBPF 执行或
   Engine 多副本。
4. 在明确发布信任链与密钥归属后，对已验收候选产物签名并自动发布。
5. 收集首个注解 Tag 的真实内核验收证据，再决定是否需要在 GitHub 托管的特权 Docker 环境之外
   增加专用、自托管的多内核版本矩阵。

`engine/Cargo.toml` 是正式版本的唯一基准；`scripts/check-version-sync.sh` 会阻止前端、SDK、
OpenAPI 文档、锁文件和面向发布的文档再次漂移。
