## 显式受信任接口

[`FileUploadStore`](../../engine/src/services/file_upload_store/mod.rs)冻结显式提供的连接池、
工作区、随机安装 UUID、私有命名空间和 `FileUploadLimits`。构造不进行 IO。
`install_empty_namespace` 仅显式在空私有命名空间安装 Schema 1；拒绝已有关系、函数和类型。
没有启动安装器，也没有迁移或回退。

| 操作 | 确认的含义 | 不提供 |
|---|---|---|
| `reserve(upload_id, owner, account_id, manifest)` | 不可变意图与逻辑字节/条数预留一同提交 | 文件字节、分块回执、当前权限、物理磁盘分配或发布 |
| `get(upload_id, owner, account_id)` | 准确 Principal 和账号代次的当前预留，或不存在 | 历史提交来源、全账本健康、续传、重试或接收者访问 |

清单工作区必须匹配，所提供 Principal 的 authority 必须匹配存储。
`LegacyAccountId` 绑定账号代次；合法但不同的所有者/代次读取为不存在。
这些是受信任过滤检查，**不是 Session 认证**；没有不受信任适配器调用此存储。
私有类型预留仅暴露元数据 getter，不暴露路径、字节或恢复构造器。

## 预留核算

限额在构造时冻结，并写入 Schema 标记。变化会被拒绝，不会被收编成配置更新。
全局和每 Principal 字节预算可以为零；条数预算必须为正，最多 **256 条意图**。
协议总声明长度上限为 **16 TiB**，不代表磁盘实际有这些空间，或操作系统已预分配空间。

核算从校验后的清单推导长度，并检查算术溢出。空文件仍占一条。
所有保留记录无限期占用预留：没有 TTL、账号删除释放、取消、配额释放或清理。
每 Principal 的额度合计**同一 Principal 的所有已记录账号代次**。重建同名账号获得新 Principal，
有独立主体额度；旧记录仍占工作区总额度。
重复 `FileUploadId` 或已预留的准确 `(FileId, FileVersionId)` 在配额准入前冲突；
同一文件的不同版本可以分别预留。

每次写入校验完整有界账本，包括其他所有者。最多读取 257 个标量 ID，拒绝超过 256 条；
之后一次只读取一份清单，SQL 在返回正文前检查长度。严格类型解析和规范字节相等检查拒绝
损坏、超长、跨工作区、重复或超预算记录，不能把它们当作零占用。
读取之间只保留紧凑指纹和有界核算。这不是全局 CPU、请求并发、内存、带宽或文件工作预算。

## 事务、身份与不确定结果

写事务明确使用 READ COMMITTED，通过两个表锁和标记行串行化，持锁至提交。
读事务使用只读快照，不获取标记写锁。检查准确普通表形状、固定命名空间/搜索路径、工作区、
安装 UUID、配置限额和持久命名空间/表 OID；不收编同名替换。
插入后准确读回，并再次比较原账本指纹加准确一条新记录；拒绝已测试的即时/延迟触发器漂移。
数据库管理员及任意触发器代码仍受信任；再次延迟后续事件的情形未验收。
请求本地同步提交，不声称已验收断电持久性或可以抵抗数据库管理员。

超时或存储/提交错误均是**未确认**，不是回滚证明；不能自动重试、释放预留、收编暂存字节或清理。
随后读取匹配也只报告当前元数据。PostgreSQL 安装身份与文件系统根的设备/inode 身份独立，
不能互相替代。

## 验证与下一道边界

`file_upload_intent_tdd` 包含默认无数据库准入测试和显式 opt-in PostgreSQL 测试。
`scripts/test-file-upload-intent.sh` 必须提供明确可销毁数据库，并逐项检查准确测试名再执行。
故障夹具会主动修改合成 Schema 和记录。源码守卫检查库存与接线，不证明 SQL 行为。
[项目日期记录](project-status.md)保留实际执行与未验收范围。

SQL 夹具使用声明元数据和合成摘要，**不是真实大文件传输**。此前流式/暂存测试证明各自字节行为，
两层仍独立。回执丢失/重启协调、物理磁盘策略、当前发布/接收授权、传输及安全客户端保存
仍需完成。暂存文件名或字节匹配预留不能自动收编成上传进度。
不改变在线 `AppState`、Session 命令、HTTP、OpenAPI/SDK、浏览器、桌面配对或部署；
Artifact 的 1 MiB、文本的 256 KiB 限额及源码版本不变。

另行的[上传绑定暂存后续](large-file-upload-staging.md)现将原预留/来源固定接到真实字节和
原文件本地回执。本 Schema 1 账本不变，仍不增加持久分块状态、收编、核对或续传权限。
独立[分块日志](large-file-chunk-journal.md)、[整字节核验](large-file-whole-verification.md)及
[发布元数据](large-file-publication.md)另行提供显式确认/检查，不提供恢复或当前授权，
也不改变本预留账本。
