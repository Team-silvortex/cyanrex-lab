# ADR-012：只读生命周期对账

状态：**C1-K 内部准备层，收录于 0.4.7**。本地命令
`cyanrex-provision reconcile` 检查准备层的持久账号、Session、身份绑定、策略及其审计历史是否
一致。结果只代表一次有界只读快照，不是授权决定、初始化回执、密钥交付确认或重试许可。
观察器不安装或迁移存储，不修复记录、恢复凭据或接入在线 Engine。收录于 0.5.1 的 OTP 消费后续改动
现要求准备层来源 Schema 2；C1-K 最初收录于 0.4.7 的历史节点保持不变。

## 运维入口与范围

使用 [ADR-011](collaboration-provisioning.md) 的 format-1 私有配置，明确指定已独立验证的本机
测试数据库、具名 Schema、authority 和旧教学 Workspace。私有文件、显式 socket/回环地址、
环境隔离与连接替换时的物理目标核对规则保持不变。为兼容配置格式，仍要求填写 `username`，
但它不是对账过滤条件，也不要求最初账号仍然存在；本命令的目标报告会省略该字段。

```bash
cyanrex-provision reconcile --config /absolute/private/target.json
```

不接受确认指纹、密码文件、注册材料文件或 repair 参数，不打开、覆盖或删除注册材料。
目录预检先核对物理目标；随后整个生命周期图在独立的同一事务内读取，不拼接预检阶段的行数。
成功输出 `status: "consistent_snapshot"`、显式非敏感目标及汇总计数。
Rust 入口为 `DurableAuthSource::reconcile_authority`；两种入口都不调用安装器。

数据库管理员可预先准备只读角色，授予 CONNECT、Schema USAGE、目录可见性、
`pg_catalog.pg_control_system()` 的 EXECUTE，以及 12 张协作表的 SELECT。认证表只需要
`users(username, account_id, otp_last_counter)` 和 `sessions(username, account_id, expires_at, token)` 的列级
SELECT，不需要 CREATE、数据写入、序列访问或密码/盐/TOTP 列权限。token 列权限仅用于数据库内
校验摘要格式，CLI 不取回摘要值。水位列也只在数据库内检查范围并返回布尔值，不取回或报告
具体水位。旧只读角色须显式补充这一列权限，不要扩大到凭据列。数据库权限和可信端点认证须
另行准备，工具不自我加权。

## 一致快照与资源边界

关系图事务使用 PostgreSQL **REPEATABLE READ, READ ONLY**，不获取行锁、安装器锁或 advisory
写锁，仍受普通关系读取锁约束。在线授权与变更读取继续保留 source-first 锁序和即时 Session
检查；对账是独立观察路径，不能替换那些带锁接口。

读取数据前先核对来源/身份/访问元数据版本 2/2/2、来源 authority、旧 Workspace 映射、普通持久表、
预期主键，以及所有选取列的类型/非空约束。即使使用超级用户，也拒绝视图、继承/分区及 RLS 表，
避免行被隐藏后误报为空且健康。现有来源约束和来源/审计触发器形态检查仍须通过。
这不是面对特权数据库管理员时，对每个 DDL 对象、触发器函数体或历史操作的完整证明。

来源 Schema 2 包含非空的有符号 64 位 OTP 水位、准确默认值 `-1` 和已验证的下界检查。对账检查
存储水位至少为 `-1`，不推断哪次验证码或操作推进了水位。来源 Schema 1 即使为空也会拒绝；对账
不能升级它或补齐缺失水位。忽略准备层元数据的 legacy AuthService 不受此版本检查约束，准备层
来源仍须与这些旧写入方隔离。

关系图读取整次限时 10 秒，单语句 5 秒，锁等待 2 秒。每个扫描集合最多 **10,000 行、4 MiB
选取的可变元数据总量、单行 16 KiB**；先验证固定宽度字段类型，再在获取可变内容前核对数量和
长度。这些是检查预算，不是注册人数或历史保留上限。超限时保留数据，后续须另行设计并审阅更大
规模的检查，不能通过删历史来让检查通过。

SQL 故障、取消、超时、结构不支持或不变量失败均不返回部分成功报告。固定错误码指出最先失败的
边界，不输出原始 SQL、账号名或逐条审计内容，也不清理过期 Session 或旧历史。

## 核对的关系

| 边界 | 必须满足的观察 |
|---|---|
| 来源账号与 Session | 账号 ID 合法唯一，用户名规范，OTP 水位在合法范围；每条 Session 对应当前准确账号代次，存储摘要格式正确 |
| 身份绑定 | 绑定对应保留的 Human Principal，坐标和状态合法；未退役绑定仍能匹配来源账号 |
| 成员关系与部署授权 | 每个旧策略的主体已绑定，Workspace 准确，成员/Grant 成对存在且修订相等，角色和状态规范 |
| 身份与策略历史 | 解析每条记录，校验坐标、请求摘要和状态转移，逐主体检查完整前后状态连续性，最终状态须与当前记录相同 |
| 当前管理者 | 至少一个活跃、未退役、带审计的 Human，准确匹配当前来源账号并持有显式部署 Grant |

审计序号允许有空洞：回滚分配及其他主体/authority 都可能消耗序号。按序号遍历不等于连续提交
游标或墙上时钟顺序。基线只描述启用时观察到的状态，不补造更早的命令和操作者。保留的审计
操作者须能对应绑定，但不会用当前 Grant 倒推其历史权限。

普通注册后尚未绑定的账号是合法状态。仅注册表退役不会删除凭据，因此退役绑定可以仍有原来源
账号；保留的 Grant 不算当前管理权。删除后同名重建且 ID 全新的账号是另一条未绑定身份；
把已有账号 ID 换到另一个用户名下，即使绑定已退役也会拒绝。管理者计数不依赖教学成员关系是否
活动、是否拥有教师角色或 Workspace 是否归档，而取决于显式 Grant 与当前有效的来源 Human。

报告包含快照观察时间、Workspace 状态、账号/未绑定/退役但来源尚存的计数、Session/过期 Session
计数、绑定/退役/禁用身份计数、策略数、当前管理者数和两类审计条数。退役与禁用计数有重叠；
`bound_identities` 包括保留的退役绑定。过期按观察时间判断，不代表稍后使用报告时仍有效。
其他 authority、未来多 Workspace/Agent 策略与无关业务表不在旧 authority 的本次检查范围内；
没有绑定的 Principal 不会被当成已认证身份输出。

## 错误解释与恢复边界

| 错误码 | 含义及处理 |
|---|---|
| `reconciliation_unavailable` | 未确认完整快照；恢复读取或排查竞争，不把失败当成回滚证明 |
| `reconciliation_unsupported_schema`、`reconciliation_invalid_namespace`、`reconciliation_scope_mismatch` | 目标或结构不支持；核对配置与安装证据，不自动安装或接管 |
| `reconciliation_limit_exceeded` | 超出检查预算；保留数据，不为通过检查删除历史 |
| `reconciliation_invalid_source`、`reconciliation_invalid_identity`、`reconciliation_invalid_policy` | 当前记录在对应边界不一致；保留证据，交由可信维护流程调查 |
| `reconciliation_identity_history_mismatch`、`reconciliation_policy_history_mismatch` | 完整历史不能验证当前记录；不得改写基线或最新状态来掩盖问题 |
| `reconciliation_no_current_manager` | 观察图中没有合格的来源管理者；不自动重新授权或把首个用户选为管理者 |

失败退出码为 2；配置、连接和目录预检错误也可能使用 CLI 原有错误码。成功退出码 0 仍只是观察：
执行中的变更可能在快照之后提交，快照也可能合法地早于该变更。报告不能建立维护窗口，更不能
证明某一次未确认操作到底提交还是回滚。
原子 OTP 消费也遵守这一限制：成功快照不是某次登录或改密的回执；不能因为提交确认丢失就
降低/清空水位或盲目重复操作。

初始化结果不明时，应保留私有标记/输出，在决定恢复前确认先前操作已结束。`inspect` 只查看目录
占用，`reconcile` 检查当前有界关系图；两者都不读取 TOTP、验证密码、重发注册材料、证明文件系统
交付或许可再次 `apply`。审计不能证明基线前历史，也无法识别特权操作者同时一致改写当前状态和
全部证据。注册材料恢复、经审阅的备份/还原及在线路由/CSRF 切换仍是独立工作。

## 验证

以下保留 C1-K 引入时针对来源/身份/访问版本 1/2/2 的验证记录；当前 Schema 2 后续改动的结果及
限制另见[项目状态](project-status.md)。

[对账测试](../../engine/tests/durable_reconciliation_tdd.rs)包含 1 条默认来源隔离用例和 12 条显式
PostgreSQL 用例，覆盖正常生命周期、没有认证密钥列权限的只读角色、Schema/RLS/类型拒绝、较早
审计被篡改或删除、当前状态不符、有界输入、无管理者、交错提交与取消。故障夹具只用一次性数据，
与现有初始化事件钩子共用测试 guard 隔离。另有一条 [CLI 回归](../../engine/tests/provision_cli_tdd.rs)
拒绝写入参数与环境降级，并修正帮助文本中残留的补丁加号。

12 条数据库用例也通过回环 TCP 与 SCRAM 认证验证，包括数据库强制只读事务、限制认证表列权限
的非超级用户。CI 按精确名称执行数据库用例，拒绝空选择。本地验证统计及范围见[项目状态](project-status.md)。
这些结果不意味着已验收远程 CI、前端生产构建、部署数据库、迁移、注册材料恢复或特权内核路径。
