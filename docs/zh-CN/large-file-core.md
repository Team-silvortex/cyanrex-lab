## 文件身份与清单

[`FileTransferManifest`](../../engine/src/models/collaboration/file_transfer.rs)独立于 Task payload、
文本元数据和 Artifact 存储。文件及版本 UUID 类型与 Task、Artifact 身份不同。必填元数据
绑定权限域/工作区、文件、版本、显示名称、字节长度、有序分块和整文件摘要。这些值本身
不授予权限，也不证明来源、发布、持久保存或真实字节一致。

独立版本 1 对象固定使用 **4 MiB 分块**，每文件至多 **64 GiB、16,384 块**。有界 JSON
入口限制 **1,152 KiB**。字段全部必填；重复/未知字段、位置数组、未知版本及非规范
UUID/SHA-256 均拒绝。摘要序列在解码时限制数量，不信任输入的预分配提示。其他 Serde
入口仍需调用方另限输入字节和时间。

长度与块数须准确一致。空文件没有块，必须采用空内容摘要；单块文件的块摘要必须等于
整文件摘要。重复块摘要合法，因为相同内容块合法；多块的整文件摘要仍需读取真实字节。
`chunk(index)`提供经检查的偏移、准确长度及摘要，越界拒绝。传入流不会自动跳到该偏移。

显示名称保留合法 Unicode，至多 128 个 UTF-16 单位。拒绝空白、首尾空白、点名称、末尾
点、路径分隔符、控制字符、双向覆盖/隔离字符和 Windows 特殊标点，不静默归一化。名称
只是惰性标签，不能决定路径、解析器或执行行为；客户端保存规则另行审阅。旧文本标签规则不变。

## 流式操作

[`services::file_transfer`](../../engine/src/services/file_transfer/mod.rs)的同步操作接收调用方提供的
`Read`/`Write`，固定字节缓冲为 **64 KiB**。它不创建文件、打开路径、解析 URL 或派发后台
工作，也不将字节解码为文本或缓存整文件/整块。有限摘要列表是元数据，不是第二份文件。

| 操作 | 成功含义 | 调用方责任 |
|---|---|---|
| `inspect_stream` | 顺序真实字节生成通过校验的分块/整文件清单 | 来源认证另做；检查不是上传 |
| `verify_chunk` | 准确单块流的长度、摘要及结束匹配 | 提供准确范围；普通流不证明偏移或来源身份 |
| `copy_chunk_checked` | 写入者接收该块，字节检查通过 | 成功前隔离输出，持久保存另行确认 |
| `verify_stream` | 有序分块、整文件摘要、总长度及最终结束均匹配 | 从头提供完整文件 |

分块检查最多消耗声明长度加一个结束探测字节。完整文件仅在最后一块之后探测结束，不在
块间探测。检查拒绝超过文件上限的输入，不生成超限清单。短读/短写可处理；IO 错误、
`Interrupted`、零写、额外字节和摘要不符均停止，没有隐藏重试。

复制**不具备原子性**。后续摘要、长度或 IO 失败时，输出可能已包含部分乃至完整未验证字节。
成功也不刷新、关闭或 fsync；成功和失败都不授予发布、收编、删除、重试或持久回执权限。
读写可阻塞：内存/字节有界不等于墙钟期限、工作名额或带宽限制。后续适配须独立实现
准入、取消与生命周期策略。

## 已打开的 Unix 文件

`inspect_file`与`verify_file`独立检查调用方预先打开、偏移为零的描述符。仅接受单链接
普通文件，拒绝不兼容长度；成功字节处理前后检查设备、inode、长度、链接数、修改及变更
时间。访问时间会被读取本身改变，因此不参与一致性比较。

这些检查拒绝本次读取中可观察到的来源变化，但不打开/验证路径、不固定存储根、不证明
私有权限/所有者、不阻止其他句柄修改、不证明永久不可变，也不保证原路径仍指向该 inode。
安全私有暂存通过[单独显式接口](large-file-staging.md)实施，
[发布元数据](large-file-publication.md)也是独立准备层；物理封存及持久重启恢复仍需另做。

## 测试与兼容边界

默认[`file_transfer_tdd`](../../engine/tests/file_transfer_tdd.rs)用真实惰性字节及严格元数据测试，
不需要数据库或网络服务。真实文件夹具大于旧 Artifact 的 1 MiB 限额并跨分块。合成流
检查缓冲长度与故障行为，但不证明进程峰值内存、性能、磁盘满处理、持久保存、接收者认证
或可续传网络流程。

在线应用、现有 Session/HTTP 适配、Artifact/文本限额、数据库格式、OpenAPI/SDK、浏览器及
版本不变。历史能力张量保留原证据和评分；内部 Rust API 和测试不等于部署服务。

独立暂存 API 已提供私有文件与有界工作；后续[上传预留](large-file-upload-intent.md)、
[分块日志](large-file-chunk-journal.md)、[整字节核验](large-file-whole-verification.md)和
[发布元数据](large-file-publication.md)仍是显式准备层。集中传输与客户端送达前，仍需完成
回执丢失/重启协调、物理磁盘策略及当前发布/接收授权。
