## 安全语义

- Agent/任务两份响应成对发布到界面，**不是两个 GET 之间的服务端事务**。一份损坏或失败不会
  发布半份更新；合法空清单和未启用状态仍可识别。
- 读取完成后等 10 秒再轮询；并发刷新合并。读取期间禁止发出操作，写入期间暂停轮询。
  已审阅任务的身份、状态、执行 Agent 改变，或 Agent 重新注册后，必须重新打开确认。
  浏览器复核不能代替服务端权限检查。
- 探针有效期使用清单里的 Engine 时间，加上从请求开始计算的浏览器单调经过时间，不假设两端
  时钟同步；样本年龄达到 20 秒也拒绝发出操作。复核后服务端状态仍可能继续变化。
- 写入头部和正文共用 20 秒期限。探针回执需匹配排队中的控制探针、Agent、消息及超时；取消回执
  接受同一已审阅任务身份的 `cancelled` 或 `cancel_requested`，不宣称活跃 Agent 已停止。
- 已确认写入不因回读失败变成“操作失败”，但旧清单仍不可操作。写入结果不确定时，操作可能
  已经生效；再次操作前必须**显式成功刷新并核对**。后台读取成功不能清掉警告或解锁操作。
  没有自动重发 POST、补偿取消、本地回退或服务端回滚。
- 导航、切换 Engine 和卸载只中止浏览器等待，不撤销 Engine 已接受的操作。切换语言只翻译面板
  提示，不重新读取，也不丢弃相邻设置表单的草稿。

## 证据与覆盖

最终 7 项浏览器基线在改运行时代码前全部失败。首次基线有 4 个按钮名称写错；第二次的回执断言
仍不充分，旧实现等待回读时也能通过。最终基线改为等待明确的确认失败反馈。这些中间诊断都保留，
不算新增产品问题。

扩展测试发现解码器还需拒绝会被日期解析器归一化的不存在日期，以及过多嵌套标签，补齐后通过。
另一个导航断言发生在 React 移除对话框之前，改为等待卸载后通过，未因此修改运行时代码。
旧浏览器夹具同步成真实 Engine 清单/任务 DTO，不再用缺字段对象或 `{ok:true}` 冒充取消回执。

新增 **34 项唯一测试：10 项单元、24 项浏览器测试**。浏览器用真实面板、SettingsPage、确认框和
国际化组件，在 Strict Mode 下控制时钟与合成响应，阻断夹具外网络。没有真实凭据、已部署
Engine/数据库、Agent、SSH/局域网或内核操作。
