## 顺序操作与本地确认

`services::file_chunk_client::FileChunkClient::fetch_and_assemble(token, grant_id, upload_id, &manifest)`
复用原客户端冻结的可信 Origin，以及与接收器**同一个原 `ChunkStaging` 句柄／根**。
先核对工作区及规范非空 36 字节 Session UUID，再准入整流程或发起 HTTP，空文件也不例外。
类型授权／上传选择器沿用既有契约。调用者提供期望类型清单，本操作不获取或认证该清单。

每个已准入流程先请求第 0 块，等真正 EOF／摘要及实际私有暂存确认后，才请求第 1 块，依次
推进。**每流程至多一个活动分块**，不派发后台网络续跑、不自动重试、跳过或收编。
仅全部选择块成功后，才由原暂存句柄拼出真实整文件；容量 1 不会自锁。
原 `fetch_and_stage` 调用仍独立于整流程准入。

空清单发起 **零次 HTTP**，但仍实际拼装本地空文件。此路径不向远端核对语法正确的 token，
空文件成功不证明当前 Session 或接收权限。非空请求复用准确七项选择器、逐次敏感 cookie、
marker、响应头策略及受控传输，不新增协议或凭据。

成功返回既有只能移动的 `AssembledFile`，仅有 `file() -> &FileVersionRef` 元数据。
原自有 0700 根、私有 0400 单链接文件、固定完整清单绑定 `v1`／`f1` 名字、独占创建、实际
有序／整文件摘要、原 inode 读回及最终输入／根复核不变。不返回用户选文件名／路径、
公共字节／描述符或远端送达回执。

## 独立容量与取消

既有 `FileChunkClientConfig.capacity` 同时控制新**独立**克隆共享整流程门限和既有独立单块
门限，默认 **4**，可信范围 **1–16**。不增加配置字段或全局调度器，分别构造的客户端预算
仍可相加。整流程准入**不预留**接收器、暂存工作、磁盘、带宽或 SQL 容量；无关消费者及
并行流程仍可能在这些独立既有门限处立即失败。

存活流程与当前已派发保存／拼装任务共享一个 `Arc<OwnedSemaphorePermit>`。
收集正文时由父流程持有；文件派发后，真实排队／运行任务也持有。丢弃异步等待者不能在
真实任务存活时释放整流程名额。私有 cursor 先释放字节、接收器名额和请求名额，最后释放
整流程引用；拼装在真正阻塞闭包中持有引用，不只包住 JoinHandle。
原公开接收器／暂存调用传 `None`，原准入语义不变。

响应头／正文阶段取消不创建当前未核验块，保留先前已确认块并释放本地流程容量。
文件派发后，当前块或整文件仍可能完成，但**不请求下一 HTTP 分块**。
取消不等于远端／OS 强杀、回滚、可复用进度或清理／重试许可，不会后台续跑。

响应头、正文空闲和正文总期限仍是**逐块**的，`total_timeout` 不是整文件期限，不能强杀
文件工作。接收器每活动流程最多缓冲一个 **4 MiB** 选择块，拼装沿用 **64 KiB** 流式缓冲和
**16,384 块／64 GiB** 有界元数据契约。各块及额外整文件副本继续占磁盘。
既有逐块清单克隆／序列化可能重复，不声称元数据成本线性。这些结构上界不是实测 RSS、
吞吐、全局配额或 64 GiB 载荷验收。

## 错误、授权与保留证据

`FileDownloadError` 区分 `InvalidInput`、整流程 `CapacityExhausted`、
`Chunk { index, error: FileChunkClientError }` 和 `Assembly(ChunkStagingError)`。
索引表示失败的选择步骤；底层错误仍是固定／脱敏类别，不含凭据、Origin、路径或原始
传输诊断。第一个失败即停止流程。

先前保存块、不确定文件和已有输出都不删除、覆盖、收编或改名。重做部分／全部完成操作
仍遇到既有分块／输出冲突，不是续传。拼装失败可留下所有分块及不确定输出。
不增加隐式清理、重试、进度日志或恢复确认。

服务端仍用既有当前接收者命令**逐块**授权。请求之间撤销可拒绝下一块，但不会回滚此前
已披露／保存字节。客户端不增加最终远端授权复核、认证清单来源、持续授权保证，也不保证
最初各分块回执身份跨后续本地拼装连续不变。最终成功只确认拼装实际观察到的本地整文件
字节，不是远端送达。HTTP 消息 EOF 仍是库帧层 EOF，不是原始 TCP 后缀／连接 EOF。

独立[清单 HTTP 适配](large-file-manifest-http.md)现提供获授权元数据 GET，但此客户端方法
仍不获取它，也不替代每个后续块的当前授权。
另行[准确清单客户端入口](large-file-manifest-client.md)现先获取元数据再进入同一下载核心，
不改变此提供清单方法或其空文件零 HTTP 行为。
原确认输出可另进入[显式私有保存](large-file-save.md)，复制到可信宿主选择的新文件；该独立
跟进不延长下载流程 lease，也不增加界面保存对话框、远端权威或续传。

新增[授权交付调用](large-file-delivery-client.md)将这些阶段合为一次显式操作，原整流程名额跨真实
块／拼装／保存任务及取消存活；首失败停止，不重试／采用，界面保存、续传和正常挂载仍独立。

独立[本人普通目录目标](large-file-user-save.md)以明确选择允许 0700／0750／0755，不放宽
私有暂存；核对原目录 UID／GID／模式并沿用实际保存，文件选择、共享可写目录、续传和挂载仍独立。

不增加正常 AppState／监听／路由、Session 签发、OpenAPI／SDK／UI、Schema
安装器、迁移、在线认证切换、用户选路径最终保存、重启／续传、点对点配对或局域网部署
验收。版本和依赖保持不变。
