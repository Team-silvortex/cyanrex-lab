## 范围与发现

F32 登录态历史、JSON/CSV 导出 → F34 未读数，覆盖 HTTP 参数、存储选择、冷热内存、SQL 故障与
修复、重新创建 EventBus 的边界。只使用合成用户和私有 Unix socket 上的临时 PostgreSQL 16.15，
不接触真实课堂事件或账户。

| 编号 | 复现 | 修复 |
|---|---|---|
| BH10-01 | 已选 SQL 读取失败仍返回成功的部分/空历史、下载或零未读；读取还可能关闭后续持久化。连接池等待缺少本轮新增的读取期限；已锁定降级时可能把易失记录当成完整结果。 | HTTP 使用可失败读取：统一不缓存的 `503`，失败下载无附件头，建表/连接池等待计入 10 秒协作式期限；读取故障不关闭持久化。非法/不可用配置及已降级存储不再当作显式纯内存模式。 |
| BH10-02 | 非法/未知筛选及不支持的格式可能静默扩大/改变查询；极端相对时间触发 panic；成功/错误响应缺少一致的不缓存契约。 | 在访问存储前校验参数解析、筛选、RFC3339 日期、格式和相对时间运算；非法/反向范围返回不缓存的 `400`。两种存储使用同一个冻结后的时间下界。 |
| BH10-03 | 不兼容的 payload 列被伪装成 `{}`，时间戳解码触发 panic。初次修复后，两个恢复测试仍被旧的历史 SELECT 返回类型缓存阻断。 | 所有历史列改成可失败解码，错误明确返回不可用；历史 SELECT 不跨读取保留预处理语句，使列类型修复后可重试。不宣称性能提升。 |

成功响应结构、会话决定的所有权、精确时间的闭区间、零时间窗口、条数默认值/上限及旧版忽略的
参数保持兼容，未认证仍先拒绝。没有新增路由、Event/数据库结构或 SDK 签名；OpenAPI 补齐失败及
不缓存契约。旧的不可失败 Rust 快照/未读辅助函数仍保留尽力返回语义，但 HTTP 不再依赖它们提供
权威读取结果。

## 先失败再修复的证据与覆盖

实现前，**3 项 HTTP、8 项 PostgreSQL** 回归全部失败；契约/CI 选择检查的 5 项中有 2 项失败。
首轮 HTTP 测试编写误把 100,000,000,000 分钟当作 Chrono 溢出，实际上仍在其日期范围内；纠正后的
失败日志用 1,000,000,000,000 分钟验证日期溢出、`i64::MAX` 验证时长溢出。两份日志均保留，误写
断言不计作产品缺陷，也不能据此认为已穷尽 PostgreSQL 的日期取值边界。

首次 SQL 修复后为 31/33 通过；剩余 payload/时间戳列修复后仍失败，诊断确认
`cached plan must not change result type`。调整 SELECT 后 33 项全部通过，最终运行还覆盖取消等待
与未认证读取。临时诊断日志初始化已从测试代码撤除。两项服务级防退化测试及最终补充断言是在
最初失败复现之后加入的。

新增 **14 个独立用例：5 项普通 Rust、8 项显式启用 PostgreSQL、1 项 Node 契约测试**；原有 CI

## 限制与下一块

- 10 秒约束可协作的异步读取，不含认证、序列化、CPU 阻塞，也不证明 PostgreSQL 已取消正在执行
  的语句。放弃等待不会关闭持久化。
- 仅当独立写入者没有锁定降级时，读取故障才可直接修复后重试；既有降级继续不可用直到新状态，
  不自动合并易失事件。
- 保留测试表后重新创建 EventBus 不等于进程崩溃、断网、提交回包丢失或断电恢复。没有多 Engine/
  外部写入者协调或读取队列屏障，快照仍可能落后于实时通知。
- 原有易失写入、已读和删除确认行为未变；旧不可失败辅助函数仍可回退，权威约束只覆盖新的
  HTTP 可失败读取路径。
- 没有穷尽枚举/损坏数据及 PostgreSQL 日期边界，也未扩展 CSV 公式/回车/表格软件安全、字节
  配额、持久重放或恰好一次投递。
- 历史 SELECT 的计划复用发生变化，未做新基准；未运行远端 CI、Rust 依赖审计、可选浏览器套件、
  真实 SSH/局域网/内核/部署或发布产物验收。
