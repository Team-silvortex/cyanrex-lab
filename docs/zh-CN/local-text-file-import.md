# 向任务草稿添加本地文本文件

源码 **0.5.9** 已收录，原为 **0.5.8** 之后的跟进，核对日期 **2026-10-13**。API **0.3.0** 和版本 1 草稿格式
不变。本功能接入本地编辑器，不接通服务端 Task 保存、Artifact 发布或独立的大文件服务准备层。

## 使用方法

1. 登录后打开 `/tasks/new` 的**任务草稿**；兼容入口 `/editor` 使用同一本地容器。
2. 点击**添加文本文件**，多选本地 UTF-8 文件。核对安全展示名、所选数量、原始总字节数、
   任务标题和追加后的内容总数。
3. 一次确认后追加整批。取消不读取正文，也不改变草稿。
4. 需要可携带副本时下载草稿 JSON。添加文件不等于保存：草稿仍只在页面内存中，
   没有自动保存、浏览器恢复或服务端提交。

笔记、Markdown、源码和配置都成为普通可选文本 payload。标题和旧内容保留。每个新项有
独立本地 ID，修订号为 1；与旧项或其他文件同名也不覆盖。已有选中项时保持编辑模型和
撤销历史，没有选中项才选择第一项新内容。手动切换仍按[编辑器说明](editor.md)替换模型。

受支持扩展名建议现有编辑语言，未知扩展名使用纯文本。语言只是惰性元数据，不是任务类型、
编译器、LSP 安装或执行授权；旧项的可携带语言提示不改写。

## 限制与失败行为

- 包含旧内容在内，最多 **32 项**。预检和确认不读取正文；满容量禁用选文件入口，超额选择拒绝。
- 单文件最多 **256 KiB** 原始字节，实际返回字节数须匹配选择时捕获的大小。
  MIME 类型和文件名不代替内容校验。
- 严格 **UTF-8**，拒绝非法字节和二进制控制字符。允许制表符和换行，保留 CRLF 和正文；
  既有解码器消费开头的 UTF-8 BOM。
- 完整序列化草稿最多 **8 MiB**，包含旧项、元数据和 JSON 转义；原文未超单项限制仍可超限。
- 确认后整批共用固定 **10 秒**期限，不是每文件十秒。读取失败、正文非法、到期或所属
  草稿变化／关闭都会拒绝整批。

全部文件读完并验证后才分配 ID，最后只提交一次新草稿；后续坏文件不会暴露有效前缀。
失败保留旧标题、内容和选中项。同页锚点关闭待处理确认但保留旧草稿；切换页面或退出登录
使旧续接失效。迟到原生读取不能追加到旧草稿，也不能污染新页面草稿。

期限与 AbortSignal 停止等待及被接受的续接，不物理取消 `File.arrayBuffer`、终止 JavaScript
工作或构成全局内存／CPU 配额。重要工作离开前仍需下载；既有离开警告不等于崩溃恢复。

## 实现与范围

`frontend/src/features/tasks/textFileImport.ts` 是 UI 适配器，复用不可变草稿契约及既有
文件名、UTF-8 和语言工具。Task 契约仍不依赖编辑器注册表。`TaskDraftWorkspace.tsx`
持有被确认修订、选择和一次提交。现用教学应用、eBPF 编辑器及服务端权限不变。

正文不上传、不执行。正常侧栏身份／状态请求仍存在，不能称整个应用离线。本轮不增加端点、
Session 签发、存储 schema、SDK、大文件 CLI、挂载、重试或部署。通用服务端保存和正常应用
大文件分发仍需独立评审认证及组合边界。
