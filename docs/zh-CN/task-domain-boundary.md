# ADR-013 任务定义与领域评估边界

源码版本 **0.5.5**（**2026-10-11**）已收录这些跟进；分日期的 `Unreleased`/未发布标记保留
当时实施阶段、源码版本和验证范围。源码收录不代表准备层 API 已挂载、浏览器保存已接通、
在线认证已切换、存储已迁移或运行实例已经验收。

状态：**C2-A 已收录于源码版本 0.4.8**。决定日期：**2026-10-03**。

平台现已拥有不可变、带版本的任务目录及类型化规则调用边界；内置 eBPF 教学包拥有五个实验的定义、
源码与运行结果规则。旧教学读取和新提交评估通过兼容适配器接入通用目录。这是一条实际使用的代码
链路，不只是改名，但仍不是完整的 C2 Task 服务。

源码版本 0.5.4 上的 **2026-10-08 未发布跟进**将冻结定义元数据与可执行评估分开。只使用元数据
构造 Task 或配置会话目录不再要求提供器；类型化评估器和原授权边界保持不变。

## 职责与组合

| 位置 | 职责 |
|---|---|
| `engine/src/models/collaboration/task.rs` | 定义与包引用、Schema/策略版本、规则结果 |
| `engine/src/services/task_catalog/definitions.rs` | 不需要评估器的冻结元数据注册与精确查找 |
| `engine/src/services/task_catalog.rs` | 组合元数据目录、类型化调用和评估结果上限 |
| `engine/src/domain_packs/ebpf_teaching/` | 实验 ID、顺序、模板、C 源码证据和挂载要求 |
| `engine/src/services/learning_catalog.rs` | 兼容门面，保留原 Rust 调用入口 |
| `LearningStore` 与原路由 | 保留历史、进度、评语、所有权与持久化 |

`TaskDefinitionCatalog::new(package, definitions)` 沿用重复、命名空间与显示信息规则，验证显式
指定的一个包版本及 1–256 个定义。非泛型、可克隆句柄共享不可变 `Arc` 快照，不保留提供器、
证据类型或可调用的评估代码。精确查找仍不回退到最新版。这是可信配置，不是请求反序列化、
包发现、发布者认证或动态策略注册表。

**2026-10-11 未发布跟进**仍基于源码 0.5.4，新增
`TaskDefinitionCatalog::compose(catalogs: &[Self]) -> Result<Self, TaskCatalogError>`，支持显式多包
配置。它接收 1–256 个已验证元数据句柄，先计算展平后的定义总数再复制；结果必须为 1–256 个
定义，输入已经组合过时也适用同一总上限。总量同时限制每个包的条目数和不同包的数量，不另设
更小的包数量上限。新冻结 `Arc` 快照保留输入目录顺序及各目录内的条目顺序。

同一包/包版本的互不重叠分片可以组合，不同包、包版本及任务定义版本也可共存。每个定义按自己的
包坐标重新校验。完整定义引用重复时一律报错，即使两份元数据完全一致也不去重、不覆盖，查找仍
不回退到最新版。组合只处理元数据，不组合提供器、证据类型，也不发现包或认证发布者。已有单包
`new` 和类型化 `TaskCatalog<P>` 构造保持严格。

`TaskCatalog<P>` 组合该元数据句柄与显式构造的可信 `TaskProvider`，`definition_catalog()`
只暴露元数据。通过关联证据类型把领域输入留在平台契约之外。
核心没有写死任务类型的枚举、任意 JSON 评估器，也不要求每种任务都创建 Run。测试中的纯文本提供器
通过同一个目录评估人工撰写的摘要，不需要编译器、教师或内核。这证明了接口可以接入第二领域，
并不表示已交付文档编辑器或新的公共工作流。

`TaskDraft::from_definitions` 与 `SessionCatalogTaskWorkspace::from_definitions` 直接接收元数据
句柄，无须构造评估器。原 `TaskDraft::from_catalog` 与工作区 `new` 委托到新路径，保持兼容。
取得或克隆定义不授予类型化 `Evidence`、`assess`、Session 权限、执行或 Task 验收能力。

**2026-10-08 未发布的目录内容跟进**进一步把该元数据与已有文本清单组合，不让内容依赖评估器。
`TaskContentStore::from_definitions` 和 `SessionCatalogTaskContentWorkspace::from_definitions`
显式选择目录准入；创建复制准确的完整定义，后续操作拒绝配置条目缺失或信息改变。
实例标题和文本标签仍独立于定义的展示信息；必填证据 Schema 和评估策略引用只被保留，不被执行。
原手动内容入口仍不带定义，存储继续使用 Schema 3，不迁移数据库。严格模式边界见
[内容存储](task-content-store.md)和[会话内容命令](session-task-content.md)；这不把目录内容
接入 HTTP、浏览器保存或草稿发布流程。

教学适配器把旧实验 ID 映射为准确的定义引用，调用通用目录，再将 `Passed` 映射回原 `completed`。
它不编译或加载代码。原源码分词器迁入教学包，解析逻辑未改；注释、字符串、辅助函数名称子串、
空指针保护、运行阶段和已验证挂载的判断保持原行为。

## 0.5.5 收录的不绑定自动评估定义

独立的 **2026-10-11 未发布评估绑定跟进**仍基于源码 0.5.4，允许定义明确不绑定自动评估。
这是未发布源码能力，不代表已发布的 0.5.4 标签具备该能力。
`TaskDefinition.evidence_schema` 与 `assessment_policy` 改为成对的 `Option<VersionedName>`：
有自动规则的定义两项都存在，不绑定自动规则的定义两项都为 `None`；只绑定一项直接拒绝。
冻结目录可混合两种形式，包括显式多包组合。名称、准确引用、展示信息限制与定义总预算不变。

JSON 中两个字段仍必须存在。不绑定的定义必须为两项分别写明 `null`；漏字段、只有一项为 null
或存在的引用格式非法均拒绝，不默认为空。旧已绑定 JSON 的字段顺序和值保持原样，已有记录无须
迁移。Rust 字段从 `VersionedName` 改为 `Option<VersionedName>`，内部源码调用方需要适配。
新双 null 定义要求新读取器；旧二进制会拒绝，不承诺旧程序读取新无绑定记录或降级兼容。
核心与存储 Schema 编号均不变。

不绑定评估的目录 Task 不会变成手工 Task：它仍保存带准确包/任务身份的 `Some(TaskDefinition)`。
已有草稿、Schema 2 会话目录及 Schema 3 内容构造器接纳两种已配置形式，不评估内容。读取和变更
仍比较完整定义；在同一引用下增加或移除绑定，两个方向都作为信息漂移拒绝。有意改变绑定应新增
定义版本，不能编辑或重新解释已存工作。

`TaskCatalog<P>::new` 仍要求每个类型化提供器条目同时具有两项绑定；`assess` 在调用提供器之前
也会核对，`TaskAssessment` 继续要求 Schema/策略引用。缺少绑定不产生占位评估、自动批准、
人工 Review 签发或 Task 验收。本跟进不增加提供器发现、公共命令、编辑器连接、授权分支、迁移，
也不实现 Review/执行流程。

## 版本与失败语义

引用同时包含包名/包版本和任务名/定义版本；有绑定的定义另行固定证据 Schema 与评估策略，
明确不绑定的定义同时不绑定这两项契约。存在的版本是正的
JSON 安全整数，不是产品版本或模块清单的 SemVer。内置教学包、定义、Schema 和策略均从版本 1 开始；
任务契约使用现有核心 Schema 版本 1。

注册时保存定义快照，拒绝相同准确标识重复注册、外来包坐标、超出包命名空间的名称及非法显示信息。
查找要求完整引用；未知包、包版本、任务名或定义版本不会回落到当前规则。结果身份来自目录注册项，
不由评估器返回值或调用方元数据决定。即使直接调用教学提供器，它也拒绝被替换的定义、策略或 Schema。

每次 `new` 注册承载一个包版本及 1–256 个定义，可同时保留同一任务的不同定义版本；显式组合
在多包间仍保留最多 256 个定义的总上限。标题非空、无控制字符、
最多 256 个 UTF-8 字节；摘要最多 2,048 字节。结果最多 64 条反馈，单条 2,048 字节、合计 16 KiB。
这些限制约束注册元数据与接纳的结果，不限制可信提供器代码本身的内存或执行成本；提供器仍负责证据
校验和处理预算，命名空间校验不等于包发布者认证。

已经发布的定义/策略版本不能原地改规则。语义变化须注册新的定义和策略版本；仍需使用旧版本时应保留
对应评估器，缺失版本显式失败。目录尚不持久保存包，也不能让被删除的代码跨部署继续可用；持久生命周期
仍是后续工作。

## 兼容与安全

五个旧实验的 ID、顺序、标题、摘要、文档/模板链接、反馈文案/顺序和未知实验错误保持不变。提交 JSON/SQL、
教师评语及 HTTP/SDK 契约不增加伪造的版本字段。历史记录按原样读取，不重新评分，也不补造历史策略版本。
进度继续保留最早通过时间，后续失败不抹掉完成状态；恢复只能读取自己的提交，教师审阅权限保持不变。

`TaskAssessment` 是临时自动规则结果，**不是**持久 Review、人工批准或 Task 状态变更。它没有经过认证的
审阅者、固定制品目标、证据摘要或审计回执；客户端提交的结果不能成为批准依据。新层不认证调用者，也不
授予执行权，仍沿用原路由、Session 与 CSRF 边界。

本轮不新增路由、UI、数据库 Schema、迁移、在线认证切换、动态插件加载或特权执行路径。模块清单 v1 的
发现和 start/stop 仍只是原有声明目录控制；注册任务提供器不会获得清单中的能力。Engine 仍是特权单体，
源码解耦不等于进程隔离。

## 验证与后续边界

`task_catalog_tdd.rs` 覆盖第二领域、准确版本共存、拒绝回落、重复/跨包注册、元数据/结果上限、严格解码
及禁止领域导入。`teaching_task_adapter_tdd.rs` 固定旧目录与反馈，对照两种适配入口的 180 种结果组合，
拒绝版本替换，并验证写盘后重新加载仍保留历史及首次完成时间。另有编译失败用例拒绝把文档证据传给
教学评估器。已有模板、学习存储、路由权限与模块边界回归继续适用。

元数据独立跟进另加 `task_definition_catalog_tdd.rs` 及会话目录 `metadata.rs` 用例，检查无提供器
构造、冻结所有权、精确查找与原授权/存储行为。其执行证据在项目状态中单独记录。
另在 `task_content_store` 和 `session_task_content` 中覆盖目录内容组合的模式隔离、完整定义
检查与原内容授权边界。
多包跟进新增 `task_definition_catalog/composition.rs`，覆盖纯组合、完整引用冲突、顺序及嵌套
总量上限；会话目录与内容组合用例检查同一元数据句柄经过既有 Schema 2/3 命令的行为。
`taskCatalogComposition.test.mjs` 守卫有界且不依赖提供器的源码边界。
独立的 `task_definition_catalog/assessment_binding.rs` 检查显式成对缺省、必需的可空 JSON
字段、旧已绑定编码、混合元数据及类型化提供器拒绝。会话目录/内容绑定用例检查存储双 null 及
同编号绑定漂移的拒绝；`taskAssessmentBinding.test.mjs` 守卫对应源码边界与精确 runner 库存。

功能链路检查器改从教学包枚举当前实验 ID，并用回归测试确认缺少源码时拒绝降级到旧门面。0.3.8 的历史
清单及指纹不变，预期漂移不被重写成新的验收基线。实际执行的检查与限制见[项目状态](project-status.md)。

[ADR-014 / C2-B](task-instance-store.md)通过可信直接接口保存 Task 快照及原子事件。[C2-I](session-catalog-tasks.md)现已为当前 Session 的私人 Task 准入准确定义：句柄只持有冻结共享元数据，
提供器销毁后仍能使用，不调用 `assess`。读取/状态转换比较完整保存的定义，同编号信息改变直接拒绝，
缺失条目不回退到 latest。支持 0–32 个确切所属输入，空输入仍要求有效的 Artifact 元数据。C2-E/G
手工入口仍不接受定义；这不是类型化 Evidence 转换、评估策略执行或 Task 验收。

[C2-J](session-task-revisions.md)在替换 Draft 输入时同样检查配置中的完整定义，
不升级定义，也不按新版策略重新解释内容。

[C2-H](session-review-commands.md)另行授权对准确所属 Artifact 的私人人工 Review，不证明历史
Session 写入来源或授予跨用户审阅权。在切换存储前，先验证离线 attempt 映射和可见性不扩大。
非教学多人审阅工作流、持久 Run/outbox 仍是
独立的 C2/C3 里程碑；这些切片均不宣称 C-M2、C-M3 或 C-M5 已完成。
