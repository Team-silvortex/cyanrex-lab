## 范围与已复现问题

| 编号 | 复现 | 修复 |
|---|---|---|
| BH08-01 | 批量和替换写入实际 SQL 行数为零，却回退内存；PostgreSQL 报重复 `VALUES`。 | 让 QueryBuilder 自己生成关键字，绑定原生 JSON；验证真实行数及中文/嵌套内容往返，禁止以内存冒充入库。 |
| BH08-02 | 修通 SQL 后，暂停队列中的事件会在删除后重现、已读后再次未读，并在保留上限改成 50 后回到 80 条。 | 变更先经有序写队列屏障，按账号保持准入；已交接 SQL 即使调用方取消也完成到缓存发布。 |
| BH08-03 | 满队列逐事件另起写任务，绕过容量和顺序约束。 | 满/关闭队列警告并锁定既有内存降级，不再创建旁路写任务；屏障及选定建表/设置/变更阶段各有 10 秒等待期限。 |
| BH08-04 | 取消保留/替换会拆开内存状态；SQL 拒绝设置时缓存与历史已先被改动。 | 取得全部内存锁后才变更；设置/裁剪与替换先提交事务再发布缓存，失败替换不删除原有持久行。 |
| BH08-05 | 删除后 DropNew 容量缓存仍为满；迟到冷读取可覆盖新设置；替换接受异账号记录。 | 变更后清除容量缓存，保留较新的设置缓存，异账号替换在改动前整体拒绝。 |
| BH08-06 | 同时间戳按事件类型字符串重新排序，保留策略反而丢弃后发布的记录。 | 批次稳定时间排序，SQL 以时间戳/行 ID 排序，保留同时间戳的发布顺序。 |

## 限制与待查

- 顺序只针对同一 EventBus/Engine 内的账号。共享队列、连接池、内存和 CPU 不是租户隔离或总字节/
  账号配额。准入元数据与既有用户历史类似，保留到进程结束；慢数据库仍可引起共享队列压力。
- 屏障排序此前发布，不覆盖所有未来生产者或快照。历史/未读读取仍独立降级，快照可能落后于实时流。
- 原有降级仍易失且锁定到重启；已读/删除响应可能只确认内存，不保证跨进程或重启后的持久状态。
  重启前须检查易失事件，不自动恢复或对账。
- 阶段期限结束的是应用等待，不一定停止数据库语句；不是统一 HTTP 期限或回滚证明。已测试明确的
  事务失败，未测试丢失提交回执、进程崩溃、多 Engine 并发；后台 INSERT 的既有重试歧义仍存在。
- 同时间戳有确定顺序，但任意时间乱序、数据库精度、快照/实时重叠不因此变成事件 ID、游标重放或
  恰好一次。冷启动 DropNew 与已满 SQL 历史的准入差异，以及后台写任务退出/排空，仍须单独检查。
- 替换是私有服务帮助函数，不是新增导入接口；事务不跨整个发布/HTTP/恢复链路。数据库结构和 Event
  原始格式不变。
- 未使用部署账号/事件/数据库、部署 `.env`、运行中的 Engine/Agent、SSH/局域网或内核变更。
  未做新依赖审计、benchmark、SDK 运行时、浏览器到真实 Engine、发行制品或远程 CI 验收；默认 Rust
  测试含隔离的编译器/工具夹具。
