# 授权后读取已校验文件块快照

源码版本 **0.5.7**（**2026-10-12**）已收录此准备层；以下分日期的 0.5.6／未发布实施与
验证记录保留原范围，源码收录不代表已挂载或验收部署。

状态：**未发布 Unix 准备层**，源码 **0.5.6**，API **0.3.0**，**2026-10-12**。
依据[提案 #2](https://github.com/Team-silvortex/cyanrex-lab/issues/2)，当前接收者可以读取准确
可信 Published 文件的一块已私下校验字节。这一步把[下载清单资格](large-file-download-manifest.md)
接到真实字节，尚不提供 HTTP 或客户端送达。结果是读取时的不可变快照，不承诺持续授权或校验后
文件系统保持不变；之后的撤销无法收回已经返回的字节。

## 配置与请求

`DurableAuthSource::file_chunk_read_workspace(downloads, staging, capacity)` 用可信
`SessionFileDownloadWorkspace` 和已打开的 `ChunkStaging` 构造惰性
`SessionFileChunkReadWorkspace`。authority／workspace 必须一致，额度范围为 1–16。
配置克隆共享预算，独立构造的配置预算独立；构造不安装任何内容，也不连接数据库。
另行打开暂存仍需验证已有的私有根目录。

`SessionFileChunkReadRequest` 包含 `download: SessionFileDownloadRequest` 和 `chunk_index: u32`，
不能提供接收者、发布者、路径、来源／根密钥或权限。教师、部署、管理者、发布者或所有者身份
不能绕过本人接收授权；空文件没有可读分块。索引大于等于 16,384 在数据库工作前拒绝；其余索引
在文件工作前按服务端选择的准确已授权清单检查。

## 授权与字节交付流程

`read_session_file_chunk(token, workspace, request)` 分为以下阶段：

1. 轻量 token、配置和请求 scope 检查先于快速失败的结果准入与 SQL。第一笔认证源事务使用
   READ COMMITTED，从当前已审计 Active Human／成员及准确账号代次推导接收者，保留原本人
   Active 接收授权、完整历史、指纹及三表 SHARE 栅栏。记录中的发布者／账号和准确上传／文件／
   版本在解码前过滤 Published 元数据；完整版本必须与授权和请求相等。
2. 原选择的发布记录保留 Schema／命名空间身份、nonce、完整清单、指纹和隐藏绑定。
   来源／根密钥必须绑定原打开暂存根。复验原记录和身份后，同一次最终数据库时钟采样检查
   Session 到期与授权有效窗口，再确认首笔 COMMIT；当前窗口无效不得派发文件工作。
3. 不持有 SQL 连接或锁，私有阻塞任务只读取准确清单／索引绑定的固定 `u1` 文件项。
   验证根身份、不跟随链接的描述符、普通文件、当前所有者、准确 0400 模式、单链接、限定长度、
   准确 EOF 和单块 SHA-256；前后描述符和可见文件项快照及最终根核对拒绝可观察替换。
   至多 **4 MiB** 进入私有缓冲区，未经验证的前缀不向调用者暴露。
4. 第二笔新认证源 READ COMMITTED 事务重入同一份原 Session／来源／Registry 身份，重新栅栏
   同一份原接收授权与 Published 观察，包括原表身份、历史、nonce 和隐藏密钥。不采纳变化记录
   或相符替代品。全部记录检查先于最终同钟 Session／授权窗口采样，然后 COMMIT。
   只有收到确认后，`SessionFileChunkRead` 才暴露 `file()`、`chunk_index()`、`chunk_sha256()` 与借用 `bytes()`；
   最终授权之后不再进行文件 IO 或 SQL。

两笔数据库阶段各限定十秒，并保留配置的 READ ONLY 策略，不强制 READ WRITE；这不是整个调用
或文件任务的十秒截止时间。间隙中的授权变更导致原记录核验失败，不会悄悄采纳新的授权。

## 资源与完整性边界

暂存工作名额覆盖真实排队／运行的阻塞任务，即使异步等待者取消也继续持有。独立结果名额进入
真实任务，再随私有缓冲区和公开只移动结果保留，直到结果丢弃。结果无 Clone、序列化、公开构造
或消耗式字节向量出口，Debug 隐去字节；受信任宿主仍可复制借用字节。局部预算不是进程 RSS、
全局带宽或整机限额，独立暂存／配置实例的预算仍可叠加。

本次只核验所选分块摘要，不重新计算整文件摘要，不证明历史写入、fsync、发布确认或重启来源。
不查询当前上传意图、分块日志或发布权限／发布者生命周期，这些存储不成为额外接收权限。
仍要求原可信 Published 绑定；发布权撤销不级联撤销独立接收授权，也不承诺原文件元数据在提交
确认时仍然最新。

`SessionFileChunkReadError` 保留 `Metadata(SessionFileDownloadError)` 类型化错误，另有
`InvalidInput`、`CapacityExhausted` 和 `Unavailable`。失败或取消不暴露字节、不修复文件、不写
元数据、不释放持久上传配额，也不重试或采纳结果。响应额度按实际任务／结果存活期归还。
丢弃等待者不终止已经启动的阻塞任务，也不证明 SQL 回滚。

## 传输仍需单独接通

本认证源命令自身不连接公共监听或 HTTP 响应。独立[二进制 HTTP 适配](large-file-chunk-http.md)
现提供未挂载显式 GET 及字节所有者预算；OpenAPI／SDK／UI、客户端保存、续传、桌面配对和
在线认证切换仍缺失，缓存清单从来不是后续读取的权限。
分日期的能力张量评分及旧执行记录保持不变。

显式 `session_file_chunk_read_tdd` 与 `scripts/test-session-file-chunk-read.sh` 使用一次性 PostgreSQL
及合成文件；私有文件读取单元检查真实阻塞任务存活期。`fileChunkRead` 公共守卫只检查源码组合、
文档和库存，不代替这些行为测试。
