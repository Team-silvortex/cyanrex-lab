# ADR-015 不可变制品版本

状态：**C2-C 已收录于源码版本 0.4.8**。决定日期：**2026-10-03**。

通用平台现在可以发布、读取确切的内容版本，不依赖教学规则、Task 或 Run。PostgreSQL 保存所有权、
当前版本指针、不可变版本元数据和事件；私有 Unix 目录保存原始内容。服务保留旧版本，并在读取时
核对内容。这是显式准备层，不是在线授权、通用文件服务器或教学数据迁移。

## 契约与操作

`models/collaboration/artifact.rs` 中的 `ArtifactRevision` 包含带作用域的 `ArtifactRef`、所有者、
正的 JSON 安全序号、可选准确父版本、命名空间类型、标题、媒体类型、长度和创建时间。引用固定
authority、Workspace、制品 ID、版本 ID 及服务端计算的 SHA-256；这些契约独立于继续沿用的产品
版本 0.4.8。内容是不透明字节，不会执行，也不被核心解释成领域专用 JSON。

仅在 Unix 构建的 `services/artifact_store/` 提供四个显式操作：

| 操作 | 行为 |
|---|---|
| `install_empty_namespace` | 仅在全新专用数据库 Schema 安装版本 1 |
| `create` | 使用调用方指定的制品/版本 ID，发布序号 1、无父版本的内容 |
| `revise` | 要求准确的当前父版本，保留所有者和类型，发布新版本并推进指针 |
| `read` | 按所有者/作用域过滤，仅返回指定版本及通过校验的字节 |

创建接受 `ArtifactDraft`，不接受反序列化的完整元数据；摘要、长度、父版本、序号和时间均由服务端
生成。编辑可以改变标题、媒体类型和字节，不能改变逻辑制品类型或覆盖旧版本。当前没有分支、删除、
共享、所有权转移、浮动 `latest` 输入或公共路径读取。重复 ID 或已有内容路径是冲突，不是命令成功
重放，也不意味着可以接管未发布文件。

每个版本允许 0–1,048,576 字节。标题非空、无控制字符，最多 256 个 UTF-8 字节；媒体类型为不带参数
的小写 `type/subtype`，最多 127 字节。制品类型使用命名空间名称，不在平台写死文档/源码/实验枚举。
元数据和事件快照严格解码，每个 JSON 上限 16 KiB；数据库约束被移除后，读取仍限制取回的大小。
这些只是单操作限制，不是总存储配额或流式上传支持。

## 私有文件存储

`ArtifactStore::open(pool, scope, root)` 同步打开一个已有的绝对目录，不创建目录、不修改已有权限，
也不读取环境配置。目录必须属于服务 UID，权限为 0700。祖先目录通过文件描述符逐级打开，拒绝符号
链接，并要求可信的所有者/权限；允许 root 所有、带 sticky 标志的临时祖先目录。应使用专用本地目录，
不使用网络挂载或旧运行数据目录。

文件名仅由类型化作用域、ID 和摘要生成，客户端不能指定路径。新文件以排他、不跟随链接的方式创建，
写入后设为 0400，并同步文件及目录；数据库发布前必须读回核对实际字节。读取拒绝符号链接、硬链接、
特殊文件、长度/摘要变化、可写文件和被替换的根目录。非阻塞打开避免被替换的 FIFO 卡住读取；文件
操作在专门的阻塞工作线程执行。

操作会重新核对目录身份和私有权限。这能发现常见替换/损坏故障，但不能阻止拥有相同 UID 或宿主特权
的操作者在检查后修改文件。0400 不是硬件不可改写存储、签名或备份；摘要匹配不证明作者身份或批准。
本轮在 Linux 验证，其他 Unix 平台及文件系统掉电恢复行为尚未验收。

## 发布与失败语义

发布横跨两个存储，并不是文件系统与数据库的单一事务：

1. 开启有界数据库事务，核对 Schema/作用域，按“元数据 → 制品”加锁；写新文件前拒绝已知的所有者、
   ID、类型和过时父版本冲突。
2. 在尚未提交的事务中准备指针/版本记录，写入、同步并校验私有内容文件；普通读取看不到这些临时记录。
3. 追加对应事件，再核对 Schema、指针/版本/事件及内容，最后提交；确认提交才返回成功。服务不会修改
   已有版本和事件。

事件记录所有者 actor、准确结果版本，以及 `cyanrex.artifact.created` 或 `cyanrex.artifact.revised`
类型。事件失败/被抑制或提交失败会回滚数据库发布；文件可能留下，写入失败时也可能是部分文件。
缺少合法数据库元数据时，服务不能读取它。取消期间，已经运行的阻塞文件操作仍可能完成写入。

错误路径不删除或接管文件。提交附近发生超时、取消或连接丢失，不证明已经回滚，自动重试或清理都可能
不安全。未发布文件需要后续对账与保留策略；本切片没有垃圾回收、修复命令或命令回执。未来备份/恢复
必须同时覆盖数据库和内容文件。当前测试注入受控失败，不等于真实断电、进程崩溃或磁盘耗尽验收。

异步操作等待上限为 10 秒，SQL 语句时限 5 秒，锁等待时限 2 秒；超时不会终止已经开始的文件操作。
错误不暴露路径、凭据或原始 SQL，也不会回落到内存或旧脚本目录。

## 一致性与授权边界

读取使用单一只读可重复读数据库快照。写入先锁元数据再锁制品，拿到锁后用后续语句读取关联记录，
以一致观察并发胜出者。当前指针必须同时匹配最新版本与最新事件，单独把指针倒退不能隐藏更新的提交；
返回的每个版本也必须匹配自己的事件。这不是全历史父链/全部内容对账，也不能证明两套存储没有被协同
篡改；当前没有事件分发器或全局提交顺序保证。

安装使用命名空间建议锁，拒绝公共/系统/含糊的搜索路径及已有关系、函数和类型，DDL 与作用域元数据
一起提交。运行时拒绝 RLS、临时表遮蔽、非永久表、分区及继承；这不是完整数据库 Schema 指纹，也不能
防御拥有数据库特权的操作者。

Principal 必须由可信适配器完成认证、授权后传入。所有者过滤不是认证，知道他人的 UUID 不是合法
凭据；相同摘要也不会扩大读取权限，文件不做全局去重。Workspace/Principal 存在性、成员、退役、撤权
和 C1 Session 事务尚未组合。没有新增路由、AppState 入口、启动安装器、CLI 或教学存储写入者。

## 任务边界与验证

非教学集成夹具发布一份文档，为该版本创建手工 Task，再发布编辑，验证保存的任务仍能解析到原字节，
无需假 Run 或教师角色。这验证两个服务的组合，但 `TaskDraft` 本身仍只校验引用格式/作用域；公共
任务创建还需要组合内容查询与当前授权。本切片不宣称已经具备经过认证的 Review、任务验收或完整
公共工作流。

4 条默认用例覆盖输入上限、数据库关闭、危险目录拒绝和禁止在线/领域耦合。17 条显式 PostgreSQL
用例覆盖历史不可变、所有者/作用域/摘要错配、并发、Task 链接、安装拒绝、失败/抑制/延迟提交、取消、
文件丢失/损坏、链接/FIFO 替换、根目录替换、一致读取、元数据/事件故障、RLS/临时表、冲突、指针倒退
及严格有界解码。CI 脚本 `scripts/test-artifact-storage.sh` 确认每个准确名称存在后，才在一次性数据库
执行。实际结果与限制见[项目状态](project-status.md)。

[C2-D](review-record-store.md)已增加固定版本的 Review 判断与历史，但该存储本身不验证 Artifact
证据或认证审阅者。[C2-F](session-artifact-commands.md)现已组合 Session 与私人 Artifact 命令，
此处直接接口仍要求可信归属。Task 引用/Review 授权、对账、配额和保留策略仍须在正式接入前完成。
经明确验证的迁移之前，既有教学历史、私人所有权及 API/SDK 契约继续保持不变。
