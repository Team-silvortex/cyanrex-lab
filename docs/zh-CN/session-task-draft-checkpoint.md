# 草稿发布元数据检查点

状态：**C2-R 内部准备层，已收录于 0.5.3**。决策日期：**2026-10-07**。
本 Unix 边界从仍存的 [C2-P 尝试](session-task-draft-publication.md)导出有界元数据快照。
显式受信任调用者可以自行保留编码数据，但导出不等于保存。解析结果只是数据，不是尝试、授权、
持久日志，也不证明其中报告的写入已经提交。

## 导出与传输格式

`attempt.checkpoint()` 构造独立的不透明 `SessionDraftPublicationCheckpoint`。
其 `to_json` 与 `parse_json` 使用版本 1 的 `cyanrex.task-draft-checkpoint` 格式。
三个操作均返回 `Result<_, ContractError>`；检查点只提供元数据只读访问器，没有可变状态入口，
也不公开实现 `Clone`、`Debug`、`Serialize` 或 `Deserialize`。
格式版本独立于产品版本 0.5.3 和存储 Schema 版本。原尝试仍不可反序列化；检查点操作不改变
尝试进度，也不执行 I/O。

外层仅包含 `format`、`version`、`task`、`manifest`、`byte_lengths`、`reported_state` 与
`reported_confirmed_artifact_count`。清单保留标题、有序显示标签及**全部已分配**的 Artifact
引用，包括尚未发布的目标。长度描述预期 UTF-8 字节数，不是已观察到的存储字节。不导出正文、
token、Session 指纹、owner、来源句柄、命名空间、存储路径、数据库 OID 或时钟。

| 字段或关系 | 必须满足的边界 |
|---|---|
| 整份编码数据 | 含转义与元数据，至多 `MAX_SESSION_DRAFT_CHECKPOINT_BYTES`，即 64 KiB |
| 清单与长度 | 沿用清单标题/标签规则；零至 32 个有序内容项，各对应一个长度，每项至多 256 KiB |
| 范围与身份 | 所有引用与 Task 同范围；保留规范非 nil 的范围 ID 及已分配 UUIDv4 目标身份 |
| 已分配引用 | Artifact ID 与 revision ID 各自唯一；相同内容摘要不合并不同目标 |
| 报告进度 | 计数介于零与内容项数之间；`complete` 必须达到全部内容项数 |

解析拒绝 BOM、不支持的格式/版本、重复或未知字段、非法 Unicode、位置数组记录及非法数字形式。
整数字段要求整数 JSON 记号，不接受浮点或指数写法。解析前先检查总输入上限，序列化结果也必须
满足上限。检查点没有正文，因此元数据一致性不能逐字节核验原计划文本。

## 报告状态只是数据

`reported_state` 为 `ready`、`unconfirmed` 或 `complete`。对于含 `N` 个已分配内容项、
报告已确认数为 `c` 的 `unconfirmed` 快照，`reported_unconfirmed_step()` 在 `c < N` 时
推导 Artifact `c`，在 `c == N` 时推导 Task；其他状态没有报告的未知步骤。此访问器只计算数据值，
不读取存储，也不调用 [C2-Q](session-task-draft-observation.md)。具名空计划无需 Artifact
占位项：其未知目标是计数为零时的 Task。

真实内存尝试记录的是各命令返回的结果；一旦导入元数据，同名字段就只是调用者声明。
结构完全合法的检查点也可能被伪造、编辑或回放。`complete` 不证明历史提交或提交确认；旧
`ready` 快照也不证明导出之后没有派发写入。引用和摘要不授予访问权、不认证 Session，也不证明
是谁创建了匹配内容。

检查点应保持私密。即使不含正文和凭据，标题、标签、引用与摘要仍可能敏感；格式验证不检测
全部秘密，也不授权公开诊断数据。

## 持久化与恢复仍是独立工作

没有保存 API、文件系统写入、刷盘保证、数据库事务或保留策略。外部调用者自行保存的内容不与
C2-P 派发或提交同步，崩溃后可能只剩旧检查点，也可能没有检查点。规范编码不提供身份认证、
防回放保护、写前意图记录或持久结果证明。

解析不能复活尝试、导入确认、选择来源、读取目标、恢复 C2-Q、重试写入或授权清理。
C2-Q 仍要求存活的原尝试及当前仍有权限的原 Session。公共 HTTP、浏览器保存、Session 签发与
在线来源安装仍未接入。

0.5.3 收录的 [C2-S](session-task-draft-inspection.md)另行提供显式检查，使用受信任工作区和调用者
当前 Session；不在解析时执行，不重建 C2-Q，也不验证检查点的原调用者。检查点仍是未经认证的数据。

后续意图日志必须另行定义派发前持久化、结果记录、写者协调和未知提交处理。重启检查及任何
重试策略也需要独立的授权与失败契约，不能从这个元数据格式推导。

## 验证边界

默认 codec 测试覆盖严格解析、上限、已分配引用一致性、状态/计数关系及导出往返。
这些是纯元数据检查，不是崩溃耐久性、当前权限、历史来源或重启恢复。实际分日期结果记录于
[项目状态](project-status.md)，[测试指南](testing-guide.md)将其与 C2-P、C2-Q 的数据库证据分开。
