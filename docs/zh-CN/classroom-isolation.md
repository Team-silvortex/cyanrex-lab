# Linux 桌面与局域网课堂隔离

决策日期：2026-09-06。本文记录目标架构，不表示这些部署能力已经交付。
当前版本仍是特权本地 Engine，加上可选的只编译 Agent。

权威补充（2026-09-09）：教师统一负责教学策略与部署管理。单人使用的部署者默认是教师；课堂
中的身份、接入、学习记录和可信验收以教师管理的控制实例为准。学生个人实例的教师身份不能
转化为课堂教师权限；这不是对等组网或由学生端选举控制者的架构。

## 部署假设

- 不需要公网服务。多名已登录学生提交自己编写的 eBPF，身份认证不等于源码可信。
- 整个教室可以由 Linux 桌面机组成：教师桌面机运行教学服务，学生桌面机运行各自的实验 VM；
  独立服务器是可选项。
- 这里的 Desktop 指部署位置，界面继续复用现有前端；此决策不引入新的原生桌面壳或第二套 UI。
- 规划默认具备 Linux 和硬件虚拟化能力，但安装时仍必须检查虚拟化访问权限、客体内核与工具链、
  可用资源；检查失败不得静默转为特权宿主机执行。

## 教学与执行分离

目标控制服务负责身份、课程、保存的源码、学习记录与教师评语，不持有加载 eBPF 的权限，也不挂载
宿主内核目录。PostgreSQL 仅供该服务访问；实验 VM 不接收数据库凭据、浏览器 Session Token 或
共享注册密钥。VM 的创建和重建由学生客体之外、教师管理的宿主监管服务负责。它是独立的技术
权限边界，不要求另一名管理员或另一套登录角色。

每个活跃学生独占一个 Linux 实验 VM。不可信源码的编译、语义补全、加载、挂载验证和内核事件采集
全部进入该 VM。浏览器和控制服务不能把客体返回的挂载标识当作本机文件路径使用。
Native 宿主执行仍可作为显式选择的可信个人实验模式，但不能称为课堂隔离。

Linux 桌面机和集中虚拟化服务器遵守同一套所有权契约。普通容器不提供独立内核，全班共享一台 VM
也不能隔离学生彼此。宿主和客体内核仍需维护更新，虚拟化配置仍需限制权限，不能把 VM 当作绝对不会
逃逸的保证。

如果桌面机由学生自行管理，他们能够修改上报结果。这些结果属于学习记录，不构成防作弊证据；
可信自动验收应在教师管理的执行环境重新运行提交。

## 环境归属与恢复

1. 环境绑定服务端授权的用户、唯一环境 ID 和代次。学生自行提交的 ID、Agent 自报的
   `virtual_machine` 标签都不能替代授权。
2. 实验期间持续保留归属，包括单次运行请求返回之后。短期执行容量租约不管理挂载、事件或 VM
   本身的生命周期。
3. 所有命令和结果都绑定用户、环境代次和操作；重新分配后拒绝旧凭据与过期结果。在允许远程加载
   之前先持久化所有权。
4. 断线、超时、清理结果不确定或控制状态丢失时，停止分配新任务并隔离环境。不能因为清单缺失，
   或客体声称 detach 成功，就认定 VM 可以交给另一个学生。
5. 换人前由宿主监管服务重建或恢复环境，移除旧可写状态与凭据并验证就绪。没有干净环境就排队或
   拒绝执行，不得退回控制机运行。

受管宿主监管服务必须限制 CPU、内存、进程、磁盘、事件/输出和环境存活时间。网络仅允许必要的
认证控制通道和受限实验流量，客体不得访问 PostgreSQL、其他学生或无关局域网设备。即使只在局域网，
课堂前端/API/WebSocket 同源 HTTPS 和经过认证的加密节点连接也仍是要求。节点注册和撤销必须按节点
限定权限，不能把当前 Agent 的全局 Bootstrap Secret 下发到学生控制的机器。

## 分阶段实现

第一步准备工作把运行、挂载清单和卸载交给 `RunnerDriver`。执行请求的用户与租约所有者不一致时，
Manager 会拒绝调用；清单和卸载沿用 Session 中的用户归属，不依赖短期执行容量租约，并有超时上限。
卸载报告由选定驱动返回，卸载路由不在控制机检查 pin。后端不可用或不支持操作返回 `503`，超时返回
`408`，非法卸载目标仍返回 `400`；成功响应结构保持兼容。

编译边界增量已把带用户归属的检查/补全接到同一驱动。每个 Manager 提供 2 个检查和 3 个补全名额，整个
操作分别限制为 15/8 秒，或配置的更短 Runner 超时；取消时释放容量与进行中统计。本地编译器按用户
区分缓存，源码工作区使用私有权限和清理守卫；没有新增远程编译传输协议。

这还不是完整的远程执行契约：挂载验证、内核事件流、环境探测和编译设置仍有本机路径，所选头文件
元数据还需要可验证的远程文件包契约。
后续先把这些行为迁入执行边界，补持久化环境归属与按节点限定的注册，再实现 VM 监管服务和驱动，
覆盖断线、重启、过期消息、配额和重建测试。

目前没有可选择的 VM 执行模式，也不会自动创建 VM。未知 Runner 模式仍会使启动失败，
`/ebpf/run` 仍在本地运行，现有 Agent 必须继续保持无特权、只编译。局域网入口加固也尚未完成：
当前 Compose 的发布服务共用绑定地址设置，native/WSL 启动器仍显式监听所有网卡。不能只改绑定地址，
就把现有栈作为本文所述的隔离课堂环境开放使用。
