## 范围与问题

F36 保留/溢出 → F33 实时发布、F32 历史、F34 未读，并检查 F35 删除、私有替换、设置变更与后台

| 编号 | 复现 | 修复 |
|---|---|---|
| BH09-01 | 冷缓存只按内存长度执行 DropNew：SQL 已满仍发布 3 条；剩 2 格却发布 10 条；并发剩 10 格接受 30 条。写入时才丢弃，实时、未读与持久历史不一致。 | 按账号先加载 SQL 基线，再计算已准入的待写事件；满额在所有可见状态前拒绝。计数与会过期的写任务缓存分离；删除/替换/设置后重置，取消不占名额。 |
| BH09-02 | 写任务保留自身发送端，最后一个外部 EventBus 退出后，空队列、已降级队列及健康写完的队列均不结束。 | 写任务入口释放自身生产者句柄；存活运行时中，最后生产者退出可触发健康队列排空并释放状态。 |

## 仍有的限制与下一段

- 冷重载是在同一临时 Schema 上构造新 EventBus，不是杀进程、系统崩溃或断电恢复测试。
- 只协调一个 EventBus 的克隆；SQL 外部写入、多 Engine、持久重放与跨进程容量预留不在保证内。
  准入元数据像既有历史/设置一样保留到服务销毁，不新增总账号或总字节配额。
- SQL 健康且运行时继续执行时才验证排空；没有新增进程关闭钩子、整个写任务的期限或持久 ACK。
  SQL 停滞、丢失提交回执、重试重复插入与突然终止仍待单独设计/测试。
- 计数查询失败沿用原有锁定内存降级；恢复 SQL 不自动合并易失事件。历史/导出/未读读取自己的
  失败回退仍未修订，快照也仍可能落后于实时事件。
- 未改路由、权限、Event/API、数据库结构、SDK 或前端产品逻辑；未使用真实 Engine/Agent、SSH/LAN、
  部署 `.env`、数据库卷或内核。未新增 benchmark、真实浏览器到 Engine 或发行制品验收。
