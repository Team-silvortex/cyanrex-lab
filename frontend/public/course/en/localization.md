# Interface and documentation translation

Included in source **0.5.9**, originally reviewed after **0.5.8** on **2026-10-13**. English, Simplified Chinese, Spanish,
Japanese and Korean each explicitly contain **865 interface entries**, with matching interpolation parameters.
This is dictionary completeness, not a claim that every external diagnostic or third-party menu is translated.

## Interface behavior

The local payload editor translates the plain-text option, accessible input label and all **22 basic
snippet descriptions**. Changing interface language reads the current translations without replacing
the model, inserted code, payload revision or undo history. Language IDs and API names stay unchanged.

The eBPF editor translates local hover/completion explanations and repair titles. Local diagnostic
display uses the same presentation adapter. Repairs use stable local diagnostic identities before
the older untagged English-message compatibility path: translated wording never selects a repair.
Code insertion and clang's semantic details are unchanged.

Known teaching summaries, automated feedback, environment descriptions and common authentication
errors are translated when displayed. The adapter matches complete known legacy templates with bounded
parameters; unknown messages remain exactly as supplied. It does not change backend records or turn
display text into authorization, assessment or successful execution. Teacher comments and submitted
source never pass through this translation adapter.

Compiler/load stdout and stderr, OS/tool output, protocol fields, identifiers and code examples stay
literal. Monaco's third-party built-in menus and external language-service diagnostics are not given
a new global NLS configuration in this pass. These are separate from the owned interface dictionary.

## Documentation sources

Korean (`ko`, 한국어) is selectable on the login page and sidebar, with a browser-local preference.
The page language follows the selection; an English fallback article separately declares `lang="en"`.
Korean course bodies are not yet supplied. Missing Korean content first falls back to English, then
Simplified Chinese if English is unavailable, with a translated notice naming the actual language.
UI completeness does not mean course, teacher-authored content or third-party menu completeness.

Every Markdown theme under `docs/en` now has a `docs/zh-CN` counterpart, including the complete
[architecture proposal](next-architecture.md). Its original dates, versions, pinned evidence and
proposal status are retained; translation does not refresh architecture or release acceptance.
Explanatory diagram labels are translated without changing graph connections or state sequences.

Sixteen public guides outside these trees have adjacent Chinese companions: root README, contribution,
security, code of conduct and TDD policies; frontend/Engine guides; SDK usage/stability; Docker usage/
offline deployment; script inventory; and the module index plus three module guides. Each English
entry links to its Chinese companion. Executable examples and commands are preserved verbatim.

`docs/` is authoritative. `frontend/public/course/` is generated by
`node frontend/scripts/sync-course-docs.mjs`; edit sources, then synchronize. The `--check` option
checks byte-for-byte synchronization without changing either tree. Course sync is not translation
quality verification. Historical changelog entries and archived execution reports are not individually
translated or rewritten by this pass.

## Regression checks

- `frontend/tests/i18nCoverage.test.mjs` checks the complete merged dictionaries, non-empty values,
  interpolation parity and literal application translation calls in every supported locale.
- `editorLocalization.test.mjs` and `cIntelligenceLocalization.test.mjs` check actual registered
  providers, display changes, unchanged code, current ownership/cancellation and repair identity.
- `legacyLocalization.test.mjs` checks exact matching, preserved parameters and untouched unknown text.
- `koreanLocale.test.mjs` checks all 865 Korean keys, parameters, critical safety copy and legacy display.
- `koreanProviders.test.mjs` exercises actual providers/markers and all 121 legacy templates with the
  merged Korean dictionary, keeping insertion, raw diagnostics and repair identities unchanged.
- `koreanLocale.browser.mjs` checks live model/undo preservation, cancelled confirmation at 390/320 px,
  login/sidebar selection, persisted preference, actual English fallback and obsolete course-body rejection.
- `editorLocalization.browser.mjs` and `runtimeLocalization.browser.mjs` check actual production
  pages, Monaco suggestions/accessibility/undo, environment output and private teacher/source content.
- `scripts/tests/localizationDocs.test.mjs` checks bilingual themes, public-guide sections, exact
  executable code blocks and local Markdown destinations. It is not a full semantic translation review.

The pure tests join `npm run test:editor-languages`; browser entry is
`npm run test:localization-browser`. Existing common checks include the documentation guards, so no
extra CI workflow is required. Browser identity and backend responses are controlled fixtures, not
real authentication, kernel, LAN or deployment acceptance.
