## 已复现并修复

| 编号 | 边界 | 原有问题 | 修复 |
|---|---|---|---|
| BH03-01 | 输入/Engine/编辑器 → 缓存 | 全局缓存没有 Engine 或编辑器生命周期维度；分隔符歧义、同长度 32 位哈希碰撞会复用另一份结果 | 缓存仅属当前编辑器，以 Engine、目标、源码、头文件上下文的完整 JSON 组合区分；重新进入不复用 |
| BH03-02 | 异步完成 → 当前草稿 | 迟到成功/失败覆盖新结果，防抖期仍显示旧标记，迟到成功还写入缓存 | 视图绑定输入键，立即隐藏旧标记，异步返回后验证取消状态再更新界面和缓存 |
| BH03-03 | 共享请求 → 取消 | 共享 Promise 的取消权属于第一个编辑器，卸载它会中断另一个编辑器的检查 | 每个编辑器独立请求/取消，移除全局进行中请求表 |
| BH03-04 | 提交/轮询/响应体 → 超时和清理 | HTTP 提交或轮询卡住时，循环里的 35 秒判断无效；迟到提交在取消后仍进入轮询 | 整次请求可中断期限、轮询前取消检查，已知迟到作业 ID 尽力清理 |
| BH03-05 | 远程终态 → 诊断 | 取消/过期任务带标准化 `result` 时被当成代码问题 | 终态优先，显示不可用且不发布诊断，不重复取消已终结任务 |

## 保留与调整的行为

- 防抖仍是 700 毫秒，大草稿为 1,200 毫秒；空白或超限草稿不发送检查。
- 同一编辑器仍保留 8 秒、最多 24 项的成功/编译问题缓存。错误和已取消回调不缓存；使用完整键而非
  短哈希，内存会保留有界的源码字符串。放弃跨编辑器去重，以获得独立取消归属。
- 本地内联请求现在最多等待 20 秒；远程 35 秒从**发出提交**开始，包含响应体和轮询。服务端驱动期限、
  排队过期、已领取租约、所有者和响应结构不变。
- 正常编译拒绝仍是 `issues`，Clang note 仍映射信息标记；远程取消/过期为 `unavailable`。诊断不调用
  `/ebpf/run`，不迁移语义补全，也不自动回退本地；发送源码到远程前仍需显式确认。
- 请求携带会话、要求 no-store 并拒绝重定向。已知未完成任务最多尽力取消一次，取消单独限时 10 秒；
  已知终态不再取消。不增加自动重试。

## 限制和下一段

重新挂载隔离不等于跨标签页检测会话切换。其他位置改变的 HttpOnly Cookie 不会暴露给此 Hook，
服务端权限仍是最终判断；已保存草稿和持久化的目标选择不会清除。8 秒缓存不证明 Agent 此刻健康，
或头文件内容已经更新，除非传入上下文发生变化。浏览器暂停会影响计时，超时/尽力取消不证明服务端
已回滚；未知作业 ID 仍由服务端排队/租约清理兜底。当前标准化响应也不能区分“没有真实编译报告的
远程失败”和普通编译失败。
