## 范围与发现

F03 在 E32/E33 观察链路上的指标消费：私有读取 → 校验 → 热点显示 → 手动/自动刷新 →
不可用/过期/恢复。实际设置页同时验证与 F36 设置及相邻 F24/F25 Runner 控件的隔离；
共同显示在一个页面不等于新增地图边。Engine 指标采集、编译模式、Runner 传输与权限不变。

| 编号 | 修复前复现 | 修复 |
|---|---|---|
| BH14-01 | 畸形操作指标导致设置页面崩溃。 | 发布状态和计算热点前校验两类快照，失败不能拖垮设置表单与 Runner 面板。 |
| BH14-02 | 停滞请求不取消，一直占用刷新位置。 | 复用不缓存、不重定向且带会话的有界请求，头部和响应体共用 10 秒期限，之后可显式重试。 |
| BH14-03 | 导航没有取消旧读取或建立新请求归属。 | Engine/导航/挂载代次各自拥有请求、结果和定时器；旧响应与旧刷新回调不能发布或重启请求。 |
| BH14-04 | 后台失败保留旧数据而不报错，并保留先前刷新成功提示。 | 通用错误可见，保留样本但标明非当前数据，移除当前健康标签/配色；校验通过的新读取才恢复。 |
| BH14-05 | 切换语言触发额外指标读取。 | 状态保存翻译键、渲染时翻译，轮询不再依赖翻译回调。 |
| BH14-06 | 保存设置清掉无关的指标故障。 | 移除跨面板清提示行为，指标反馈归回自身面板。 |
| BH14-07 | 事件设置等待中禁用了独立的指标刷新。 | 指标刷新按钮只跟随自身请求状态，不依赖设置加载。 |

自动读取在完成后等 10 秒再启动，包括失败后；手动刷新合并在途请求，并重新计算下一次轮询时间。
Strict Mode 清理、导航与卸载会取消所属请求；切换范围立即隐藏旧样本。没有新增自动写入或变更重试，
普通的延迟**只读**轮询仍会继续。

计数及显示用加总须为非负 JavaScript 安全整数。时延允许非负有限小数，上限为
Number.MAX_SAFE_INTEGER 毫秒，高于 Engine 的 u64 纳秒表示范围。忽略扩展字段，拒绝缺失、
非数值、不安全或非有限字段。不强加跨计数相等/先后关系：Engine 各原子计数独立采样，不是同一事务。
服务端指标含义与 API Schema 不变。

存在的 error 字段仍为空。初版解析测试还把 MAX_SAFE_INTEGER + 0 误当溢出，已把夹具改为加一。
两份诊断均保留，不作为新增产品问题。

SettingsPage、实际确认/语言组件、React Strict Mode、受控响应和浏览器时钟，阻断非夹具网络。

## 限制与下一块

- 指标仍是进程内近似观察，不是分布式追踪、当前 Engine 健康证明、权限证明或原子快照；
  成功样本也可能在下一次轮询前变旧。
- 期限约束协作式浏览器等待，不限制 CPU/事件循环停滞或服务端任务；读取失败不撤销其他已派发的
  设置或 Runner 操作。
- 本轮只验证指标故障时 Runner 面板仍可用、正常取消仍需确认；没有验证 Runner 自身清单解码、
  期限、失败回执与导航取消安全。
- 未运行 Rust/SQL/SDK 运行时测试、整个项目门禁、远端 CI、全部可选浏览器套件、实际浏览器到
  Engine 串联、部署/局域网/内核验收或新一轮性能基准。
