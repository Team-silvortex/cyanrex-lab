| 编号 | 复现 | 修复 |
|---|---|---|
| BH11-01 | 已读/删除 SQL 失败、此前发布的写屏障失败或已经锁定降级时，仍可能返回 `200`，并未确认持久修改。 | HTTP 改用可失败确认，与旧尽力返回帮助函数分开；非法/不可用配置和失败屏障返回通用 no-store `503`，不再以内存修改冒充成功。明确的查询/建表失败保留历史/未读，修复后可重试。 |
| BH11-02 | SQL 已提交但缓存发布被锁阻塞时，调用方等待超过测试的 12 秒上界。 | 服务层协作式等待最多 10 秒，包含账号准入；已交接 SQL 的任务在调用方取消/超时后，仍持有账号顺序直到缓存发布结束。返回结果未确认，而非成功或“已回滚”。 |
| BH11-03 | HTTP 成功确认没有 no-store；删除参数解析另走纯文本错误分支。 | 成功及处理器错误都不缓存；删除参数解析与校验统一为通用 JSON `400`。先失败断言验证已读成功头缺失，最终扩展测试覆盖两条成功路径及非法/未知/重复参数。 |

确认后的 SQL 删除计数包含未缓存行，保留剩余行的已读标志，等待此前本地发布落库；冷缓存也会

无筛选删全部、旧版忽略的 owner 字段、成功格式与 SDK 签名不变。内存删除在取得历史/未读/容量锁
后才修改，防止取消留下缓存半更新；此项属于补充防退化测试，不另算已独立复现的旧缺陷。

## 限制与下一块

- 未确认不等于回滚：SQL 或缓存发布可能在取消、超时、响应丢失之后完成。测试明确验证响应超时后
  的完成，不把 SQL 超时解释为数据库已回滚。先核实状态再手动重试，本轮未新增自动重试。
- 10 秒只约束服务层协作式等待，不含认证、序列化、CPU 阻塞或后台任务整个生命周期；已交接任务
  仍可能等待缓存锁。准入前取消不派发；交接后取消不终止操作。
- 明确查询/建表错误可重试，但原有屏障/存储超时或独立写任务失败仍可能锁定降级。修复/重启不
  合并易失事件，没有新增退出排空、断网/提交回包丢失注入、崩溃/断电恢复或持久重放。
- 顺序仅覆盖一个 EventBus 的克隆，不协调其他 Engine 或外部写入者。旧不可失败变更 API、设置和
  事件发布降级保持原有契约；显式纯内存 HTTP 成功仍是易失操作。
- 前端源码未变，现有测试覆盖错误处理，但不是新一轮真实浏览器到 Engine 验收。未运行远端 CI、
  Rust 依赖审计、可选浏览器、新基准、SSH/局域网/内核/部署或发布产物验收。
