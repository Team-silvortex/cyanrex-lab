# ADR-021 会话授权的目录定义任务

状态：**C2-I 已收录于源码版本 0.4.9**。决定日期：**2026-10-03**。

本阶段把[版本化任务目录](task-domain-boundary.md)接到当前 Session 授权的私人任务操作。成员
可按服务端允许的准确任务定义创建、读取和推进任务，并引用 0–32 个自己拥有的 Artifact 输入。
复用[任务输入事务](session-task-inputs.md)，不新增教学专用任务类型，不要求 Run，不执行规则或
验收 Task。源码版本 0.4.9 保持现有教学数据、公共 API 和在线认证不变。

## 可信定义配置

仅 Unix 支持的 `SessionCatalogTaskWorkspace::new(tasks, artifacts, catalog)` 接受可信
服务器配置。Task 与 Artifact 句柄必须指向不同命名空间，且 authority/Workspace 一致；命令
使用来源连接访问同一数据库中已初始化的存储，不调用安装器、迁移、文件修复或第二个事务。

句柄把不可变 `TaskCatalog` 定义列表复制到私有共享存储，不保留提供器或其证据类型，不在授权
期间调用 `assess`、发现包或执行领域代码。原目录/提供器销毁后，句柄仍可使用。沿用目录 1–256
个定义的上限，客户端不能反序列化或替换句柄字段。复制的条目是此句柄的显式定义白名单，不是
动态策略注册表。

命令只从该白名单选择准确的包名称/版本和定义名称/版本，不能自报定义信息、证据 Schema 或策略。
创建时把完整 `TaskDefinition` 复制进 Task。读取和状态变更时，将保存的完整快照与配置比较，
包括核心 Schema 版本、定义/包引用、证据 Schema、评估策略、标题和摘要。准确条目缺失返回
`UnknownDefinition`，同一引用下信息不同返回 `DefinitionMismatch`；两者都不回退到 latest，
也不静默改写旧任务。此适配器拒绝没有目录定义的任务。

即使只改定义的展示信息，若旧任务仍需使用，也应明确新增版本。配置中保留旧条目才能继续操作旧
任务，不同定义版本可同时存在。创建新句柄不会撤销旧句柄或持久化目录变更；包真实性、持久目录
生命周期和协调配置替换仍不属于本准备层。

## 操作与输入边界

| 来源操作 | Session 与配置之外的输入 | 确认后的结果 |
|---|---|---|
| `create_session_catalog_task` | Task ID、准确定义引用、标题、0–32 个 Artifact 引用 | 带固定定义的 Draft 任务修订 1 |
| `get_session_catalog_task` | Task ID | `SessionTaskInputs { task, inputs }`；不存在或他人所有则无记录 |
| `transition_session_catalog_task` | Task ID、预期修订、已有目标状态 | 标题、定义、输入不变的新 Task 修订 |
| `replace_session_catalog_task_inputs`（[C2-J](session-task-revisions.md)） | Task ID、预期修订、0–32 个准确引用 | 替换有序输入、定义不变的 Draft |

所有者来自当前账号代次、有效审计 Human 成员和有效 Workspace。教师/部署权限不能扩大对他人
私人任务或输入的访问。原手工入口保持严格：C2-E 只支持无定义、无引用的任务；C2-G 只支持无定义
且有 1–32 个输入的任务，不变成绕过目录检查的入口。

准确输入固定 Workspace、Artifact ID、版本 ID 与摘要。重复坐标、超限列表、缺失内容、他人所有
或字节不匹配/损坏均被拒绝。读取保持保存的顺序与旧版本，最多返回 32 MiB 字节及元数据。输入
校验不把字节转换成提供器的类型化 Evidence，也不验证其领域证据语义；Artifact 类型或 MIME
标签不能代替该契约。

零输入目录任务返回空 `inputs`，不需要伪造文件或 Run。Task 写入前后仍固定 Artifact 命名空间，
校验并锁定其 Schema 元数据和作用域；空输入不能绕过存储缺失、替换或作用域错误。这种情况不读
内容文件，但构造配置时仍需要一个现有私有 Artifact 根目录。

## 共享授权事务

目录任务与手工输入任务使用同一个来源事务执行器，通过私有策略分支区分准入条件。先锁来源和
注册表，再锁 Task 元数据/头记录，最后锁 Artifact 元数据并按固定顺序锁制品头；任何写入之前
固定命名空间身份。Task 被锁定时检查定义准入及准确内容；写后复验内容与待返回任务，最终由共享
检查复核全部命名空间、身份、成员和使用数据库新鲜时间核对的准确 Session。只有确认提交成功，
才返回记录或保留的字节。

沿用原修订保护状态图，不新增 accepted/completed 状态，不根据规则结果或私人 `approved`
Review 自动推进任务。定义缺失或输入损坏同样阻止此入口取消任务，没有紧急绕过或修复旁路。
保留整体 10 秒、语句 5 秒、锁等待 2 秒的时限；成功、失败和取消均须恢复事务局部搜索路径。

不写入或删除 Artifact 文件/事件。文件校验不能防止同一 Unix UID 在验证后修改内容；最终会话
检查不保证任意延迟 COMMIT 期间持续有效。超时、取消或丢失响应不能证明回滚；没有自动重试、
成功回执重放、内容接管或恢复。可信直接 Task/Artifact 写入仍保留，信息一致不证明旧 Task 原本
经过 Session 命令创建。

## 验证与剩余工作

3 条默认测试和 16 条显式 PostgreSQL 用例覆盖非教学提供器、提供器生命周期独立、准确版本、
同编号信息漂移、零输入元数据检查、顺序固定的私人输入、严格手工边界、生命周期撤权、修订竞争、
写入/命名空间故障、锁等待、过期/登出
及取消。显式 CI 入口 `scripts/test-session-catalog-tasks.sh` 先检查每个准确名称存在，再在
一次性 PostgreSQL 上执行。实际结果和没有重跑的检查见[项目状态](project-status.md)，与覆盖
描述分开；故障夹具不能作用于现用数据。

这只是定义准入与信息一致性，不是领域证据验证或评估策略执行。认证规则 Review 签发、跨用户
资源/审阅者授权、历史写入来源、验收策略、公共 HTTP/CSRF/UI、迁移和在线切换仍待完成。原 C2-I
切片不改 Schema；后续 [C2-J](session-task-revisions.md)要求全新 Task 存储 Schema 2，拒绝
Schema 1 而不迁移。冻结 API/SDK 契约不变；C2 及多人 C-M5 工作流尚未完成。
