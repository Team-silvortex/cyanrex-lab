这些值为[集中分发](large-file-distribution.md)定义准确的文件权限候选，不签发、保存或认证授权。

## 准确绑定

| 值 | 必需绑定 |
|---|---|
| `FileAccountRef` | `PrincipalRef` 和准确 `LegacyAccountId` 账号代次，不是用户名 |
| `FileVersionRef` | Authority／工作区、文件 ID、不可变版本 ID、字节长度和 SHA-256 |
| `FilePublisherGrant` | 契约 Schema、非空 `FileGrantId`、正修订号、工作区、主体账号、有效期及状态 |
| `FileRecipientGrant` | 契约 Schema、非空 `FileGrantId`、正修订号、准确文件、发布者账号、接收者账号、有效期及状态 |

所有账号的 Authority 必须等于选中工作区的 Authority。版本引用从所提供
`FileTransferManifest` 投影，不进行 IO，也不证明发布或保留原存储代次。
展示名和路径不决定权限。不同文件、版本、工作区或账号代次即使摘要相同也不匹配。

`FileGrantValidity` 要求整数 Unix 秒，满足
`0 <= not_before < expires_at <= 253402300799`，没有可空或永久有效期。
区间是 `[not_before, expires_at)`：起始秒可匹配，到期秒不匹配；提供越界时钟也不匹配。
这是时间表示，不是可信时钟来源或授权时长策略。

## 独立操作

`FilePublisherGrant::matches(workspace, subject, now)` 要求准确主体、工作区、活跃状态和
当前有效区间。`FileRecipientGrant::matches(file, publisher, recipient, now)` 还要求
所有准确版本字段和双方账号代次一致。

发布许可负责候选发布与新分享操作；接收许可是读取已选版本的独立候选。
撤销发布许可不隐式撤销已有接收许可，停止那些分享需要分别明确撤销。
可以显式把自己设为接收者，但所有权不会自动生成许可。教师、工作区所有者及部署角色
都不自动提供这两种权限。

两个选择器只返回布尔值。授权 ID、修订号和活跃状态是所提供数据，不是签发者归属、
审计来源、当前策略或持有即授权的凭证。真实记录撤销后，旧活跃副本仍可能匹配。
调用方不得缓存布尔结果作为权限，也不得把客户端授权 JSON 当成认证过的许可。

## 严格元数据解码

两个授权类型的 `parse_json` 都限制输入为 **4096 字节**。每层嵌套记录必须是对象，
包括 Principal 和工作区引用；缺失、null、重复、未知字段及位置数组都拒绝。
ID 和摘要沿用规范标量编码；Schema、修订号、长度和时间要求准确且受支持的整数。
版本长度保持清单上限及空文件摘要规则。
状态只接受 `active` 和 `revoked` 两个字符串，不接受 Serde 外部标签对象别名，例如 `{"active":null}`。

通用 Serde 解码仍验证结构，但不限制原 JSON 字节数，使用它的调用方必须自行执行
输入准入。解析不读取数据库或文件，不检查 Session、身份状态、成员关系、发布状态或真实字节。

## 持久授权边界

下一层持久服务必须认证授权管理操作、保存签发者／审计来源和修订变化，并固定自身范围及
安装身份。当前 Session 操作必须从审计过的当前身份推导接收者或发布者账号，而不是接收
客户端声明。读取必须比较受信任 Published 清单及所有者／账号，随后在受保护事务内
新鲜复核当前授权修订、撤销、成员关系、账号代次和数据库时间。
字节工作另需审阅准入及进行中请求的撤权窗口。

现有[Session 私有元数据](large-file-session-metadata.md)命令仍只允许本人访问，不使用这些
契约。没有新增 Schema、迁移、安装器、线上认证变化、HTTP／SDK／UI 连接、文件访问、
网络传输、回执恢复或部署变化。
