| 编号 | 修复前复现 | 修复 |
|---|---|---|
| BH13-01 | 读取失败后仍能保存缓存/默认值。 | 仅已校验的服务端事件设置可建立就绪状态；读取失败锁定编辑，需显式重新读取，缓存草稿不算确认。 |
| BH13-02 | Strict Mode 的旧读取把当前 500/DropOldest 覆盖为 800。 | 请求代次绑定 Engine、导航与重新读取，取消旧请求并禁止迟到响应发布。 |
| BH13-03 | 事件回执 `ok: "true"` 仍触发编译器写入。 | 严格校验字段、布尔回执及与确认草稿一致的归一化值，再推进下一步。 |
| BH13-04 | 事件保存中导航离开，迟到响应仍发送第二步编译器保存。 | 确认信号关联请求取消，各异步交接检查归属；卸载后也不能继续写入或发布迟到状态。 |
| BH13-05 | 事件已成功、编译器失败时只显示后端原始文本，未核实便可再次保存。 | 四语言明确提示部分成功/未确认，保留已确认的事件状态、刷新未读，并要求重新读取后再保存。 |
| BH13-06 | 初始请求停滞没有期限，也没有重新读取入口。 | 请求不缓存、不重定向；读取 10 秒、每次写入 20 秒的等待期限覆盖头部和响应体，不自动重试变更。 |

编译器读取不可用时明确标注只能保存事件设置。确认冻结归一化草稿并禁用编辑；空白/小数上限拒绝，
有效整数仍按 50..50000 截断。重新读取只读、不重试旧保存，丢弃已编辑草稿要确认；刷新指标不能
抹掉部分保存警告。本轮未改变 Engine/API/数据库/角色或共享确认组件；指标与 Agent 请求仍分开处理。

  读取不保证多进程一致性，也不是两类设置的原子快照；另一教师可能在步骤间改变全局编译器模式。

  事件设置仍按账号隔离，编译器模式仍为全局。

  全部可选浏览器套件、Rust 依赖审计、部署/局域网/内核验收。
