# 大文件私有分块暂存

已收录于源码版本 **0.5.6**。下方分日期实施和验证保留原 0.5.5／未发布阶段及范围；
源码收录不启用网络传输或公共 API。

状态：**Unreleased Unix 准备层**，源码 **0.5.5**，日期 **2026-10-11**。
这是[提案 #2](https://github.com/Team-silvortex/cyanrex-lab/issues/2)的第二步：在显式给定的私有目录
中存储准确校验的分块，并独立限制后台工作。它建立在[流式核心](large-file-core.md)之上，
不启用网络传输。[分发提案](large-file-distribution.md)中的持久上传状态、磁盘预留、重启恢复、
发布和接收授权仍需单独完成。

## 受信任接口与身份绑定

[`ChunkStaging`](../../engine/src/services/file_transfer/staging/mod.rs)仅支持 Unix。
`open(scope, root, workers)`接受既有绝对私有根目录及 **1–16** 的受信任工作额度，
不创建或修改根目录。清单工作区必须准确匹配固定范围，块序号必须存在。这不认证给定的
范围、发布者或读取者，也没有任何不可信路由调用此接口。

| 操作 | 成功含义 | 不代表 |
|---|---|---|
| `stage_chunk(manifest, index, reader)` | 准确块复制、校验、封存、同步，并从创建时原 inode 读回通过 | 整文件完整性、上传日志记录、发布、授权送达或重放许可 |
| `verify_staged_chunk(manifest, index)` | 当前私有文件项及真实字节检查通过 | 历史写入已确认、恢复、收编或持久上传进度 |

不透明文件名绑定**整份规范 typed 清单**的 SHA-256 与块序号。指纹通过流式序列化计算，
不分配完整 JSON 缓冲。显示名称、请求 URL 或调用方给定文件名不会决定磁盘路径。
即使块内容相同，另一份清单也不能使用原清单的文件项。

## 私有文件与故障处理

根目录必须为当前用户拥有的 **0700** 目录，固定设备与 inode。逐层描述符相对遍历拒绝
符号链接及不可信可写父目录；仅显式允许 `/tmp` 这类 root 所有的 sticky 目录。
每次工作前后复查根路径。这是可观察身份核对，不永久阻止同 UID 或 root 修改。

创建使用 `O_EXCL` 与 `O_NOFOLLOW`；**任何已有目标都只返回冲突**，即使字节正确。
新文件必须为单链接普通文件，请求初始 0600，`umask`可能进一步收紧。原 **64 KiB** 复制循环准确检查长度、块摘要及
最终结束，再设为 **0400**、同步文件与目录、读回创建时原 inode。前后元数据与可见文件项
身份核对拒绝可观察替换或变化。本层不要求再组装一份完整文件副本。

`InvalidInput`与`CapacityExhausted`在派发前拒绝；根目录预检失败为`Unavailable`，
已有文件项为`Conflict`。其他创建错误及成功创建后的任何失败均为 **`Unconfirmed`**。
可能留下私有权限的部分字节或完整 0400 字节，不覆盖、不自动删除、收编或重试。
普通读取校验失败为`Unavailable`；后台任务异常保守返回`Unconfirmed`。

后续验证残留文件仅观察当前状态，不能把丢失或失败的写入确认变成历史成功。
后续上传日志必须区分这些状态。单块通过也不证明多块清单的有序整文件摘要。
0400 不是防同 UID/root 修改的 WORM 存储；本地文件系统确认同步也不等于已经验收断电
恢复或硬件持久性。

## 工作生命周期与剩余限额

克隆共享一个立即拒绝超额工作的 semaphore。先准入，再复制清单与派发；真实阻塞任务在
**排队或运行**期间都持有额度。等待方被丢弃、取消或超时不会提前释放，任务真正结束才释放。
不新增等待准入队列或隐藏重试；读取校验也使用同一文件工作额度。

独立打开的句柄有独立且可叠加的额度；这不是进程级、分布式、密码工作、HTTP 响应或磁盘配额。
给定读取者可无限阻塞；没有任务强杀、墙钟期限、带宽上限、预留字节或全局内存保障。
因此在独立入口/存储准入完成前，创建多份清单或句柄仍仅限受信任调用者。
调用方在准入前已经持有读取者，本额度也不限制这些外部资源。

## 验证与接线边界

默认 Rust 测试使用私有文件与确定性后台工作屏障，不依赖数据库或网络。
真实文件跨 **4 MiB** 边界，故障路径保留不确定输出并带健康对照；实际运行记录见
[项目状态](project-status.md)。这些用例不验收真实磁盘满/fsync 故障、断电恢复、RSS/吞吐、
认证网络、浏览器保存、TLS/局域网部署或桌面互通。

本暂存 API 自身不增加 SQL 上传 Schema、日志、配额预留、清理 API、发布、接收授权、HTTP 路由、在线
`AppState`、启动安装、迁移、OpenAPI/SDK 或客户端接线；Artifact/文本限额和发布版本不变。
后续[上传意图账本](large-file-upload-intent.md)现提供独立受信任元数据与逻辑预留，
尚不连接或收编本层文件。
另行的[上传绑定适配](large-file-upload-staging.md)现为自身固定目标产生原文件本地回执，
不收编旧式文件，也不记录持久进度。
独立[分块日志](large-file-chunk-journal.md)、[整字节核验](large-file-whole-verification.md)及
[发布元数据](large-file-publication.md)现基于该绑定路径，而非旧式文件。
回执丢失/重启协调、物理磁盘策略、当前授权、传输与安全客户端送达仍是独立门槛，
本私有暂存 API 不提供这些能力。
