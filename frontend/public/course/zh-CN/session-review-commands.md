# ADR-020 会话授权的私人人工审阅

状态：**C2-H 已收录于源码版本 0.4.9**。决定日期：**2026-10-03**。

本阶段把当前 Session、私人人工 Review 历史及自己拥有的准确 Artifact 目标/证据组合到同一来源
事务，扩展[审阅存储](review-record-store.md)，不接入现有教学流程。包括 `approved` 在内的个人
意见不等于 Task 验收、审阅他人内容的权限，也不证明策略已执行。源码版本 0.4.9 不切换
在线路由、认证来源、Schema 或现用数据。

## 配置与操作

仅 Unix 支持的 `SessionReviewWorkspace::new(namespace, scope, artifacts, policy)` 接受可信
服务器配置，字段私有、不可从请求反序列化。Review、现有 `SessionArtifactWorkspace` 与来源/
注册表须为同一数据库中已经初始化的独立命名空间；两类资源必须匹配同一 authority/Workspace。
准确的策略名称和版本由配置固定，不来自命令请求。配置不安装或执行策略，不创建目录或修复存储。

| 来源操作 | Session 与配置之外的输入 | 确认后的结果 |
|---|---|---|
| `create_session_review` | Review ID、准确目标、准确证据、`HumanReviewEdit` | 人工 Review 修订 1 |
| `read_session_review` | 准确 `ReviewRef` | 指定历史记录；不存在、未来修订或他人所有则返回无记录 |
| `revise_session_review` | 预期当前 `ReviewRef` 与 `HumanReviewEdit` | 下一不可变人工修订 |

审阅者来自当前账号代次、有效且经过审计的 Human、有效 Workspace 与有效审计成员关系。不要求
教学或部署权限；这些权限也不能越权读取别人的私人 Review 或内容。命令不接受自报审阅者、来源、
策略、规则结果或领域定义。Rule 记录及策略名称/版本不匹配的 Human 记录均被拒绝。更换策略需要
新建 Review，不会静默升级旧意见。

目标要求 1–32 个准确 Artifact 引用，证据允许 0–32 个。每个引用固定 Workspace、Artifact ID、
版本 ID 与摘要。同一列表内的重复坐标、两列表间同坐标的冲突摘要均被拒绝；同一准确引用可以同时
作为目标和证据。所有目标与证据都必须归当前 Session 的 Principal 所有，并能读取到校验一致的
字节。知道他人的内容摘要不产生访问权限。

修改只改变结论、评语及派生的修订号、时间和前驱；审阅者、目标、证据与策略固定不变。沿用原有
评语上限与整条记录 64 KiB 上限。Artifact 出现新版本不会使旧 Review 跟随 latest。读取仅返回
记录、不返回内容字节；历史意见可能已经被后续修订替代。

## 事务与锁定边界

来源拥有连接、事务和提交权。共享私人工作检查先验证来源与审计成员，再锁 Review 元数据和当前
归属匹配的头记录，随后锁 Artifact 元数据和头记录。目标与证据合并后按 Artifact/版本 ID 全局
排序，仅在完整引用一致时去重；逐个校验字节后丢弃，不依赖 Task、Run 或教学代码。

借用 Review 读取在 READ COMMITTED 下先锁当前头，再校验最新事件与指定历史，并保留固定目标/
策略一致性检查。直接可信存储的独立读取仍使用 REPEATABLE READ、READ ONLY 快照；不能把该
无行锁实现直接借到来源事务作为授权读取。

任何 Review 写入前都固定 Artifact 命名空间最初的名称和 OID。头记录、修订和 outbox 写完后，
再次核验全部内容，再回读完整待返回 Review，以发现行锁无法阻止的同事务触发器副作用。返回旧
命名空间时核对最初固定值，不接受同名替代对象。最终检查全部命名空间、来源、身份、成员关系，
最后用等待后的数据库新鲜时间核对准确 Session，且确认唯一一次提交成功后才返回记录。最终会话
检查不承诺在任意延迟的 COMMIT 期间持续有效。

## 失败与权限限制

缺失、他人所有、不匹配或损坏的内容都会阻止创建、读取和修改，不会静默丢弃证据。Review/历史/
事件故障、命名空间替换、过期修订、成员撤权或 Session 过期均不产生成功记录。沿用整体 10 秒、
语句 5 秒、锁等待 2 秒的上限，不降级到内存；成功、失败或取消后均须恢复事务局部搜索路径。

此适配器不写入、删除或修复制品文件，也不生成 Artifact 变更事件。超时的阻塞文件读取可能继续。
取消、超时或丢失提交响应不能证明回滚；没有自动重试、恢复或成功回执重放。检查保护协作写入路径，
不能防御协同篡改数据库或同一 Unix UID 在校验后修改文件。准确内容验证不证明作者或证据语义充分。

可信直接 Review/Artifact 写入仍保留，没有来源标记或切换栅栏；因此历史记录可访问不代表最初通过
Session 创建。固定策略只是显式配置标签，不证明策略已安装、评估或具备授权效力。`Approved`
仍是个人意见，不能推进 Task。规则/Agent 签发、跨用户审阅授权、适用领域策略、Task 验收、公共
HTTP/CSRF/UI、迁移、保留策略与可靠 Run/事件交付仍待完成，不代表 C2 或 C-M2/C-M5 整体验收。

## 验证

3 条默认测试与 18 条显式 PostgreSQL 用例覆盖配置与上限、无教学角色的私人归属、准确历史/策略
固定、生命周期撤权、损坏目标/证据、
抑制写入、提交失败、命名空间替换、锁顺序、会话过期/登出及取消。显式 CI 入口
`scripts/test-session-review-storage.sh` 须逐项确认准确测试
名称存在，再使用一次性 PostgreSQL 数据库。实际执行结果和未重跑检查见[项目状态](project-status.md)，
覆盖描述本身不表示全部验证已经通过。故障夹具绝不能作用于现用数据。
