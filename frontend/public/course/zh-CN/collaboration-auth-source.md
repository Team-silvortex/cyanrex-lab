## 决定与范围

[持久认证源](../../engine/src/services/auth_service/durable_source/mod.rs)接收注入的 PostgreSQL
连接池和明确固定的 `AuthorityId`。不读取环境配置，不种子化教师，不设内存凭据/会话存储，也不在
数据库失败时降级。一个 Schema 只属于一个认证源；换 authority 打开会失败，不新建另一套身份。

注册把随机非 nil 的 `LegacyAccountId` 与用户名、凭据一起提交；会话同时绑定**用户名和准确的
账号创建代次**。删除后同名重建使用另一代次，不能继承旧会话或注册表身份。安装后的 Schema
禁止原地改写账号/会话坐标及会话摘要。

| 内部操作 | 确认结果与边界 |
|---|---|
| `install_empty_schema` | 仅显式安装到不存在或结构兼容的空认证表；不导入、回填账号 |
| `register` | 提交确认后返回新代次及 TOTP 设置；不创建 Principal、角色、Membership 或 Grant |
| `login` | 核对密码/TOTP、当前代次并提交会话；数据库仅保存 token 的 SHA-256 摘要 |
| `validate_session` | 只读、实时核对准确账号/会话及过期时间；不清理、不查角色、不分配身份 |
| `logout` | 确认删除这一条会话，不存在时幂等；不是账号退役、设备退出或内核资源清理 |
| `prune_expired_sessions`（收录于 0.5.2） | 可信维护每次最多清理 128 条过期 Session；只返回确认的本批数量，不证明来源已空 |

这些只是可信适配器的内部原语，注册不是公开加入或教师引导。`DurableAccountRef` 和
`DurableSession` 都可由调用方构造，且只是读取时的数据/快照，**不能作为后续身份或策略命令的
授权凭证**。不接入路由、AppState，也不切换现有 AuthService；HTTP/SDK 及教师/学生流程不变。

## 显式安装，不推断迁移

原 C1-E 阶段的[安装器](../../engine/src/services/auth_service/durable_source/schema.rs)以 Schema 级 advisory lock
串行化安装，再锁住两张认证表检查为空；校验旧字段类型、非空约束、主键及级联外键的实际目标，
随后执行新增 [0010 模板](../../engine/migrations/0010_durable_auth_source.sql)，登记认证源 Schema 1
和固定 authority。DDL、约束与启用状态同事务提交。已发布的 0001–0009 模板不改写，启动和读取不调用安装器。

非空旧表直接拒绝，不分配 ID、不改凭据、不撤销会话。即使是空表，缺少会话主键也不兼容：字段
投影成功不证明唯一性。回归先复现该缺口，再补充目录校验，同时拒绝缺外键、凭据可空及时间类型错误。
这一要求记录在限定模块范围的[维护规则](../../.github/instructions/durable-auth-source.instructions.md)。

重复安装核对现有结构、坐标不可改写触发器、版本及 authority，不修补缺失状态。新代次字段无默认值，
旧 SQL 插入省略它会失败；**但这不能封锁旧 AuthService 的内存降级及全部旧写入口**：旧运行时仍可
降级、改凭据或删除记录。禁止把两套实现同时指向启用后的 Schema；真实切换必须另做旧写入封锁和
经过审查的迁移。结构检查/触发器只保护遵守协议的代码，不抵抗数据库所有者篡改。

## 事务与认证

认证源修改先对元数据行取 `FOR UPDATE`，一致性读取取 `FOR SHARE`，之后才锁账号/会话行，
包括尚不存在的键。当前有意让同源写入跨连接池串行；会话读取会等待未提交的退出，再观察删除结果，
而非返回缓存。整个调用十秒、锁等待两秒、单条 SQL 五秒上限。

原切片复用现有 Argon2 密码助手；下方后续章节增加专用准入和固定参数策略。昂贵验证期间不占用
数据库事务。登录先读凭据并验证密码/TOTP，
再取得源/行锁，完整比对凭据快照及账号代次后插入会话；插入后再查一遍，防止触发器在同一事务中
更改身份或凭据。增删确认影响行数及最终读回，提交确认前不返回账号 ID、设置密钥或原始 token。
含密钥的注册/登录返回包装不实现 Debug 或 Serialize。

会话从锁等待后的数据库实时时间起有效十二小时；读取也在行锁之后检查数据库实时时间，不使用
事务开始时间。过期会话只拒绝，不在读取时悄悄删除。取消、超时、提交响应丢失仍**不证明回滚**；
注册结果不确定时不能换代次重试，本切片不提供持久命令回执、重取设置密钥或自动补偿/对账接口。

登录准入有界但**仅进程内有效**：克隆实例共享最多 1,024 个用户名条目，每名在固定五分钟窗口最多
准入五次；包括存储错误在内的准入后失败计入次数，确认登录成功清除条目。独立构造的新实例不共享
此限制。密码最多 4,096 字节、OTP 最多 64 字节，注册密码至少八字节。向不可信客户端公开前，仍须
补齐分布式限流、公开注册策略以及 HTTP/CSRF 接入。下方后续章节补充了仅针对准备层的进程内
任务准入和明确的存储哈希成本策略。

### 未发布会话边界加固 · 2026-10-03

`login`、`validate_session`、`logout` 现在先固定当前命名空间及 `users`、`sessions`、来源元数据
三张实际关系的身份。要求单个有效的私有规范 Schema、没有临时命名空间、持久普通表、已验证且
不可延迟的主键、无行级过滤或继承，并满足既有来源结构与 authority 契约。只检查这三张来源表，
不要求注册表存在，也不隐式安装注册表。

登录跨密码验证保留第一段事务的命名空间/表身份，在第二段事务核对；相同凭据的替代表并不是
原来的来源。写入后先核对当前路径，不能先恢复路径掩盖漂移，再复查关系、结构及 authority 后
读回结果；所有防护等待之后再检查会话实时有效期。退出必须在原来源确认会话不存在。
回归复现了一个真实问题：DELETE 被触发器抑制，后续读取被改向空影子表，旧实现却返回退出成功，
实际会话仍然可用。新防护拒绝这一事务并回滚。

同一次操作内原始 `search_path` 字符串也须完全相同，包括登录两段事务从池里取得的连接。
即使不同引号写法解析到同一 Schema，也会拒绝；这不是跨独立来源实例或不同请求的全局路径固定。

这是对三个原语的明确收紧：不接受 `public`、系统或多个有效 Schema、临时命名空间及过滤/替换
关系。本轮不重构安装、注册、改密/删除命令或在线 AuthService，也不声称所有原语已有一致连接
规则，不修复结构、不迁移数据、不授权公开端点。共享的私有工作命名空间规则和注册表检查仍单独
成立；不能据此推导对数据库所有者篡改的防护，也不改变提交结果不确定的语义。

下方后续改动按任务存活期限制准备层准入、固定哈希成本，并增加 Schema 2 OTP 消费。面向不可信
客户端签发 Session 前，仍须明确账号枚举时序策略、入口/会话限额及恢复组合。用户名计数器或专用
Cookie 名不提供这些保证。C2-N 仍是未挂载的内容路由，不是登录流程。

后续回归位于[会话边界目标](../../engine/tests/durable_session_boundary_tdd.rs)及其子模块，
准确选择入口为 [`test-durable-session-boundary.sh`](../../scripts/test-durable-session-boundary.sh)。
实际执行结果单独记录在[项目进度](project-status.md)，不加入下方历史 C1-E 总数。

### 未发布密码工作准入 · 2026-10-03

准备层注册、登录、改密和空权威初始化共用一个进程内密码工作限额，包括独立创建的来源实例与
连接池。最多向 Tokio 阻塞执行器**派发 4 项计算，总准入 20 项**，总数包含已派发和等待工作名额
的请求。这是保守的固定准入策略，不是经过 benchmark 得出的容量；满额返回 `RateLimited`，
不建立无界内部等待队列，也不新增环境或配置覆盖入口。

等待仍在原操作十秒预算内，并且不持有数据库事务。取得两个名额之后才复制密码材料给阻塞任务；
派发前取消会释放准入且不开始计算。派发后两个名额由阻塞闭包持有，包括尚未被 Tokio 调度的
阶段；调用者取消或超时不能提前归还。计算结束或栈展开才释放名额，工作线程失败返回
`StorageUnavailable`，不能伪装成密码错误。已派发计算可能在调用者消失后结束，但不会恢复已丢弃
的数据库命令。

此限额本身约束**任务数量**，不约束单项计算的内存、成本或耗时；下方独立的存储哈希改动固定
可接受的参数，但两者都不是耗时或进程 RSS 硬上限。也不迁移凭据、不引入 OTP 消费、分布式配额或来源间公平性
保证。旧在线 AuthService 助手与默认教师的同步初始化不使用此限额，因此不是整个进程全部密码
计算的上限。仍未增加 HTTP 签发或在线切换。

确定性的生命周期测试与私有工作实现放在一起，另用源码接线检查拒绝五个准备层哈希/校验调用点
绕过防护。实际测试数量和相邻数据库重跑结果单独保存在[项目进度](project-status.md)。

### 未发布存储密码哈希策略 · 2026-10-03

准备层账号读取和密码验证现在会在工作准入、复制密码前拒绝不支持的 PHC 记录。解析前先限制
文本不超过 1,024 字节；只接受 `argon2id`、明确的 `v=19`，以及各出现一次的 `m=19456`、`t=2`、
`p=1`（顺序可变）和 32 字节摘要。缺项、重复、额外或非规范参数均拒绝，即使底层解析器允许。
盐须在固定缓冲区内完整解码为 8–48 字节；不要求 UUID，也不新增与独立盐列的绑定校验。
这是成本和格式策略，不是盐一致性规则。

注册、初始化和改密显式写入同一参数组合，与原锁定库的默认输出兼容，不跟随未来默认值漂移。
不支持或畸形记录返回 `InvalidRecord`；支持范围内的密码不匹配仍返回 `InvalidCredentials`。
测试拒绝时不执行巨量计算。预检不会把未检查数字交给 Argon2 参数转换，避免重复项解析差异
或参数乘法溢出绕过本地限制。

这一收紧仅针对准备层：不改写或接纳其他凭据格式、不改 Schema 版本、不消费 OTP，也不撤销
已有 Session。会话验证和退出继续使用独立的来源检查；旧在线 AuthService 与同步教师初始化不变。
19,456 KiB 是固定的 Argon2 内存参数，不是进程 RSS、全部旧计算或耗时上限；已运行计算仍不能
被请求时限终止。公开签发、时序/OTP 恢复策略、可信入口和经过审查的迁移仍是独立门槛。

[哈希策略 SQL 目标](../../engine/tests/durable_password_profile_tdd.rs)、纯逻辑测试及工作接线检查
覆盖这一边界；本轮运行结果单独记录在[项目进度](project-status.md)。

### 早期 OTP 时效阶段 · 2026-10-03

历史阶段说明：下方 Schema 2 后续接入在这些时效检查上增加了消费事务。

准备层登录和改密在密码验证后、取得来源写锁后，以及最后一项 SQL 读回/时间检查结束后、请求
COMMIT 前重新核对提交的 TOTP。验证码若在锁、触发器或读回等待期间离开接受窗口，返回
`InvalidCredentials`：登录不发布待提交 token；改密在这一提交前检查失败时回滚凭据和 Session
变更。原有命名空间/凭据固定、会话过期、锁顺序及提交确认规则继续成立。

保留 SHA-1、去除首尾空白后的六位 ASCII 数字、30 秒步长，以及应用 UTC 前后各一步的接受范围。
Session 到期仍按数据库实时时间检查，两套时钟没有暗中合并，也不因此抵抗时钟回拨。负 Unix 时间
拒绝，纪元边界不会把负候选计数器转换成无符号数。测试不改机器时间；仅单测构建提供私有、逐来源
测试时钟，配合真实 SQL 等待确定性地推进 OTP 过期。

这是**时效检查，不是一次性消费**。同一验证码在接受窗口内仍可能多次成功，包括独立来源实例
以及登录和改密之间。[RFC 6238 第 5.2 节](https://www.rfc-editor.org/rfc/rfc6238.html#section-5.2)
另要求成功验证后拒绝重用；这需要与账号代次绑定的持久消费事务和明确的 Schema/恢复合同。
本轮不用内存缓存或 Session 数量冒充该保证。公开签发仍须完成这一策略、时序/入口限制和其他接入门槛。

最终检查发生在发送 COMMIT 前，而非收到确认时；提交阶段的延迟约束/工作、网络延迟或响应丢失
仍可能跨越窗口或留下不确定结果。本轮不增加 Schema 迁移、消费记录，不更改 OTP 格式或在线
AuthService。私有 OTP 单测/SQL 和准确选择入口见[测试指南](testing-guide.md)；实际结果单列于
[项目进度](project-status.md)，不加到原 C1-E 历史总数中。

### OTP 消费策略及其早期纯逻辑阶段 · 2026-10-04

私有 [`otp_consumption` 模块](../../engine/src/services/auth_service/durable_source/otp_consumption.rs)
定义拟议的计数器转换，本身不是数据库消费者。第一阶段刻意未接线，保留 Schema 1；下方后续接入
现已由登录和改密调用。给定水位不是可信存储，纯策略本身不建立跨进程防重放。

`Watermark` 表示最高已消费时间步，并同时排除全部更早的时间步。显式 `-1` 表示从未消费；
更低值是损坏状态，不能作为恢复默认值。其余有符号 64 位值均可表示，包括领先当前时钟的水位；
此时拒绝较早的验证码，不暗中降低水位。以后不能把数据库缺失状态未经审查地映射成 `-1`。

`prepare` 接收显式时间、有界密钥/验证码文本和水位，检查原 SHA-1、六位数字、30 秒/前后一步
窗口内的**全部**匹配计数器。只要任一匹配不高于水位就拒绝，即使同一串数字也匹配更新的计数器；
否则选择最高匹配值。这是计数器单调消费，不是六位数字永久唯一。快时钟认证器可能提前消费下一步，
用户须等到更晚的计数器；时钟回拨不降低状态，但并非所有向后调时都被拒绝。

待处理提案用带领域前缀及长度边界的摘要私下绑定解码后的密钥和去除首尾空白后的验证码，只提供
前后水位及复查；无公开构造、Debug/序列化/Clone 或明文密钥/验证码存储。归一化等价输入仍等价，
不同密钥即使生成相同验证码也不能替换原密钥。`recheck` 使用**原水位**重新选择，要求相同的新计数器
和绑定；窗口移动不能暗中把提案改到另一碰撞时间步。重复纯调用不消费状态，摘要也不是账户身份、
凭据、数据库记录、事务回执或提交确认时效保证。

持久化需要独立接入：固定准确账号代次和完整凭据，取得来源锁，比较更新旧水位到新水位，并在
同一事务写后核对水位及业务结果。登录签发 Session、改密/撤销 Session 必须与消费一同提交；改密
不得清空水位。启用前须明确版本、旧写入封锁、存量数据接入及不确定结果恢复合同；下方 Schema 2
后续实现给出全新安装合同。现有复用 OTP
的测试须保留其目标故障/锁障碍，不能把提前拒绝重放误记为回滚测试通过。

纯测试使用固定公开密钥碰撞向量和显式时间，不涉及机器时钟或数据库；实际结果见[项目进度](project-status.md)。

### 未发布 OTP 原子消费 · 2026-10-04

准备层登录和改密现在要求**认证来源 Schema 2**。每个准确账号行存储非空 BIGINT
`otp_last_counter`，初值为 `-1`，带已验证的下界约束。全新显式安装在未改动的基础模板后追加
`0015_durable_otp_consumption.sql`；注册和初始化确认交付前检查初始水位。已有 Schema 1 即使为空
也拒绝，不自动接纳、修复、回填或迁移。禁止直接对存量数据执行该模板、改版本元数据或重置水位来
绕过检查。产品/API 版本号与该存储版本独立。

密码工作后，两条命令保留原来源身份固定，取得来源写锁，复查准确账号代次和完整凭据，再以
**当前持久水位**生成消费提案。登录比较更新旧水位后插入 Session；改密在一次更新中替换密码并
推进水位，再撤销全部 Session。写后复查水位及业务结果；请求 COMMIT 前复核绑定的准确计数器，
中间不再等待其他 SQL，确认提交后才返回成功/token。改密不清空消费状态；普通会话验证/退出不消费 OTP。

账号行和事务而非进程缓存让独立来源互斥。复用已提交时间步返回 `InvalidCredentials`，登录和改密
之间也一样；成功改密后重新登录须使用更晚的 OTP。纯策略的碰撞规则保持：任一匹配计数器不高于
水位则拒绝，否则消费最高匹配；六位数字不是永久唯一。提前匹配下一步也关闭更早时间步，快时钟
认证器可能需要等待。水位属于准确账号代次，不随同名删除重建沿用。

已知提交前失败会让消费和会话/密码效果共同回滚，验证码仍符合窗口及水位时才可重试。取消、超时
或 COMMIT 响应丢失**不证明回滚**：可能已经消费却未交付会话 token。不要盲目重试、恢复旧会话
或重置计数器；通过可信维护核对，使用更晚的 OTP。尚无凭据回执、TOTP 密钥轮换/恢复或存量迁移。
OTP 仍使用应用 UTC，Session 到期使用数据库时间；这不保证提交确认时仍有效，也不拒绝所有时钟回拨。

Schema 2 能围住遵守版本门的旧准备层写入方，不能围住旧在线 AuthService 或特权 SQL 所有者；
必须隔离旧写入方，不能在其在线表上启用本来源。不挂载公开签发，也不跳过时序枚举、入口、迁移及
恢复门槛；不宣称所有私有资源命令都已在每次写后完整复核 Schema。

现有 SQL 夹具在只测试改密时显式种入合成 Session，真实重复登录则使用后续 OTP 时间步。故障计数器
证明目标触发器确实命中，不能让提前拒绝重放冒充回滚覆盖。消费、Schema、时效的准确测试入口及
分日期结果见[测试指南](testing-guide.md)和[项目进度](project-status.md)。

### 未发布缺失账号密码工作 · 2026-10-07

准备层登录现在保留可选账号快照，不再因用户名不存在立即返回。只有查询成功且确实没有账号时，
才选择固定公开的合成 PHC 记录，其 Argon2id v19、m=19456/t=2/p=1、32 字节摘要参数与真实
准备层凭据一致。已存凭据损坏、Schema 不兼容、authority 错配和数据库错误仍直接失败，不能
伪装成缺失账号，也不通过合成验证掩盖。

命令先复核原来源身份并确认第一段事务 COMMIT，再进入既有共享密码校验入口。真实与缺失账号
共用这一次验证路径，受相同的四项派发、二十项总准入及整次十秒时限约束；等待或执行密码工作时
不占数据库锁或连接。超长输入和用户名尝试限额仍先行拒绝；已经派发的阻塞工作在调用者取消或
超时后继续持有两个许可，直到实际结束。

验证后还须独立确认原快照确实含有账号：即使提交的密码匹配公开合成记录，也不能登录。缺失账号
快照不进入第二段事务、不消费 OTP、不创建 Session，也不写账号状态；密码工作期间注册同名账号
不能让这个旧快照获得认证。真实账号继续接受原有代次、完整凭据、OTP 及来源身份复核。

这只消除缺失账号跳过密码 KDF 的显著分支，不等于恒定时长登录或全面抗账号枚举；准入、存储、
解析及 OTP 路径仍可能不同。源码保持 0.5.1，不新增依赖、HTTP 签发、在线 AuthService 改动或
存储迁移。公开签发仍须审查时序、入口、Session 和恢复策略。准确回归入口及分日期结果见
[测试指南](testing-guide.md)和[项目进度](project-status.md)，不加入原 C1-E 历史总数。

### 未发布显式过期 Session 清理 · 2026-10-07

`prune_expired_sessions() -> Result<u32>` 是可信来源维护原语，不接受调用方指定的数量、token
或所有者，也不是终端用户授权接口。不接 CLI、HTTP 或自动调度；普通登录、会话验证没有新增清理
副作用。认证来源仍为 Schema 2，产品版本保持 0.5.1。

同一来源事务先取得来源写锁并固定原命名空间/表身份，再读取一次数据库实时时间作为截止点。
按过期时间和 token 摘要排序，锁定到期时间不晚于该点的至多 128 条记录。SQL 投影在传输前限制
token 文本为 64 字节、用户名最多 64 字节，不用筛选条件隐藏损坏候选。选择和删除读回还在 SQL
侧先检查到期及创建时间，选中候选的无限/超出解码范围时间返回 `InvalidRecord`，不触发解码器
panic、不跳过坏行，也不截断成有效时间。这仅保护维护路径，不是全驱动修复或依赖变更。
删除前须完整解码并核对全部候选的 token 摘要、用户名、准确账号代次、到期及创建时间。
`EXISTS` 只返回准确账号是否存在，
不读取密码、TOTP 密钥或 OTP 消费状态。损坏记录或孤儿会使本次失败，不暗中修复或当作废弃数据。

删除只针对本批选中的摘要，并继续使用同一到期截止点；返回的完整行经排序后须与原快照完全一致，
包括创建时间。复核原来源身份后，再确认所有选中摘要均已不存在，此查询不附加到期条件，因此
触发器把同一摘要以未来到期时间重新插入也会拒绝确认。最后再次复核身份、确认 COMMIT 后才返回
数量；空批次也须最终复核并确认提交。删除被抑制或返回内容被改写不能被确认成本批清理成功。

返回数量只确认这一批，不证明来源已空、不保证每次删满 128 条，也不限制全局 Session 存量、
磁盘占用、进程 RSS 或实际执行时间。沿用整次十秒、锁等待两秒、单条 SQL 五秒时限。取消、超时
或提交响应丢失不证明回滚，也不授权盲目重试。显式变更只针对 `sessions`，但选中行复核不是对
任意恶意触发器修改未选中数据的全库审计。活跃会话配额、调度、运维/HTTP 入口准入和恢复策略
仍是后续工作。准确入口和分日期结果见[测试指南](testing-guide.md)及[项目进度](project-status.md)，
不加入原 C1-E 历史总数。

### 未发布 Session 到期时间安全解码 · 2026-10-07

准备层共享 `session_record` 读取器现在先在 SQL 内检查 `expires_at`，再做二进制时间解码。
无限值和超出 chrono 上界的有限值返回 `InvalidRecord`，不触发解码 panic、不伪装成会话不存在，
也不截断为有效时间；包括 `infinity`、`-infinity` 和有限的 262143 年。正常到期判断继续使用
锁后的数据库实时时间。PostgreSQL 公元前 4713 年日期、截取到微秒的 chrono 最大值等可表示
有限边界仍按正常规则判断到期，不仅因年代久远或距离过长就拒绝。

共享读取器覆盖会话验证、登录写后读回及调用它的授权守卫。触发器写入的非法登录到期时间不能
成为已交付 Session；Session/OTP 效果仍由原事务约束。[只读对账](collaboration-reconciliation.md)
在 SQL 内检查相同范围，但只取回是否过期的布尔值，坏值返回 `InvalidSource`。两条路径均不
暗中修复时间，对账也不取回原始到期时间供报告输出。

该阶段只覆盖来源 Session 到期字段和上方独立清理投影，不包括注册表时间。后续独立的
[注册表时间防护](collaboration-reconciliation.md)在 SQL 解码前检查可空 `retired_at` 和必填的
身份/策略审计 `recorded_at`，涵盖重放、历史、追加读回和对账；坏非空退役时间不能变成活动身份。
其他时间路径不能因此被认定安全。不改依赖、产品版本或
来源 Schema，不新增在线签发、CLI 或公共 API。准确测试清单和分日期结果仍分别见
[测试指南](testing-guide.md)及[项目进度](project-status.md)。
