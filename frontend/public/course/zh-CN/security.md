# 安全与课堂部署

## 核心结论

Cyanrex Engine 是特权内核实验环境，不是多租户安全沙箱。

Docker 配置需要访问宿主机或虚拟机的 eBPF、tracefs、BTF 和 bpffs。包括学生在内的认证用户
可以进行内核实验；教师还管理部署设置。不要将 Engine 暴露给不受信任网络，也不能把角色权限
当作内核隔离。

## 默认防护

- Docker 发布端口默认绑定 `127.0.0.1`；native/WSL 启动器目前设置 `ENGINE_HOST=0.0.0.0`，
  在局域网启动前必须检查真实监听地址并限制访问；
- 首次启动生成随机数据库、部署教师和 TOTP 密钥（保留旧 `CYANREX_ADMIN_*` 配置键）；
- `.env` 权限为 `0600` 并被 Git 忽略；
- 注册和密码方式 TOTP bootstrap 默认关闭；
- eBPF 检查、语义补全、脚本操作和普通会话接口对认证用户开放；
- 教师统一管理模块修改、系统设置、Runner Agent 和教学；学生不能调用这些管理 API，旧管理员
  身份兼容为教师身份；
- 公开注册不能选择角色或抢占教师/旧管理员名单中的名字；默认部署教师不能删除自己，避免实例
  只剩学生、无人管理；
- 登录失败达到阈值后暂时锁定；
- eBPF 任务有全局及单用户 Runner 容量、源码大小和执行时间限制；
- Runner 状态明确报告 `shared_kernel`，本地配额不代表租户安全隔离；
- 本地检查/补全缓存按用户区分；源码工作区在 Unix 使用 `0700`，返回或取消时执行清理守卫，
  清理失败会记录日志。这些措施不是独立内核边界；
- 数据库保存会话令牌摘要，而不是可直接使用的明文令牌。
- 携带会话的 `/ws/events` 握手也执行 Origin/Referer 来源策略；CORS 响应头本身不能保护
  WebSocket。原生客户端必须提供允许的 Origin。已有的 `CYANREX_ALLOW_MISSING_ORIGIN` 豁免
  也作用于此接口，局域网中应保持关闭，除非已明确接受风险。详见[事件流恢复](event-stream.md)。
- 实时事件队列使用已认证会话的用户，不接受客户端指定身份，避免他人流量挤占订阅队列。
  容量按活跃用户计算，并非全局连接/内存配额或租户隔离；原有来源、会话与共享内核限制仍适用。

这些措施降低误暴露风险，但不能把特权 Engine 变成安全的共享执行平台。

### 教师权威升级

已有教师名单将授予部署管理权，不再仅限教学读取。部署此变更前请审查
`CYANREX_TEACHER_USERNAMES` 和 `CYANREX_ADMIN_USERNAMES`。单人使用的默认部署账号就是
教师，但不会提升第一个公开注册者、信任客户端自报角色、跳过 TOTP 或改变内核/Agent 权限。
增设教师前必须核实已有账号的归属，具体步骤见[教师指南](teacher-guide.md)。

### 防误操作保护

界面在内核运行、卸载、危险删除、草稿替换、管理状态变更及远程编译器选择前展示目标和影响；
批量删除/清理需输入确认词，默认焦点放在“取消”。执行中阻止重复点击，失败后需核对状态并重新确认。
事件删除固定时间截止点，不再把有上限的显示条数当作删除总数。这些措施是浏览器操作保护，
不是服务端授权、幂等键、事务回滚或内核隔离。离开页面后已发出的请求仍可能完成；API 客户端仍依赖
Engine 的 Session、教师/学生角色、CSRF、密码和 OTP 策略；角色统一不替代服务端校验。

### 会话与数据库故障

退出登录仅结束当前会话，不会结束其他设备的会话或正在运行的内核实验。浏览器只有在收到
HTTP 成功且明确确认退出的响应后才进入登录页；被拒绝、响应无效、超时或网络故障时，会提示
会话可能仍有效，需手动重试。等待期间阻止重复点击；离开页面会丢弃迟到的 UI 回调，但不能
撤销 Engine 已收到的请求。

启用 PostgreSQL 认证持久化时，退出、改密和删账号必须确认存储写入；未确认则返回 `503`，
不清除会话 Cookie，也不只改内存就宣称成功。会话清理与账号删除在同一事务中提交；改密和
删账号绑定已验证、归一化的用户名及凭据快照，影响零行时拒绝成功响应，并发改密不能静默
覆盖更新后的密码。
退出时若没有删除任何行，只有确认会话已不存在才会返回成功。
删账号还会确认没有会话残留，包括级联删除被抑制的情况。

在 PostgreSQL 启用时开始的登录，必须在同一事务中确认插入恰好一条会话并复核已验证凭据，
然后才发布缓存令牌和 Cookie；账号删除/重建或并发改密不能让旧的待完成登录获得新会话。
未确认的登录写入返回 `503`，不签发新 Cookie，也不只写内存就返回成功；提交前取消会回滚。
已提交但响应丢失的登录仍可能留下会话直到过期。这不移除原有读取/注册降级，也不保证分布式撤销。

`503` 或响应丢失不代表一定没有提交：恢复存储后，应核实当前账号/会话状态，再明确重试。
单次写入失败不会关闭持久化；如果此前的读取故障已触发永久认证数据库降级，需先恢复
PostgreSQL 并重启 Engine，才能进行这些操作，断库期间临时注册的账号也适用。主动采用
纯内存模式的实例仍沿用易失行为；不要为绕过认证存储错误而把持久化部署切成纯内存模式。

PostgreSQL 确认会话不存在或已过期时，Engine 也会移除对应的内存降级副本；账号查询确认
不存在时，会移除该缓存账号及其缓存会话。已观察到的失效不会仅因随后断库而重新生效。
原有内存降级仍是易失的，断库期间无法发现其他进程做出的撤销或凭据变更；这不保证分布式
撤销同步，也不能替代安全事件恢复措施。

### 浏览器诊断边界

浏览器内联诊断缓存和待完成检查只属于当前编辑器及完整的 Engine/目标/源码/头文件上下文，不再是
进程级共享池。离开后重进编辑器会丢弃缓存，已取消的回调不能发布旧诊断。这不检测其他标签页的
Cookie 变化、不撤销会话、不擦除已保存草稿，也不是权限边界。诊断请求禁止重定向并要求 no-store，
作业/租约归属仍由 Engine 判断；超时或尽力取消不代表服务端回滚。见[沿链路抓虫 03](functional-network-bug-hunt-03.md)。

语义服务同样拒绝其他编辑器或已销毁模型，请求/缓存各自独立；手动头文件检查在源码或上下文变化时
取消。补全和已选元数据读取整次限时 10 秒，手动检查沿用本地 20 秒限制；三条请求路径均禁止
重定向并要求 no-store。刷新元数据失败时明确展示上次成功列表，不声称没有已选头文件。客户端
上下文版本只让旧界面工作失效，用户归属和当前头文件仍由 Engine 选择，头文件变更仍专属教师。
不新增原子头文件快照、跨标签页会话撤销检测、远程补全或自动执行。见[沿链路抓虫 04](functional-network-bug-hunt-04.md)。

### 浏览器运行边界

手动运行/卸载携带会话凭据、要求 no-store 并禁止重定向。单个控制器的同步互斥门阻止并发派发，
但不是跨标签页幂等保证。导航取消浏览器等待，编辑隐藏旧结果；两者都不会卸载已经派发的程序。
变更请求 330 秒、挂载读取 20 秒只是活跃浏览器等待上限，不证明服务端回滚。结果不确定时必须核查，
不会自动重试或卸载。只有明确的 `clean: true` 才确认清理；列表读取失败/格式错误不算空列表，
旧列表的清理按钮会禁用，直到刷新成功。会话归属、CSRF 与 Runner 权限仍由 Engine 强制执行。
显式 `pin_path: null` 批量操作仍作用于当前账户在执行时的全部挂载（含执行前新增项），原有输入短语
确认已说明该范围，不是冻结的服务端快照。本轮不新增会话撤销检测或内核检查。见
[沿链路抓虫 05](functional-network-bug-hunt-05.md)。

断点会话/行号筛选、严格探针标记解析及文档归属高亮，避免把过期或异常观察归到当前草稿；它们不认证
内核事件生产者。共享追踪日志中的会话标记不是秘密，也不是租户边界。访问权仍由 Engine 的会话/
Origin 检查和按用户订阅决定。恢复快照同样要求 no-store、禁止重定向；异常实时帧保留可能缺失提示，
不声称已完整恢复。本轮不新增撤销检测、重放保证或自动内核操作。见
[沿链路抓虫 06](functional-network-bug-hunt-06.md)。

### 学习数据边界

学习记录损坏或不可读会明确报错，不会显示成空课堂；学习聚合读取及其存储错误响应不缓存。
新建本地学习目录/快照采用 Unix 0700/0600、排他随机临时文件与失败清理。旧目录不会自动收紧
权限，仍需限制数据目录及父路径的所有权与权限；这不提供崩溃恢复或恶意父路径保护，见
[学习记录存储](learning-storage.md)。

### 课堂接入边界

课堂使用独立的[发现/邀请边界](classroom-connection.md)：名称和 ID 不是证书，应通过可信渠道
核实教师完整 HTTPS 地址；不能把 Agent 共用 bootstrap token 发给学生。邀请默认关闭，绑定
学生用户名、短时有效、原子单次消费，不自动登录或提权。兼容检查针对接入协议与必需能力，而
不只是产品 patch。SSH 管理限于本机运维 CLI，必须核实主机密钥和具体目标，不能被学生邀请或
发现数据触发。两条入口均不提供内核隔离，不自动开放监听，也不取代可信入口与独占 VM。

### Runner Agent 凭据边界

远程 Agent 注册默认关闭；只有设置至少 32 个字符的 `CYANREX_RUNNER_AGENT_TOKEN` 才会启用。
接口应只位于私有管理网络，或置于带来源限制的 TLS 入口之后。不要把 Token 写入前端代码、日志或
代码仓库；节点丢失或被入侵后应立即轮换。

预共享 Bearer Token 只用于注册。注册响应通过 `Cache-Control: no-store` 一次性返回每节点独立的
256-bit 凭据；使用相同 ID 重新注册会轮换凭据。心跳和作业接口必须使用 HMAC-SHA256 签名，签名
覆盖方法、路径、Agent ID、Unix 时间戳、Nonce 和正文摘要。时间戳有固定时效窗口，每个 Nonce 只能
使用一次。

Bootstrap Token 的持有者仍能重新注册并冒充 Agent ID，因此它依旧是高价值密钥。作业具备领取
Lease、截止时间、取消确认和结果大小限制。编辑器默认使用本地编译器；只有显式选中远程后端时，
检查源码才会发送给能力匹配的 Agent，并且不会加载或返回目标文件。公开后端清单不包含标签与内核
细节，远程作业绑定已登录用户，每个用户最多同时进行两个检查。`/ebpf/run` 仍在本地执行。签名只能
证明结果来自某个已注册凭据，不能证明编译结果诚实；跨越更强信任边界前仍应考虑双向 TLS、节点
绑定密钥或证明。

执行前已观察到丢失的租约会被丢弃，不再执行或确认取消；轮询仍可继续处理后续任务，但不会因此
中断已经开始的编译。未领取的用户检查等待 35 秒后在下次队列访问时过期，释放源码和名额；教师
管理的无用户归属任务仍显式取消。响应正文逐块检查 640 KiB 限制，没有长度声明时也不等收完整包再拒绝。

内置独立 Agent 默认拒绝非回环明文 HTTP，只有显式设置实验网例外才会放行；同时禁用 HTTP 重定向
和环境代理、限制响应体大小，并支持从挂载文件读取 Bootstrap Secret。编译模式必须显式开启，且
`shared_kernel` 会被拒绝；执行器只以固定参数调用绝对路径 Clang，清空环境，使用私有临时工作区，
限制进程资源和输出，在摘要后删除目标文件，并预先拒绝非字面量或可越界的 Include 写法。Agent 应
使用无特权账户，不使用宿主 PID、内核挂载、Docker Socket 或 Linux Capability。Clang 会处理不受信
输入，因此仍需容器或虚拟机边界。

可选的托管 Compose Profile 会自动应用这套基线：使用无特权数字 UID、只读根文件系统、不发布端口、
丢弃全部 Capability、启用 `no-new-privileges`、使用 `noexec` 临时工作区，并限制 PID、CPU 和内存。
管理脚本把 Bootstrap 值写入权限为 0600 的宿主文件并作为 Docker Secret 挂载，不会输出该值；只有
教师显式启动后 Profile 才会启用。独立内部网络仅允许 Engine 控制流量，阻断到默认数据库/前端
网络和外部网络的直接访问。

## 推荐部署级别

对于多名学生提交自编代码，下一阶段目标已确定为无特权教学控制服务加每个活跃学生独占的 Linux VM。
桌面机可以承载 VM，不强制使用集中执行服务器。这一目标尚未实现，环境归属、恢复和学生自管设备
结果可信度的限制见[Linux 桌面与局域网课堂隔离](classroom-isolation.md)。不要直接给现有只编译
Agent 增加特权来开启远程加载。

### 个人电脑

每位学生一个本地实例。Windows 使用 WSL2，Linux 使用 native 或 Docker。这是首选方案。

### 远程个人虚拟机

每位学生一台 VM，通过 SSH 隧道访问回环端口。VM 可以在课程结束后整体销毁。

### 集中服务器

不建议多个学生共用同一个 Engine。如果硬件有限，应通过 VM、microVM 或独立实验节点隔离，
并限制每个节点的网络、CPU、内存和生命周期。

## 禁止事项

- 不要把 `CYANREX_BIND_ADDRESS` 改为 `0.0.0.0` 后直接暴露公网；
- 不要提交或分享 `docker/.env`；
- 不要把 Docker socket 挂入 Engine；
- 不要关闭认证或把公开注册当成课堂隔离；
- 不要允许学生运行来源不明的程序；
- 不要把宿主机重要工作负载和教学 Engine 放在同一安全域；
- 不要把 verifier 当成完整的恶意代码沙箱。

## 需要远程访问时

优先使用 SSH 隧道：

```bash
ssh -L 3000:127.0.0.1:3000 \
    -L 8080:127.0.0.1:8080 \
    USER@SERVER
```

长期服务应使用 TLS 反向代理、来源限制和主机防火墙，并设置
`CYANREX_SECURE_COOKIES=true`。启用 Secure Cookie 前必须确认浏览器通过 HTTPS 访问。

当前 Compose 的数据库、Engine 和前端发布端口共用 `CYANREX_BIND_ADDRESS`。改成局域网地址会同时
开放三者，不只是浏览器入口。应保持内部端口私有并核实监听与防火墙行为；专用课堂入口配置仍待实现。

## 课前和课后检查

课前：

- 更新依赖并运行 `npm audit`、`cargo audit`；
- 验证随机凭据和回环端口；
- 快照或备份实验 VM；
- 试跑全部实验；
- 确认宿主机没有敏感生产工作负载。

课后：

- 卸载所有 eBPF attachment；
- 停止实验栈；
- 清理临时账户和凭据；
- 检查 bpffs 是否存在异常残留；
- 集中环境优先销毁并重建 VM，而不是继续复用未知状态。

## 依赖扫描治理

- 前端依赖下限为 Next.js 15.5.24 和 sharp 0.35.4，对应上游的
  [Windows 服务端](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)、
  [AVIF 图像优化](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) 和
  [sharp/libheif](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c) 安全公告。
  需要重新构建并部署才能应用补丁，修改锁文件不会更新运行中的容器；自定义全局 libheif 也需至少
  1.23.2，npm 审计不代表宿主机动态库验收。
- 我们会对 Rust 后端执行 `cargo audit`，并将已接受的告警记录在
  `scripts/security-audit-exceptions.json`。
- 当前已登记例外：
  - `RUSTSEC-2023-0071`（`rsa`）——通过 `sqlx-mysql` 在 `Cargo.lock` 中传递。
    当前后端未直接使用 RSA 操作，且该告警尚无可用补丁版本。
- 每个例外都包含复核截止日期，需要在到期前重新评估依赖版本。

## 安全事件处理

若怀疑凭据泄漏或存在未知程序：

1. 立即断开实验节点网络；
2. 停止 Engine；
3. 不要只在应用内修改密码后继续使用；
4. 导出必要日志和 attachment 信息；
5. 对一次性 VM 直接销毁重建；
6. 轮换数据库、管理员、TOTP 和 SSH 凭据；
7. 检查宿主机其他工作负载是否受到影响。
