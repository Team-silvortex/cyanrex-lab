在线认证已切换、存储已迁移或运行实例已经验收。

[顺序下载](large-file-download-client.md)、[清单 HTTP](large-file-manifest-http.md)及
[准确清单客户端](large-file-manifest-client.md)、所选保存、观察／取消和配对分发路由现收录于

## 核心结论

Cyanrex Engine 是特权内核实验环境，不是多租户安全沙箱。

Docker 配置需要访问宿主机或虚拟机的 eBPF、tracefs、BTF 和 bpffs。包括学生在内的认证用户
可以进行内核实验；教师还管理部署设置。不要将 Engine 暴露给不受信任网络，也不能把角色权限
当作内核隔离。

## 通用平台安全边界

| 入口 | 当前保证 | 不能据此推导 |
|---|---|---|
| 本地任务 payload 编辑器 | 文本/JSON 上限、父任务修订和目标绑定确认 | 持久化、服务端身份、执行安全或独立 JS/TS 工作线程 |
| 直接 Task/Artifact/Review 存储 | 明确作用域、可信所有者过滤、有界记录及确认数据库写入 | 调用方自报所有者已认证，或历史写入来自 Session |
| Session 资源命令 | 同一事务复核账号世代、审计成员、命名空间身份和最终会话 | 教师可读他人私人内容、跨用户审阅权或 Task 验收 |
| Artifact 发布与任务换版 | 不可变准确引用，Draft 检查旧/新输入及预期修订 | 文件/数据库原子回滚、自动接管或失败后删除新内容的许可 |
| 领域目录 | 准确的服务端定义元数据 | 包安装可信、准入即完成类型化证据验证或策略执行 |
| 遥测与业务事件 | 在线事件历史与资源事务 outbox 分开 | 可靠投递、恰好一次工作流，或事件页包含完整安全审计 |

准备层安装器只接受显式空命名空间。Task 存储 Schema 2 拒绝 Schema 1，不能修改版本号、删除数据
或重新引导来绕过拒绝。在线教学表、凭据、私人 Artifact 根目录和回退材料不能当作合成测试夹具。
结果不确定时保留证据供受控对账，超时或响应丢失不是回滚证明。

来源事务中的私人工作详见[任务输入](session-task-inputs.md)、[Draft 换版](session-task-revisions.md)
与[私人人工审阅](session-review-commands.md)。这些路径尚未成为公共浏览器 API，服务级测试不能
证明在线 HTTP/CSRF 或部署验收。应用角色和源码抽象仍不能隔离共享 Linux 内核。

### 私人元数据索引边界

源码 0.5.5 上独立的 **2026-10-11 未发布[任务内容索引](task-content-index.md)**只返回
所有者私有元数据。可信列表不认证自报所有者；会话列表派生所有者、锁定有限任务头，
提交前用新鲜数据库时间复核命名空间与当前权限。选中记录及前瞻损坏或定义未配置均拒绝。
同作用域的他人/不存在游标只是位置，不是授权。不访问 Artifact 命名空间或 blob，因此列表
不证明内容可读、未扫描记录完整或全库健康。不增加 HTTP/SDK/UI、写入、安装、迁移或恢复。

源码 0.5.5 上同日独立的**未发布[索引 HTTP 适配](task-content-index-http.md)**只委托该当前
Session 命令。原始查询不能选择所有者、作用域或命名空间；专用 Cookie/标记检查先于共享
响应存活期准入，GET Origin 可省略，提供时须精确匹配。元数据以 `no-store` 保持私有；路由仍未挂载，
不签发 Session、不接浏览器/SDK、不证明内容可用，也不提供全局容量配额。

### 私有分块暂存边界

源码 0.5.5 上 **2026-10-11 未发布[Unix 暂存 API](large-file-staging.md)**仅限受信任调用。
它固定既有、当前用户拥有的 0700 根目录，独占文件项绑定整份 typed 清单/块序号，准确
校验字节、同步文件/目录并读回创建时原 inode。任何已有目标均冲突；创建/创建后不确定结果
保留文件，不收编、覆盖或清理。当前读取校验不是历史写入回执或上传进度。

克隆共享额度由真实排队/运行任务持有，等待方取消也不提前释放；独立句柄额度可叠加。
0400 权限与元数据观察不隔离同 UID/root，工作也没有强杀/期限或预留磁盘配额。
不增加上传日志、当前 Session 授权、发布/接收授权、公共路由或在线接线。

### 受信任上传意图边界

独立[上传账本](large-file-upload-intent.md)绑定所提供所有者/账号代次、固定命名空间/表代次及
持久逻辑限额，不是当前 Session 守卫。写入串行化配额准入并校验全部有界记录，包括其他
所有者及全部账号代次。错误不释放预留或收编暂存字节；元数据读取不证明已上传字节、
历史提交来源或重试权限。网络仍未接通。

另行的[上传绑定暂存适配](large-file-upload-staging.md)捕获原来源和准确预留，文件工作前后
以新鲜 READ COMMITTED 读取复核。一次性内存尝试在准入后首个等待前变为 Unknown；
只有原文件读回才能产生本地回执，回执持有原只读描述符。SQL 锁不跨 IO，不声称跨存储
原子性、持久进度、重试或当前 Session 授权。

独立[分块日志](large-file-chunk-journal.md)要求文件派发前得到 Unknown 行的提交确认。
唯一上传/块坐标在任一状态均占用，变化的来源/根绑定不能绕过。日志包装器在最终确认
获确认后再检查原来源/文件；之后错误可能留下 Confirmed 记录，而调用方仍 Unknown。
元数据观察不能重造回执，也不允许重试或清理。

另行的[整上传核验](large-file-whole-verification.md)读取当前 `u1` 字节，检查有序块/整文件
摘要并复核原来源/根/文件项观察。不以日志状态证明字节，也不修改日志。元数据结果不保留
块描述符，不证明原始写入来源、永久完整性、当前 Session 权限或发布。

另行[持久发布元数据](large-file-publication.md)同时要求原完整已确认日志与新鲜真实整文件
字节。不可变插入仅首次创建，上传/版本冲突不收编；提交确认之后继续复核原来源、日志、发布
和文件。之后的拒绝可能留下已发布行，而调用方 Unknown。存储行或匹配读取均不恢复回执、
不授予下载、不证明当前健康、永久物理封存或回滚，也不允许重试或清理。

另行[Session 私有元数据](large-file-session-metadata.md)要求当前审计过的活跃 Human／成员，
服务端推导 owner／账号代次，在一笔认证源事务内保留原认证源／目标身份、选中记录及配置行锁，
最后新鲜复核策略与到期。重建账号及教师身份不能继承另一所有者的记录。私有预留和元数据读取
不授予发布、文件字节访问或接收权限。

另行[纯文件授权契约](large-file-access-contract.md)比较准确账号代次、版本、活跃状态及有界
到期区间。JSON 或 `matches` 返回 true 都不证明签发来源、当前审计策略或下载权限。
撤权之后旧活跃副本仍可能匹配，未来命令必须读取并复核当前授权，不得复用该布尔结果。
发布许可撤销不隐式撤销独立接收记录。

[未发布的持久发布账本](large-file-publisher-grants.md)只记录可信签发者与撤销者的来源归属，
不证明调用方拥有 Registry 权限。本人 Session 读取要求当前审计 Human 成员、准确账号代次、
原授权／历史固定及提交前新鲜授权；粗粒度表 SHARE 屏障也阻止事务期间追加历史的幻读。
到期／撤销记录仍是可读元数据，不是可用许可。未来管理必须明确实现 `ManageFileGrants`，
不能代用部署授权或教师身份；本轮不增加接收或字节访问授权。

后续 [Session 授权管理](large-file-grant-management.md)认证可信宿主指定的准确当前账号，
不接受请求选择签发者或继承角色。签发复核目标 active 审计 Human 成员；撤销允许退休／
删除主体。替换宿主配置不撤存活 clone／在途工作，须排空并销毁旧句柄或重启。持久在线
管理权撤销、发布权限消费、接收及字节访问仍是独立门槛；旧可信归属不会升级为认证证明。

独立 [Session 发布](large-file-session-publication.md)现要求文件工作前的当前准确操作者及原活跃
发布授权，再在新认证源事务复核第一次认证源／Registry／授权固定。原授权／上传／日志屏障
覆盖插入及延迟／最终检查；最后时钟样本同时覆盖授权和 Session 过期。SQL 锁不跨文件工作，
撤权／取消也不持续中止已派发工作。提交后失败可留 Published 而调用者 Unknown；下载、接收权限与恢复仍缺失。

后续[接收账本](large-file-recipient-grants.md)独立于发布权限保存可信准确文件／账号绑定。
当前本人元数据在屏障内保持选中直到认证源最终授权及提交；未来生效／过期／已撤销元数据
可以读取，但不授权下载，声明文件引用或 Active 状态都不证明准确可信 Published 版本。

10 月 12 日[发布者本人分享](large-file-sharing.md)认证当前原发布者，将全部预期版本坐标
与本人选中 Published 比对，权限／历史／发布／写屏障持续到延迟及最终新鲜认证源检查。
撤销在 UPDATE 前匹配原发布者／账号，不要求当前发布授权、发布记录或接收者；不授予字节
或全局教师代办权，未知提交不证明回滚。

独立[下载清单观察](large-file-download-manifest.md)要求当前审计接收者及原 Active 准确文件
授权。记录原发布者／账号及文件／版本在 Published 正文解码前过滤；完整版本及原固定复核
先于最终新鲜授权／Session 有效期和提交确认。没有接收授权的教师或所有者仍被拒绝；清单
不授权后续字节披露，发布撤权不级联。

独立[分块读取](large-file-chunk-read.md)在重入原授权及提交之前，私下验证至多 4 MiB，
未经校验的前缀不进入调用者输出。最终同钟 Session／授权到期检查先于交付，之后无 IO；结果
只是已校验的读取时字节快照，不是确认时路径健康或持续授权，且返回字节继续占用额度。

独立[二进制 HTTP 适配](large-file-chunk-http.md)增加严格七键原始 query、专用 cookie／标记／
Origin、空正文准入及 Range／条件头拒绝。两种本地预算保留到最后一个仍持有所有者的 Bytes
引用丢弃，不只到正文 EOF；空 slice 可脱离所有者且不保有敏感数据。首帧须在认证源返回十秒内轮询；没有自主额度释放计时器、轮询时重新
授权或远端送达保证。之后撤销无法收回已批准字节；路由未挂载，不输出用户文件名、隐藏密钥或部分字节。

另行[已提供响应接收器](large-file-chunk-receiver.md)在文件派发前拒绝重复／不匹配元数据、编码／
Range／cookie、超长／短正文及尾部错误或 trailer。真正 EOF、SHA-256、idle 与固定 total 期限
先于私有独占暂存；取消等待者后，排队／运行工作继续保有接收缓冲／名额。远端元数据不选路径，
冲突不收编，创建后含糊文件结果不代表回滚。不增加请求器、凭据策略、当前远端权限或在线挂载。

另行[显式客户端](large-file-chunk-client.md)仅接受宿主冻结规范 Origin 及类型选择器；HTTPS 正常
校验证书／SAN，明文须明确字面环回，不用 DNS localhost。逐次敏感 cookie 不入 query／错误／
默认状态；禁重试／跳转／代理／解码。响应头与正文期限独立，整调用准入进入真实保存工作。
不证明原始 socket EOF、远端／OS 工作强杀、当前远端身份／工作区权限或已挂载分发服务。

另行[私有整文件拼装](large-file-chunk-assembly.md)先实际核对旧式分块，在原 0700 根内独占
创建固定完整清单绑定输出；校验复制、0400 同步／读回及原输入／根复核先于确认。不采用用户
文件名／路径、Source key 或保留输出。创建不确定保留证据，取消不强杀实际工作、不允许清理／
重试。三遍载荷读取使用有界缓冲／元数据，不是磁盘预留、原子公共发布、当前远端权限或
永久抗同 UID 封存。

### 准备层 HTTP 准入跟进

0.5.8 收录的[顺序下载器](large-file-download-client.md)跨当前真实保存／拼装任务持有
整流程名额；取消不启动下一请求，也不释放活动工作的名额。空文件成功是零 HTTP 本地拼装，
不是远端认证。每个非空服务端请求仍需当前接收权限，不保证最终持续授权或最初回执身份
连续。已有文件只冲突，不成为续传进度。

独立未发布的[清单 GET](large-file-manifest-http.md)只在当前准确接收者授权后暴露 Source
选定私人元数据；六项选择器不选择 scope／owner，既有凭据／正文门限及脱敏错误先于有界
JSON 投影。HTTP 名额随正文结束，不随保留的 JSON Bytes 延长。返回快照及后来撤销不授权
字节；正常启动、Session 签发及在线 API 不变。

新增[准确清单客户端](large-file-manifest-client.md)经原受控传输校验有界单例头、实际帧
EOF、严格原始 JSON 及完整期望版本；组合空文件也须远端元数据 GET。该观察不是持续授权
或认证主体来源，每个后续块仍独立复核。元数据取消在文件任务之前释放元数据／流程 gate；
真实工作持有旧流程 lease。不采用已有输出，不接在线挂载、界面保存对话框或续传。

新增[显式私有保存](large-file-save.md)使用原固定拼装描述符，不靠匹配版本元数据或采用
替换 inode。宿主已有本人 0700 父目录及独立 basename 选择独占新文件，实际核验复制／原
inode 读回；不推导远端文件名、覆盖、清理、远端授权或普通目录／界面策略。真实任务跨取消
保留暂存准入，不确定输出保留为证据。

新增[授权交付调用](large-file-delivery-client.md)将这些阶段合为一次显式操作，原整流程名额跨真实
块／拼装／保存任务及取消存活；首失败停止，不重试／采用，界面保存、续传和正常挂载仍独立。

独立[本人普通目录目标](large-file-user-save.md)以明确选择允许 0700／0750／0755，不放宽
私有暂存；核对原目录 UID／GID／模式并沿用实际保存，文件选择、共享可写目录、续传和挂载仍独立。

可选[实时交付观察](large-file-delivery-progress.md)仅提供单调用最新阶段与真实块ACK前缀，
不加回调或消费队列；全部暂存不是保存完成，关闭不是任务终止或回执，界面／持久进度／续传仍独立。

可选[协作式取消句柄](large-file-delivery-cancellation.md)在请求被选定时停止单调用等待。
丢句柄不取消，已派发任务仍持资源并可能完成；请求不是即时派发屏障，也不授予清理许可。

显式[整交付HTTPS验证](large-file-delivery-https.md)以一次性原生TLS对端测试既有链路；
传输身份不是当前文件授权，loopback验收不等于已部署局域网、界面或无特权服务隔离。

显式[分发路由组合](large-file-distribution-router.md)现从同一个所给Source及固定分块workspace
派生两个端点，HTTP预算仍独立；缓存配置一致性不是Session签发、正常挂载或特权隔离。

0.5.8 标签之后未发布的[真实Source／HTTPS联验](large-file-source-https.md)增加同一条原生
授权／文件／router／TLS／保存测试链，覆盖派发前撤权及真实响应正文取消；不改生产监听、
策略或分日期张量评分。

**2026-10-08 未发布的 C2-N 跟进**不属于已发布的 0.5.4 标签。
其[显式内容路由](task-content-http.md)默认共享四个请求/响应名额（可信配置 1–16），
状态克隆及分别用其构造的路由共享预算。低成本端点与凭据请求头检查先于准入；容量满时返回
私有 503 `capacity_exhausted` / `not_attempted`，不轮询正文、不调用 SQL，也不带 `Retry-After`。

名额覆盖正文收集、原会话命令、序列化及返回的响应正文，至最终帧/结束、错误或丢弃才释放；
已准入错误正文同样持有名额。取消不证明回滚，也不终止已派发的阻塞 I/O。不同状态实例的预算
独立，这不是全局内存/工作线程/网络/代理缓冲配额、隔离或重试机制。它不增加监听、Session
签发、公共/浏览器 API、在线认证切换或日志接线。

### 准备层文本发布边界

## 默认防护

本节默认描述现有运行时；准备层契约会单独注明。不能把两者的认证或存储策略混用。

- Docker 发布端口默认绑定 `127.0.0.1`；native/WSL 启动器目前设置 `ENGINE_HOST=0.0.0.0`，
  在局域网启动前必须检查真实监听地址并限制访问；
- 首次启动生成随机数据库、部署教师和 TOTP 密钥（保留旧 `CYANREX_ADMIN_*` 配置键）；
- `.env` 权限为 `0600` 并被 Git 忽略；
- 注册和密码方式 TOTP bootstrap 默认关闭；
- eBPF 检查、语义补全、脚本操作和普通会话接口对认证用户开放；
- 教师统一管理模块修改、系统设置、Runner Agent 和教学；学生不能调用这些管理 API，旧管理员
  身份兼容为教师身份；
- 公开注册不能选择角色或抢占教师/旧管理员名单中的名字；默认部署教师不能删除自己，避免实例
  只剩学生、无人管理；
- 登录失败达到阈值后暂时锁定；
- eBPF 任务有全局及单用户 Runner 容量、源码大小和执行时间限制；
- Runner 状态明确报告 `shared_kernel`，本地配额不代表租户安全隔离；
- 本地检查/补全缓存按用户区分；源码工作区在 Unix 使用 `0700`，返回或取消时执行清理守卫，
  清理失败会记录日志。这些措施不是独立内核边界；
- 数据库保存会话令牌摘要，而不是可直接使用的明文令牌。
- 携带会话的 `/ws/events` 握手也执行 Origin/Referer 来源策略；CORS 响应头本身不能保护
  WebSocket。原生客户端必须提供允许的 Origin。已有的 `CYANREX_ALLOW_MISSING_ORIGIN` 豁免
  也作用于此接口，局域网中应保持关闭，除非已明确接受风险。详见[事件流恢复](event-stream.md)。
- 实时事件队列使用已认证会话的用户，不接受客户端指定身份，避免他人流量挤占订阅队列。
  容量按活跃用户计算，并非全局连接/内存配额或租户隔离；原有来源、会话与共享内核限制仍适用。

这些措施降低误暴露风险，但不能把特权 Engine 变成安全的共享执行平台。

### 防误操作保护

Engine 的 Session、教师/学生角色、CSRF、密码和 OTP 策略；角色统一不替代服务端校验。

### 会话与数据库故障

退出登录仅结束当前会话，不会结束其他设备的会话或正在运行的内核实验。浏览器只有在收到
HTTP 成功且明确确认退出的响应后才进入登录页；被拒绝、响应无效、超时或网络故障时，会提示
会话可能仍有效，需手动重试。等待期间阻止重复点击；离开页面会丢弃迟到的 UI 回调，但不能
撤销 Engine 已收到的请求。

启用 PostgreSQL 认证持久化时，退出、改密和删账号必须确认存储写入；未确认则返回 `503`，
不清除会话 Cookie，也不只改内存就宣称成功。会话清理与账号删除在同一事务中提交；改密和
删账号绑定已验证、归一化的用户名及凭据快照，影响零行时拒绝成功响应，并发改密不能静默
覆盖更新后的密码。
退出时若没有删除任何行，只有确认会话已不存在才会返回成功。
删账号还会确认没有会话残留，包括级联删除被抑制的情况。

在 PostgreSQL 启用时开始的登录，必须在同一事务中确认插入恰好一条会话并复核已验证凭据，
然后才发布缓存令牌和 Cookie；账号删除/重建或并发改密不能让旧的待完成登录获得新会话。
未确认的登录写入返回 `503`，不签发新 Cookie，也不只写内存就返回成功；提交前取消会回滚。
已提交但响应丢失的登录仍可能留下会话直到过期。这不移除原有读取/注册降级，也不保证分布式撤销。

`503` 或响应丢失不代表一定没有提交：恢复存储后，应核实当前账号/会话状态，再明确重试。
单次写入失败不会关闭持久化；如果此前的读取故障已触发永久认证数据库降级，需先恢复
PostgreSQL 并重启 Engine，才能进行这些操作，断库期间临时注册的账号也适用。主动采用
纯内存模式的实例仍沿用易失行为；不要为绕过认证存储错误而把持久化部署切成纯内存模式。

PostgreSQL 确认会话不存在或已过期时，Engine 也会移除对应的内存降级副本；账号查询确认
不存在时，会移除该缓存账号及其缓存会话。已观察到的失效不会仅因随后断库而重新生效。
原有内存降级仍是易失的，断库期间无法发现其他进程做出的撤销或凭据变更；这不保证分布式
撤销同步，也不能替代安全事件恢复措施。

0.4.7 收录的 [C1-H 来源适配器](collaboration-password-change.md)独立提供自助改密与全部会话撤销
原子事务，要求当前 Session、密码和 TOTP。它未接入上述在线端点，不恢复退役身份的权限，也不能
让旧在线写入者共用已启用准备层的来源表。

[C1-I 引导](collaboration-bootstrap.md)只供可信运维代码显式初始化全新命名空间，不是匿名设置
端点或首次注册认领。已有/部分安装的 Schema 会被拒绝，初始身份、Grant 和审计一起提交，不签发
Session。提交响应丢失须对账，不能删数据或自动补建管理者。

独立的 [C1-J 本地 CLI](collaboration-provisioning.md)只连接 Unix socket 或字面量回环地址，忽略
环境中的数据库/运行时设置，要求私有自有输入文件和已核对的目标指纹。TOTP 仅在确认提交后写入
排他预留的私有文件，不输出到终端。数据库提交和文件交付不原子：失败时账号可能已提交，但注册
材料缺失/不完整。须保留证据并对账；仅检查目录的 `inspect` 不是完整健康检查、密钥恢复或重放机制。

[C1-K 对账](collaboration-reconciliation.md)在同一有界只读快照中读取来源、注册表及完整审计
历史，拒绝会隐藏行或不兼容的表结构，只输出汇总，不输出凭据、令牌摘要或逐个身份。一致快照
可能早于执行中的提交，不能证明未确认命令的结果，也不授权重新初始化、恢复密钥或受保护操作。
现有授权仍须即时核对 Session 并获取行锁。

0.5.1 收录的[持久会话来源加固](collaboration-auth-source.md)为登录、校验、退出固定命名空间及认证表
身份，覆盖登录密码工作线程间隙及写后路径漂移；仅接受单个有效私有 Schema 与无过滤的持久来源表。
这不要求注册表、不迁移或切换在线认证，能阻止读取空影子表误报退出成功，但不等于公开签发已就绪。

准备层注册、登录、改密和初始化现共用进程内限额：最多四项已派发密码计算、二十项总准入。
调用者取消/超时后，阻塞任务仍占名额直到真正结束；等待名额仍计入原操作预算。另对准备层账号
读取和准入前验证强制原有的 Argon2id v19/m19456/t2/p1/32 字节参数组合，限制 PHC 文本、解码盐，
拒绝重复/未知参数。其他格式返回 `InvalidRecord`，不改写凭据或隐式撤销 Session。这不约束旧在线
AuthService、其他进程、耗时或进程 RSS，也不终止运行中的计算。时序枚举以及入口/会话
限额仍是面向不可信客户端签发 Session 前的门槛。

0.5.2 收录的 2026-10-07 登录改动在账号确实缺失时，经原来源身份复核、查询事务确认提交后，使用
同一支持参数的合成记录，通过共享限额做一次密码校验。损坏凭据及来源/数据库错误不使用替代
记录。之后仍独立要求原始真实账号，匹配公开合成记录或验证期间同名注册都不能签发 Session
或消费 OTP。输入和尝试限额仍先行检查，已派发工作在取消后继续占许可。这消除了缺失账号跳过
KDF 的分支，不消除全部时序差异或枚举渠道；不承诺恒定耗时、不新增公开签发、在线切换或 Schema 改动。

准备层登录和改密还会在取得写锁后、最后 SQL 等待结束且请求提交前复查 OTP 时效，此时过期会
拒绝签发或回滚改密。Schema 2 后续接入还在同一事务内消费逐账号单调计数器并签发 Session，
或替换密码/撤销会话。完整当前凭据和旧水位作为更新条件，写后检查和绑定准确计数器的复查在
COMMIT 前完成；独立来源不能都提交同一步。改密保留消费状态，重新登录须使用更晚的 OTP。
碰撞处理拒绝任一已消费匹配，不禁止同一六位数字未来再次出现。纯提案本身不是持久状态或账号权限。

仅全新显式安装/初始化创建 Schema 2；已有 Schema 1 原样拒绝。不提供水位重置、密钥恢复、自动
迁移或在线 AuthService 切换。COMMIT 响应丢失可能已经消费但未交付 token，不能假定回滚或重置
状态再试。这不保证提交确认时效，也不防止所有时钟回拨。版本门只围住配合的准备层写入方，不能
围住旧在线认证或特权 SQL，仍须隔离。见[完整 OTP 合同](collaboration-auth-source.md)。

0.5.2 收录的显式 `prune_expired_sessions` 维护在来源写锁及单次数据库截止时间下，最多选择 128 条
过期记录；先校验整批，再删除、比对返回完整行，并在原固定来源确认全部选中摘要消失，未来到期

损坏/孤儿候选直接失败，不修复。确认提交后只返回本批数量，空批次

状态，显式变更只针对 Session，但不审计任意触发器的全库副作用。不接自动调度、CLI/HTTP，也不让
登录/读取顺带清理；活跃会话配额、维护准入和恢复策略仍须另补。见[清理合同](collaboration-auth-source.md)。

超范围 `expires_at`。会话验证、登录写后读回和调用守卫得到 `InvalidRecord`，不是 panic 或

坏值返回 `InvalidSource`，不暴露原始到期时间。注册表时间不在该阶段范围内，由下方独立后续补齐。

修复记录。不新增年代/排序规则，不改依赖、Schema 或在线授权边界，也不保证全部时间字段安全。

### 浏览器诊断边界

浏览器内联诊断缓存和待完成检查只属于当前编辑器及完整的 Engine/目标/源码/头文件上下文，不再是
进程级共享池。离开后重进编辑器会丢弃缓存，已取消的回调不能发布旧诊断。这不检测其他标签页的
Cookie 变化、不撤销会话、不擦除已保存草稿，也不是权限边界。诊断请求禁止重定向并要求 no-store，
作业/租约归属仍由 Engine 判断；超时或尽力取消不代表服务端回滚。见[沿链路抓虫 03](functional-network-bug-hunt-03.md)。

语义服务同样拒绝其他编辑器或已销毁模型，请求/缓存各自独立；手动头文件检查在源码或上下文变化时
取消。补全和已选元数据读取整次限时 10 秒，手动检查沿用本地 20 秒限制；三条请求路径均禁止
重定向并要求 no-store。刷新元数据失败时明确展示上次成功列表，不声称没有已选头文件。客户端
上下文版本只让旧界面工作失效，用户归属和当前头文件仍由 Engine 选择，头文件变更仍专属教师。
不新增原子头文件快照、跨标签页会话撤销检测、远程补全或自动执行。见[沿链路抓虫 04](functional-network-bug-hunt-04.md)。

### 浏览器运行边界

手动运行/卸载携带会话凭据、要求 no-store 并禁止重定向。单个控制器的同步互斥门阻止并发派发，
但不是跨标签页幂等保证。导航取消浏览器等待，编辑隐藏旧结果；两者都不会卸载已经派发的程序。
变更请求 330 秒、挂载读取 20 秒只是活跃浏览器等待上限，不证明服务端回滚。结果不确定时必须核查，
不会自动重试或卸载。只有明确的 `clean: true` 才确认清理；列表读取失败/格式错误不算空列表，
旧列表的清理按钮会禁用，直到刷新成功。会话归属、CSRF 与 Runner 权限仍由 Engine 强制执行。
显式 `pin_path: null` 批量操作仍作用于当前账户在执行时的全部挂载（含执行前新增项），原有输入短语
确认已说明该范围，不是冻结的服务端快照。本轮不新增会话撤销检测或内核检查。见
[沿链路抓虫 05](functional-network-bug-hunt-05.md)。

断点会话/行号筛选、严格探针标记解析及文档归属高亮，避免把过期或异常观察归到当前草稿；它们不认证
内核事件生产者。共享追踪日志中的会话标记不是秘密，也不是租户边界。访问权仍由 Engine 的会话/
Origin 检查和按用户订阅决定。恢复快照同样要求 no-store、禁止重定向；异常实时帧保留可能缺失提示，
不声称已完整恢复。本轮不新增撤销检测、重放保证或自动内核操作。见
[沿链路抓虫 06](functional-network-bug-hunt-06.md)。

### 事件历史与已读边界

事件导出/删除及未读/已读请求保留会话、要求 no-store 并禁止重定向。导出/删除最多等待 20 秒，
未读状态相关请求最多等待 10 秒；离页取消不代表服务端回滚。删除/已读响应失败或格式异常不算
成功，变更失败后不自动重试。现有已读接口覆盖当前会话用户的全部事件，包括筛选或 200 条视图
之外的记录，界面会明确说明；本轮没有改成逐条或持久确认。MIME/文件名检查用于避免误下载格式，
不代表 CSV 公式净化、归档认证、完整重放或新增载荷字节预算。见[沿链路抓虫 07](functional-network-bug-hunt-07.md)。

Engine 事件变更现在等待此前入队写入，并按账号保持准入直到已交接 SQL 与缓存更新完成，修复本地
顺序/取消竞态，不改变 Session、CSRF 或教师权限。私有替换帮助函数拒绝异账号记录。队列溢出与
存储期限会警告并锁定内存降级；已读/删除 HTTP 成功仍不承诺重启或其他进程中的持久删除。
不要把事件流当作恰好一次的安全审计日志。事务只保护设置/裁剪与替换，不覆盖完整的发布/HTTP/
恢复链路，见[沿链路抓虫 08](functional-network-bug-hunt-08.md)。

### 学习数据边界

学习记录损坏或不可读会明确报错，不会显示成空课堂；学习聚合读取及其存储错误响应不缓存。
新建本地学习目录/快照采用 Unix 0700/0600、排他随机临时文件与失败清理。旧目录不会自动收紧
权限，仍需限制数据目录及父路径的所有权与权限；这不提供崩溃恢复或恶意父路径保护，见
[学习记录存储](learning-storage.md)。

### 课堂接入边界

课堂使用独立的[发现/邀请边界](classroom-connection.md)：名称和 ID 不是证书，应通过可信渠道
核实教师完整 HTTPS 地址；不能把 Agent 共用 bootstrap token 发给学生。邀请默认关闭，绑定
学生用户名、短时有效、原子单次消费，不自动登录或提权。兼容检查针对接入协议与必需能力，而
不只是产品 patch。SSH 管理限于本机运维 CLI，必须核实主机密钥和具体目标，不能被学生邀请或
发现数据触发。两条入口均不提供内核隔离，不自动开放监听，也不取代可信入口与独占 VM。

### Runner Agent 凭据边界

远程 Agent 注册默认关闭；只有设置至少 32 个字符的 `CYANREX_RUNNER_AGENT_TOKEN` 才会启用。
接口应只位于私有管理网络，或置于带来源限制的 TLS 入口之后。不要把 Token 写入前端代码、日志或
代码仓库；节点丢失或被入侵后应立即轮换。

预共享 Bearer Token 只用于注册。注册响应通过 `Cache-Control: no-store` 一次性返回每节点独立的
256-bit 凭据；使用相同 ID 重新注册会轮换凭据。心跳和作业接口必须使用 HMAC-SHA256 签名，签名
覆盖方法、路径、Agent ID、Unix 时间戳、Nonce 和正文摘要。时间戳有固定时效窗口，每个 Nonce 只能
使用一次。

Bootstrap Token 的持有者仍能重新注册并冒充 Agent ID，因此它依旧是高价值密钥。作业具备领取
Lease、截止时间、取消确认和结果大小限制。编辑器默认使用本地编译器；只有显式选中远程后端时，
检查源码才会发送给能力匹配的 Agent，并且不会加载或返回目标文件。公开后端清单不包含标签与内核
细节，远程作业绑定已登录用户，每个用户最多同时进行两个检查。`/ebpf/run` 仍在本地执行。签名只能
证明结果来自某个已注册凭据，不能证明编译结果诚实；跨越更强信任边界前仍应考虑双向 TLS、节点
绑定密钥或证明。

执行前已观察到丢失的租约会被丢弃，不再执行或确认取消；轮询仍可继续处理后续任务，但不会因此
中断已经开始的编译。未领取的用户检查等待 35 秒后在下次队列访问时过期，释放源码和名额；教师
管理的无用户归属任务仍显式取消。响应正文逐块检查 640 KiB 限制，没有长度声明时也不等收完整包再拒绝。

内置独立 Agent 默认拒绝非回环明文 HTTP，只有显式设置实验网例外才会放行；同时禁用 HTTP 重定向
和环境代理、限制响应体大小，并支持从挂载文件读取 Bootstrap Secret。编译模式必须显式开启，且
`shared_kernel` 会被拒绝；执行器只以固定参数调用绝对路径 Clang，清空环境，使用私有临时工作区，
限制进程资源和输出，在摘要后删除目标文件，并预先拒绝非字面量或可越界的 Include 写法。Agent 应
使用无特权账户，不使用宿主 PID、内核挂载、Docker Socket 或 Linux Capability。Clang 会处理不受信
输入，因此仍需容器或虚拟机边界。

可选的托管 Compose Profile 会自动应用这套基线：使用无特权数字 UID、只读根文件系统、不发布端口、
丢弃全部 Capability、启用 `no-new-privileges`、使用 `noexec` 临时工作区，并限制 PID、CPU 和内存。
管理脚本把 Bootstrap 值写入权限为 0600 的宿主文件并作为 Docker Secret 挂载，不会输出该值；只有
教师显式启动后 Profile 才会启用。独立内部网络仅允许 Engine 控制流量，阻断到默认数据库/前端
网络和外部网络的直接访问。

## 推荐部署级别

对于多名学生提交自编代码，下一阶段目标已确定为无特权教学控制服务加每个活跃学生独占的 Linux VM。
桌面机可以承载 VM，不强制使用集中执行服务器。这一目标尚未实现，环境归属、恢复和学生自管设备
结果可信度的限制见[Linux 桌面与局域网课堂隔离](classroom-isolation.md)。不要直接给现有只编译
Agent 增加特权来开启远程加载。

### 个人电脑

每位学生一个本地实例。Windows 使用 WSL2，Linux 使用 native 或 Docker。这是首选方案。

### 远程个人虚拟机

每位学生一台 VM，通过 SSH 隧道访问回环端口。VM 可以在课程结束后整体销毁。

### 集中服务器

不建议多个学生共用同一个 Engine。如果硬件有限，应通过 VM、microVM 或独立实验节点隔离，
并限制每个节点的网络、CPU、内存和生命周期。

## 禁止事项

- 不要把 `CYANREX_BIND_ADDRESS` 改为 `0.0.0.0` 后直接暴露公网；
- 不要提交或分享 `docker/.env`；
- 不要把 Docker socket 挂入 Engine；
- 不要关闭认证或把公开注册当成课堂隔离；
- 不要允许学生运行来源不明的程序；
- 不要把宿主机重要工作负载和教学 Engine 放在同一安全域；
- 不要把 verifier 当成完整的恶意代码沙箱。

## 需要远程访问时

优先使用 SSH 隧道：

```bash
ssh -L 3000:127.0.0.1:3000 \
    -L 8080:127.0.0.1:8080 \
    USER@SERVER
```

长期服务应使用 TLS 反向代理、来源限制和主机防火墙，并设置
`CYANREX_SECURE_COOKIES=true`。启用 Secure Cookie 前必须确认浏览器通过 HTTPS 访问。

当前 Compose 的数据库、Engine 和前端发布端口共用 `CYANREX_BIND_ADDRESS`。改成局域网地址会同时
开放三者，不只是浏览器入口。应保持内部端口私有并核实监听与防火墙行为；专用课堂入口配置仍待实现。

## 课前和课后检查

课前：

- 更新依赖并运行 `npm audit`、`cargo audit`；
- 验证随机凭据和回环端口；
- 快照或备份实验 VM；
- 试跑全部实验；
- 确认宿主机没有敏感生产工作负载。

课后：

- 卸载所有 eBPF attachment；
- 停止实验栈；
- 清理临时账户和凭据；
- 检查 bpffs 是否存在异常残留；
- 集中环境优先销毁并重建 VM，而不是继续复用未知状态。

## 依赖扫描治理

- 前端依赖下限为 Next.js 15.5.27、DOMPurify 3.4.16、sharp 0.35.5 和 source-map-js 1.2.2。
  2026-10-08 的 Unreleased 门禁在 Next.js 15.5.24 中发现一项中危依赖告警，涉及上游
  [SSG/ISR 页面缓存投毒](https://github.com/vercel/next.js/security/advisories/GHSA-4jqv-mc3x-m676)和
  [catch-all 路由缓存投毒](https://github.com/vercel/next.js/security/advisories/GHSA-mcj8-r9mp-w47p)
  两份公告，因此将 Next.js 下限提升至已修复的 15.5.27，此修复收录于源码版本 0.5.4。
  依赖告警和补丁不证明具体部署可被利用、
  运行中的实例已更新，也不等于针对具体部署的漏洞利用回归验收通过。
  Next.js/sharp 下限保留上游的
  [Windows 服务端](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)、
  [AVIF 图像优化](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4) 和
  [sharp/libheif](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c) 安全公告。
  sharp 更新还修复[捆绑 librsvg 问题](https://github.com/advisories/GHSA-wq5f-xc86-pv6w)，
  source-map-js 修复[索引映射放大问题](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)。离线回归
  要求受支持 Next.js 15.x 的安全下限、DOMPurify/sharp/source-map-js 的安全覆盖下限和每个锁定副本，
  包括跨平台 sharp 0.35.5/libvips 1.3.4；
  联网审计仍是独立检查。
  需要重新构建并部署才能应用补丁，修改锁文件不会更新运行中的容器；自定义全局 libheif 也需至少
  1.23.2，npm 审计不代表宿主机动态库验收。
  2026-10-07 已发布 0.5.2 的检查保留一项 DOMPurify 低危，没有中危/高危/严重提示；该历史结果
  不变。之后收录于 0.5.3 的 DOMPurify 改动重新执行生产依赖审计，各严重级别均为零告警。两次结果都
  不证明所有依赖或部署中的动态库安全，依赖审计也不会盘点生成资源中内嵌的第三方代码。
- 我们会对 Rust 后端执行 `cargo audit`，并将已接受的告警记录在
  `scripts/security-audit-exceptions.json`。
- 锁定的 rustls 依赖至少为 0.23.45，修复 TLS 1.3 握手加密层级校验问题
  [RUSTSEC-2026-0285](https://rustsec.org/advisories/RUSTSEC-2026-0285.html)。需要重新构建并部署
  Engine 和 Runner Agent 二进制文件/镜像，修改锁文件不会修补运行中的进程。
  离线预检覆盖该已知安全版本下限，联网审计继续检查其他安全公告。
- 当前没有已接受的安全公告例外；原先的 `rsa`/`sqlx-mysql` 依赖链已不在锁文件中。
- 每个例外都包含复核截止日期，需要在到期前重新评估依赖版本。

### 0.5.3 的 DOMPurify 与 Monaco 资源加固

2026-10-07 的后续改动将 DOMPurify 提升到 3.4.16，采用上游针对 `IN_PLACE` 模式中
[钩子移除子树](https://github.com/cure53/DOMPurify/security/advisories/GHSA-p98j-92pf-mc4p)和
[强制移除 rawtext 根节点](https://github.com/cure53/DOMPurify/security/advisories/GHSA-6688-9rhm-gjv2)
的修复。此改动收录于源码版本 0.5.3，不属于此前的 0.5.2 版本；生产审计阈值不变，不新增安全公告例外。

Monaco 0.55.1 的 AMD 资源另内嵌 DOMPurify 3.2.7，仅修改 npm override 不会替换该副本。
资源同步先核对受支持的 Monaco 精确版本、原始 chunk SHA-256 及 JavaScript 语法树结构，再仅将
第三方代码块替换为隔离 IIFE 内的官方 DOMPurify 3.4.16 ESM 实现。新内容摘要生成新的 chunk
文件名并同步改写 AMD 引用，避免复用旧 chunk URL。版本、摘要或结构不符合预期时直接失败，
不回退到旧清理器。仅改变生成资源，不修改 `node_modules` 或 Monaco 包版本。

校验、复制及补丁写入先在 `public` 之外的私有临时目录完成，随后才替换生成资源目录。准备阶段
失败保留原公开资源；最后的删除再重命名发布步骤不是原子事务。

前端 Docker 配方在复制工作区之后，从依赖阶段复制经 postinstall 校验生成的 `public/monaco`。
构建上下文排除宿主机的 `public/monaco`：Docker 复制目录会合并，仅覆盖新资源不能清除宿主机
残留的旧 chunk。公共源码守卫核对这条输入边界，不代表已经构建或部署镜像。

默认工具单测覆盖替换契约；显式[浏览器夹具](testing-guide.md)中的九项用例对实际生成的 AMD
chunk 做测试插桩，取得 Monaco 使用的同一清理器实例，检查 HTML 清理、钩子移除子树、rawtext
根节点拒绝、健康根节点身份及真实 hover 消费路径。第十项通过未修改的 AMD loader 与编辑器入口，
从请求拦截提供的本机文件加载新 chunk 和语言注册图。夹具不启动 Next 或 Engine、不产生外网访问；
不证明应用已存在可利用漏洞，也不是已部署前端验收。应用修复需要重新生成、构建并部署资源，
依赖审计零告警不能代替这些步骤。

## 安全事件处理

若怀疑凭据泄漏或存在未知程序：

1. 立即断开实验节点网络；
2. 停止 Engine；
3. 不要只在应用内修改密码后继续使用；
4. 导出必要日志和 attachment 信息；
5. 对一次性 VM 直接销毁重建；
6. 轮换数据库、管理员、TOTP 和 SSH 凭据；
7. 检查宿主机其他工作负载是否受到影响。
