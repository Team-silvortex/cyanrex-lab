# ADR-016 绑定版本的审阅记录

状态：**C2-D 已收录于源码版本 0.4.8**。决定日期：**2026-10-03**。

Review 现在独立保存针对确切 Artifact 版本的判断，不要求 Task、Run 或教学角色。人工评语保留
修订历史，规则结果不能通过编辑变成人工批准。直接存储仍是可信适配器使用的 PostgreSQL 准备层，
不是认证、已验证证据或任务验收；本准备层收录于源码版本 0.4.8。0.4.9 另行收录的
[C2-H 适配器](session-review-commands.md)增加会话授权的私人人工命令。

## 契约与来源区分

`ReviewRef` 固定 authority、Workspace、Review ID 与正的 JSON 安全修订号。`ReviewRecord` 另含
审阅者、确切目标、证据引用、判断、直接前驱 `supersedes` 与创建时间。来源使用严格的带标签结构，
拒绝未知字段和未知来源。

| 来源 | 保存的判断 | 修改方式 |
|---|---|---|
| `human` | 固定策略版本、`approved` / `changes_requested` / `commented`、纯文本评语 | 同一 Review 的新修订 |
| `rule` | 固定定义/包、策略、证据 Schema、`passed` / `not_passed`、反馈 | 不可修改；重新评估使用新 Review ID |

Agent/session 来源契约尚未建立，因此不接受 Agent 来源。人工 `approved` 只是保存的意见，不证明
审阅权限，也不代表任务验收策略已满足；规则通过不会转换成这个人工结论。Review 不推进 Task 状态、
安装策略、执行评估器或发布内容，也不要求创建假 Run。

`ReviewDraft::human`、`ReviewDraft::rule` 字段私有且不能反序列化，人工修改使用 `HumanReviewEdit`。
这些构造器只验证结构与上限，不能建立信任。适配器仍须从服务器权威上下文取得审阅者、来源和策略，
不能直接相信浏览器声明。规则构造器接受可信代码提供的 `TaskAssessment`，并不证明规则确实运行、
策略已经安装，或目标内容确实是评估器当时的输入。

目标要求 1–32 个引用，辅助证据允许 0–32 个；每个引用固定 Workspace、Artifact ID、版本 ID 和摘要。
同一列表不允许重复坐标，即使摘要不同；目标可以同时作为证据，但两边不能为同一坐标声明冲突摘要。
所有引用必须属于存储指定的 Workspace。

人工评语最多 8,192 个 UTF-8 字节，允许制表符和换行，拒绝其他控制字符。`commented` 与
`changes_requested` 必须提供非空白文本；批准允许空评语。规则反馈沿用目录上限：最多 64 条，
每条 2,048 字节，总计 16 KiB。定义、策略与证据 Schema 名称必须属于记录的包命名空间。
整条修订/事件序列化后还受独立的 64 KiB 上限约束。

## 存储操作与历史

`ReviewStore::new(pool, scope)` 不执行 I/O，不读取环境配置。显式安装器只接受空的独立命名空间；
普通操作不会创建或修复缺失表。

| 操作 | 结果 |
|---|---|
| `create(id, reviewer, draft)` | 修订 1，无前驱；重复 ID 返回冲突 |
| `revise(expected, reviewer, edit)` | 加锁并核对当前 Review 引用，仅为人工判断创建下一修订 |
| `read(reference, reviewer)` | 按审阅者过滤，读取确切历史修订；不是“当前批准”的浮动视图 |

修改只改变人工结论/评语及派生的修订号、时间、前驱。目标、证据、策略与审阅者不变；新的内容目标、
策略或规则评估需要独立 Review。Artifact 发布新版本后，旧批准仍只针对原目标。读取旧记录不证明
它是最新意见，也不证明当前内容获批。本轮没有列表/当前批准投影、删除、转交或验收命令。

该存储**不解析 Artifact 引用、不校验内容摘要、不授权读取引用资源**，也不核验 Principal 类型/
存在性或组合 C1 成员、退役、撤权检查。审阅者过滤不是认证，知道 UUID 不是合法凭据。不能将其
直接暴露为不可信公共 API。未增加路由、在线状态、启动安装器、CLI 或旧评语迁移，也不改变现有认证。

## 事务与失败行为

`0013_collaboration_reviews.sql` 提供 Schema 元数据、Review 头指针、不可变修订行与 outbox。
创建/修改在同一事务更新头指针并插入修订和事件。事件具有生成的 ID、审阅者归属、完整结果记录，
类型为 `cyanrex.review.recorded` / `cyanrex.review.amended`。服务不覆盖已有修订/事件；只有行数、
写后作用域与回读一致，且提交确认成功，才返回成功。

写入先锁 Schema 元数据，再锁 Review 头。关联读取在行锁之后进行，让等待中的写入者看见已提交的
并发胜者。独立读取使用一个只读、可重复读快照；C2-H 借用来源的 READ COMMITTED 事务读取时，
则先锁住头记录再查关联记录。头指针必须同时匹配最新修订与最新事件，倒退指针不能
隐藏后续意见。目标修订必须与事件、引用和审阅者一致；历史读取还比较其固定目标/策略与头记录。
这是有界的头与指定修订校验，不是完整历史对账，也不能防御协同修改数据库。未请求的历史缺口不扫描。

安装拒绝 public/系统/歧义路径与已有关系、函数、类型。运行时要求四张永久普通表，拒绝 RLS、分区、
继承和临时表遮蔽，并用关系锁固定检查对象。元数据固定 Schema 1 和作用域；这不是完整 Schema 指纹。
即使数据库约束被移除，读取仍限制快照大小。整个操作限时 10 秒、语句 5 秒、锁等待 2 秒；错误不暴露
原始 SQL、路径或凭据，也不降级成内存成功。

取消、超时或丢失提交确认不证明回滚。重复写入不是成功凭据重放；没有自动重试、修复、事件分发器、
全局事件顺序、消费游标或恰好一次交付，也不接入旧遥测总线。

## 验证与下一边界

4 条默认测试覆盖草稿上限、来源区分、数据库不可用及禁止在线/教学耦合。17 条显式 PostgreSQL
用例覆盖历史保留、作用域/审阅者、并发修改、规则不可编辑、安装拒绝、抑制/延迟写入、取消、一致读取、
写后损坏、RLS/临时表、事件缺失、指针倒退、有界解码、锁超时、溢出与历史目标错配。跨存储夹具用
Artifact 校验后的字节调用纯文本任务提供器，保存规则与人工意见后发布新内容，再验证原引用/字节和
Task 状态不变。夹具明确提供可信归属，不代表已验证会话用户工作流，也不证明 ReviewStore 自动验证证据。

`scripts/test-review-storage.sh` 要求一次性数据库，确认每个准确名称存在后才执行；CI 使用同一
脚本，另有回归检查清单覆盖。实际结果与未执行检查见[项目状态](project-status.md)。不要对已部署
数据执行故障注入。

[C2-E](session-task-commands.md)与 [C2-F](session-artifact-commands.md)提供私人任务/制品授权。
[C2-H](session-review-commands.md)现在把当前经审计 Human 成员、私人 Review 命令及
确切所属目标/证据校验组合为同一来源事务，只接受匹配配置策略标签的人工意见；标签不证明策略已执行。
可信直接写入口仍没有来源标记或切换栅栏，因此经 C2-H 读取记录不证明它原先由 Session 创建。
跨用户审阅权、规则/Agent 发出判断的权限及适用领域策略仍需另行实现。Task 验收必须核对准确的
任务/内容/Review 修订和该策略，不能只消费 `approved`。公共 UI/API、旧教学离线迁移、保留策略及
可靠 Run/事件交付仍待完成；C2 与 C-M2/C-M5 尚未完成。
