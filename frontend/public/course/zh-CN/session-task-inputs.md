# ADR-019 会话授权的私人任务输入

状态：**C2-G 已收录于源码版本 0.4.9**。决定日期：**2026-10-03**。

成员现在可以创建、读取和推进以自己 Artifact 的确切版本作为输入的私人任务。当前 Session 授权、
Task 状态/事件与输入访问检查处于同一个来源事务，连接[私人任务](session-task-commands.md)与
[私人制品](session-artifact-commands.md)适配器，不增加领域定义、Run、Review 批准或公共工作流。
源码版本 0.4.9 没有改变在线教学数据或路由。

## 配置与操作

仅 Unix 提供的 `SessionTaskInputsWorkspace::new(SessionTaskWorkspace, SessionArtifactWorkspace)`
接收可信服务端配置，不接收请求自选的命名空间或路径。两个句柄必须属于同一 authority/Workspace；
Task、Artifact 与来源/注册表命名空间必须互不相同，且已在同一数据库中初始化。命令只用来源连接，
不另开存储事务，也不创建、接管、迁移或修复命名空间。

| 来源命令 | Session 和配置以外的输入 | 确认后的结果 |
|---|---|---|
| `create_session_input_task` | Task ID、标题与准确 `ArtifactRef` 列表 | Draft、修订 1 的私人 Task 快照 |
| `get_session_input_task` | Task ID | `SessionTaskInputs { task, inputs }`；不存在或属于别人时为空 |
| `transition_session_input_task` | Task ID、预期 Task 修订和下一状态 | 输入不变的新 Task 快照 |
| `replace_session_input_task_inputs`（[C2-J](session-task-revisions.md)） | Task ID、预期修订、1–32 个准确引用 | 替换有序输入后的 Draft |

仅支持没有目录定义且包含 1–32 个输入的任务。引用固定 Workspace、制品 ID、版本 ID 和摘要，
重复制品/版本坐标会拒绝。每个输入必须属于当前 Session 的 Principal，并能在配置的制品存储中
解析出通过校验的字节。知道摘要、拥有教师身份或部署管理权都不授权读取他人内容。原 C2-E 的
纯手工接口仍拒绝所有 Artifact 输入和目录定义。

状态变化保留原标题与输入列表。Artifact 的新版本不会让旧任务浮动到 `latest`，任务仍读取原版本。
没有共享、转交或定义升级；[C2-J](session-task-revisions.md)现已提供显式 Draft 输入换版，检查
旧、新内容及预期修订。无输入的手工任务继续使用 C2-E 适配器。

[C2-I](session-catalog-tasks.md)通过独立目录适配器复用此事务，支持 0–32 个输入，只复制
服务端准入的定义元数据，不保留或执行提供器；读取/状态转换要求与完整保存快照相等。零输入仍在写入
前后固定并校验 Artifact 命名空间/Schema 元数据。此处 C2-G 方法继续拒绝任何目录定义，元数据准入
不验证类型化 Evidence 或执行评估策略。

## 单一授权与存储事务

适配器从准确且当前的账号代次、经审计的活跃 Human、活跃 Workspace 和活跃成员关系解析所有者，
整个资源操作期间持有来源及注册表锁。先检查并锁定 Task Schema/元数据和已有任务行，再锁 Artifact
元数据与头指针。输入按稳定 ID 顺序访问以固定加锁顺序，不改变保存的输入顺序。借用事务的制品
读取在 READ COMMITTED 下先锁头指针再查版本/事件，同时验证所有者、准确引用、长度、摘要和
私有文件约束。

创建或状态转换先验证输入，再写 Task/outbox，随后复验全部输入，回到 Task 命名空间完整读回待提交
快照，最后完成授权复核。这两种修改逐个检查并丢弃输入字节；不会写入、删除或修复 Artifact 内容，
也不新增制品变更事件。

共享检查保留每个访问过的命名空间首次名称/OID。离开当前目标前必须核对，重访同名目标不能覆盖
原固定值。提交前复核全部目标，恢复来源，再查当前身份/成员，最后使用数据库的新鲜时间复核准确
Session。来源名称或 OID 不能当作资源目标。事务局部搜索路径在成功、失败或取消后不得泄漏到连接池。

读取也经过这条加锁授权路径。返回的 `inputs` 与任务原始引用顺序一致，只包含经过校验的内容。
沿用单版本 1 MiB 上限，一次最多返回 32 MiB 输入字节及相应元数据；不是流式读取或总存储配额。
最终复核与提交确认前不返回待提交记录或内容。读取结果不是后续命令的授权凭证，也不是维护工具的
可重复读观察。
最终 Session 复核不保证任意延迟的 COMMIT 期间会话持续有效。

## 失败与取消策略

输入不存在、属于他人、引用不符或内容损坏均拒绝操作，不跳过输入，也不伪造空内容。这同样阻止
转入 `cancelled`：本切片保守地要求每种状态修改都能读取并授权全部输入，没有紧急取消或修复旁路。
取消 Task 仍不会停止 Run 或释放内核资源。

沿用原状态图、预期修订冲突、终态限制和 Task/outbox 原子发布。存储、事件、命名空间、授权或提交
失败不发布成功的任务修改。整个操作等待上限 10 秒、语句 5 秒、锁等待 2 秒，不降级到易失成功。
超时后阻塞文件读取可能继续，但此适配器不启动文件写入。

取消、超时及丢失提交响应不证明回滚。本轮没有命令回执、成功重放、自动重试、清理或恢复。
数据库锁保护遵守协议的存储路径，不能防止数据库特权操作者或同 Unix UID 在文件校验后更改内容。
字节校验不证明作者身份、内容语义、Review 证据策略或任务验收。

## 验证与剩余工作

3 条默认测试与 20 条显式 PostgreSQL 用例覆盖配置与输入边界、准确版本/顺序保留、无需教学角色的
私人所有权、过时 Task 修订、
输入丢失/损坏、事件及提交故障、命名空间替换、生命周期撤权、锁等待、过期与取消。
显式 CI 入口为 `scripts/test-session-task-inputs.sh`，须逐项确认测试名称存在，再在一次性数据库
运行；禁止对已部署数据注入故障。实际执行结果与未重跑项另记于[项目状态](project-status.md)，
此处覆盖范围说明不代表所有检查已经通过。

可信 Task/Artifact 直接写入口仍保留，没有切换栅栏或新的来源标记。此适配器检查当前所有权和内容，
不证明历史记录由 Session 命令创建。[C2-H](session-review-commands.md)另行增加当前
Session 授权的私人人工 Review 命令，在同一事务校验确切所属目标/证据；配置策略标签不证明策略
已执行、历史记录由 Session 创建或 Task 已验收。类型化证据验证、评估策略执行、跨用户审阅/资源授权、
旧写入栅栏、Task 验收、公共 HTTP/CSRF/UI、迁移、内容保留及可靠 Run/事件交付仍是独立工作。没有切换在线
AuthService、API/SDK 契约或部署。后续 [C2-J](session-task-revisions.md)将全新 Task 存储模板改为
Schema 2，拒绝 Schema 1 且不迁移；C2 与 C-M2/C-M5 尚未整体验收完成。
