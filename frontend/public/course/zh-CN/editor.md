# 任务 payload 编辑

`/tasks/new` 持有本地任务草稿及其 payload：按需要添加的笔记、代码、配置等文本内容。
多语言编辑器只负责当前选中内容的编辑，不独立存储正文。`/editor` 保留为同一任务容器的兼容入口。
新任务默认没有代码或其他内容项，页面沿用侧栏登录门禁。

这项前端能力收录于源码版本 `0.4.9`，尚不创建服务端 Task 或保存 Artifact。下载之前，草稿只在页面内存中；编辑
不会上传、执行或评估内容。源码发布不代表本地编辑器已连接后端准备层。

0.5.0 收录的修复让同页锚点跳转保留草稿与编辑器；路径或查询参数变化仍会复查身份。
导入/下载文件名在长度边界保留完整 Unicode 字符，不放宽正文校验。

## 语言能力

以下 14 个配置来自 [`languages.ts`](../../frontend/src/features/editor/languages.ts) 中实际启用的
提供器，不代表已经安装对应语言服务器。页面会显示当前语言能力，并禁用不支持的工具栏操作。

| 语言 | 内置能力 |
|---|---|
| TypeScript、JavaScript | 补全、悬停提示、参数提示、定义跳转、引用、重命名、大纲、格式化、诊断 |
| JSON | 补全、悬停提示、大纲、格式化、诊断 |
| HTML | 补全、悬停提示、重命名、大纲、格式化；没有诊断服务 |
| CSS | 补全、悬停提示、定义跳转、引用、重命名、大纲、格式化、诊断 |
| Rust、Python、C、C++、Markdown、YAML、SQL、Shell | 仅语法高亮和明确的代码片段补全 |
| 纯文本 | 文本编辑，不声明语言服务能力 |

诊断只是编辑辅助，不等于编译、测试或评估成功；未报告问题也不证明文档有效。基础语言配置没有
编译器、类型检查、项目导航或格式化服务。当前没有 rust-analyzer、Pyright、clangd 或 LSP 传输，
也未启用 JSX/TSX 配置。

## 使用方法

1. 登录后从侧栏进入**任务草稿**，或访问 `/tasks/new`。先填写任务标题；任务不一定需要代码。
   **添加文本**会创建空白纯文本内容项。可以添加多项笔记、配置或源码，并分别选择语言。
2. 使用当前语言支持的**代码补全**、**格式化**或**文档大纲**。`F1` 打开 Monaco 命令面板，
   `Ctrl/Cmd+Space` 请求补全，支持定义跳转的配置可使用 `F12`。点击问题列表中的条目可定位到对应位置。
3. **从文件替换**和**清空此项正文**经确认后，只操作当前选中项。导入文本按受支持的扩展名选择
   语言，未知扩展名使用纯文本。修改内容文件名不会切换语言，也不授予文件系统访问权。
4. **下载此项内容**只导出当前 UTF-8 文本；**下载任务草稿**将标题和全部内容导出为
   `cyanrex-task-draft.json`。请确认浏览器确实保存了文件；发起下载不代表任务已保存或已提交。
5. **打开任务草稿**经确认后从受支持的 JSON 格式替换整份草稿。**移除选中内容**和**清空任务草稿**
   也需要确认，且不能撤销。它们只影响内存中的任务，不删除已保存文件或服务端记录。

每项文本最多 256 KiB UTF-8，输入和粘贴同样受限；一份任务最多包含 32 项。非法 Unicode 和二进制
控制字符会被拒绝，保留已接受的内容；允许制表符和换行。标题最多 256 个 UTF-8 字节。整份草稿
JSON 的导入和导出上限为 8 MiB，包含转义和元数据，因此原文未超限也可能无法导出。导入不会执行文本。
确认和异步读取绑定当时的任务代次及修订，过期结果不能替换之后的草稿。

切换内容项会把各项文件名、语言和正文保留在父任务中，并销毁当前显示模型。切换语言同样会创建带
匹配扩展名的新模型。这两种操作都不保留撤销历史。整份任务替换会释放旧编辑器，即使导入的内容 ID
和修订号相同。被拒绝的编辑会恢复到父任务最后接受的值。
草稿没有浏览器存储、自动保存或恢复历史。关闭页面警告和显式网页链接确认只能辅助防误操作，
不能覆盖全部程序导航、历史导航、会话变化、浏览器崩溃或恢复。重要内容请先下载。

## 本地服务与隔离限制

Monaco 资源和工作线程从 `/monaco/vs` 加载，不回退到外部 CDN。语言工具不请求外部 Schema 或下载包，
不把文档源码发送给 Engine。侧栏原有身份检查和状态请求保持不变，因此不能将整个应用称为离线或无网络环境。

每份文档使用唯一的内存 URI。自定义片段只响应所属编辑器当前、存活且语言匹配的模型；被替换的模型
会销毁，卸载页面时还会清理编辑器监听器和自定义提供器。原 `/ebpf` 编辑器仍独立保留 Engine 编译检查、执行、头文件和调试
功能。其 C 补全拒绝其他语言；即使同一模型从 C 切到其他语言再切回，也会取消旧请求并清空缓存。

TypeScript 和 JavaScript 内置服务在页面内共享 Monaco 工作线程及默认配置。强制按模块解析可以减少
意外的全局符号混用，但这一设置和唯一 URI 都不是安全沙箱，也不提供多工作区项目隔离。
多项 payload 编辑不等于文件系统项目：尚无跨文件模块解析、包安装、执行环境或服务端 Task/Review 工作流。

## 草稿格式与服务端边界

本地格式为 `{ format: "cyanrex.task-draft", version: 1, title, payload }`。每项内容包含
`kind: "text"`、本地 `id` 和 `revision`、`filename`、`language`、`text`。代码、Markdown 和配置
共用文本内容契约，不给所有任务强加 `code` 字段。未知字段、格式版本、内容类型、语言及重复 ID 均被拒绝。
本轮只实现文本 payload，尚不支持导入二进制附件或服务端 Artifact 引用。

本地 ID 和修订只用于防止编辑竞态，不是服务端身份、授权或不可变 Artifact 版本。Rust 准备层已经
通过 `TaskSnapshot.input_refs` 固定 Artifact 修订；[C2-J](session-task-revisions.md)现已增加
Session 授权的 Draft 任务引用换版，前提是另行发布新的 Artifact 内容。换版失败不授权删除该内容。
公共任务编辑 API 和浏览器保存仍未接通，本前端不绕过授权、预期修订检查或缺失的服务端适配。

0.5.0 收录的 [C2-K 内容清单](task-content-manifest.md)定义独立服务端元数据与给定快照纯校验，
不是本地导入格式或保存命令：纯契约本身不持久化元数据，本地空标题仍需保存时明确处理，浏览器语言白名单
保持不变。文件名标签与语言提示不授予文件系统或执行权限。

独立的 [C2-L 可信存储](task-content-store.md)在 Schema 3 中持久化元数据；
[C2-M](session-task-content.md)增加内部 Session 与文本字节检查，但都没有连接浏览器草稿，
不会让本地导出变成服务端保存。同一版本还收录未挂载的 [C2-N HTTP 路由](task-content-http.md)，
但没有 Session 签发器或浏览器保存接线。

## 实现与回归范围

`frontend/src/features/tasks/` 负责不可变任务草稿、选中内容、确认操作和严格 JSON 格式。
`frontend/src/features/editor/` 提供受控文本编辑组件和本地语言服务：编辑携带预期修订交给父任务，
同步父任务接受的内容时不重复产生编辑。它不依赖具体任务类型，也不复用 eBPF 控制器。
回归覆盖任务往返、非法及过期编辑拒绝、提供器归属与取消、语言切换、销毁清理和真实工作线程行为。
实际验收结果见[项目进度](project-status.md)，
本能力表不代表所有测试已经通过。

整体前端与 Engine 边界见[系统架构](architecture.md)。
