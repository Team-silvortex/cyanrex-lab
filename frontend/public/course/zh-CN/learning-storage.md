# 学习记录存储与查询开销

学习记录保存提交源码、自动反馈、完成证据和当前教师评语。本地内存持有方式、文件写入与查询
算法保留学习验收、权限、HTTP/SDK 成功载荷、PostgreSQL 查询及 JSON 存储格式。
2026-09-13 的沿链路抓虫使读取错误明确可见，并收紧本地快照创建边界。

## 本地快照

路径为 `CYANREX_DATA_DIR/learning/<instance>/attempts.json`。首次访问时读取普通 JSON 数组，
构造共享快照及引用计数记录。取得快照只复制一个共享指针，不复制所有学生源码；查询释放内存
锁后，在同一只读快照上扫描、聚合，不修改原记录。

新增只创建指针索引和一条新记录；保存评语只复制索引与被修改的记录。其余记录继续共享，旧
读者的快照保持原样，过期评语版本在构造替换快照前拒绝。这是内部写时复制，不是 HTTP 缓存，
后续请求会读取最新已发布快照。

本地写入由同一持久化锁串行处理：阻塞工作线程通过 64 KiB 缓冲，将新集合流式编码为原有 pretty
JSON，写入同目录随机命名的 `.learning-<uuid>.tmp`，显式 flush、关闭文件，再 rename 替换
`attempts.json` 并发布内存。
编码和文件 I/O 不再占用异步执行器线程，也不分配完整编码文件缓冲；编码/写入/flush/rename
返回错误时不发布未保存内容。
缺少 `teacher_feedback` 的旧数组仍能读取，无需迁移或引用封装；历史 API 返回的记录仍独立持有。

临时文件以排他创建方式打开，不截断或跟随已有临时路径。新建 Unix 目录/文件采用 0700/0600，
不修改既有父目录权限。报告写入失败时尝试清理本次创建的临时文件，清理失败记日志；旧固定名
临时路径不触碰。数据目录及父路径仍需可信所有权；这不防御恶意替换父目录，也不迁移旧目录权限。

## 首次加载

第一次访问本地记录时，先取得同一把持久化锁，再交给阻塞工作线程执行文件读取、整文件 UTF-8
校验和 JSON 解析，不占用异步执行器。私有 Serde 数组解码器直接把每条记录包装为共享指针，
不再先构造完整 `Vec<LabAttempt>`。输入仍是完整内存字符串，不是流式或有大小上限的读取。
未知字段、旧记录、顺序及尾随/非法输入的拒绝行为不变；未知字段中出现非法 UTF-8 也会拒绝整文件。

每个共享 Store 最多有一个排队或运行的初始化/提交；并发首读复用成功发布的快照。等待锁时取消
不会派发工作，交接后即使调用者退出，工作线程仍持锁完成完整快照发布，再设置就绪标记；热态
访问只检查标记，不再启动工作线程。不会用[可取消的 OnceCell 初始化](https://docs.rs/tokio/1.53.1/tokio/sync/struct.OnceCell.html#method.get_or_try_init)
来管理已经脱离调用者的阻塞任务。

只有 `NotFound` 被视为空记录，且不创建文件；其他 I/O 错误（包括父路径不是目录）、非法 UTF-8
或 JSON 解析失败均不标记就绪、不发布部分结果，后续调用可以重试。错误不缓存，也不合并等待者
的失败重试；通用警告不记录存储内容。公共读取会传递加载错误，不再返回空/默认成功，写入也
返回存储错误。未增加 `.tmp` 恢复或外部文件监听。

## 读取错误与后端选择

`GET /learning/attempts`、`/learning/labs`、`/learning/teacher/overview` 和
`/learning/teacher/attempts` 在存储读取失败时返回通用 `500`，与已有的按归属恢复单条历史一致。
不可读数据不再变成空历史、零进度或空课堂。成功读取和存储错误响应均带 `Cache-Control: no-store`，
权限和成功载荷不变，错误不暴露源码或文件路径。只有本地文件确实缺失才表示新课堂的空记录。

读取一旦选中启用中的 PostgreSQL，模式初始化/查询失败就返回错误，不为这次读取关闭数据库或
静默读取旧本地快照；冷/热本地快照和重复失败均如此。原有运行记录写入降级没有移除，也不撤销
之前写入/配置已经建立的降级状态。Rust 聚合读取方法现在返回 `Result`，调用者必须处理错误。
首次加载失败后修复文件可以重试；成功加载后的 Store 仍不监听外部编辑。

## 请求取消与写入完成

调用者先取得共享写锁，再构造替换快照并交给工作线程；每个 Store（含其克隆）在阻塞线程池中
最多有一个排队或运行的提交。等待写锁或交接前取消不会启动磁盘写入；交接后，即使请求取消，
工作线程仍持锁完成 rename 和内存发布，避免后续写入用旧内存覆盖刚保存的文件。
已排队的工作线程也不会因调用者退出而释放名额；无人等待返回时，存储错误仍记录到日志。

这是“取消后完成提交”，不是回滚：超时或浏览器断开后仍可能保存成功。重试前先刷新历史/评语；
过期评语版本仍会冲突，追加记录未新增幂等键，正常成功响应会等待内存发布完成。
该行为基于 [Tokio 阻塞任务生命周期](https://docs.rs/tokio/1.53.1/tokio/task/fn.spawn_blocking.html)
及 [JoinHandle 脱离语义](https://docs.rs/tokio/1.53.1/tokio/task/struct.JoinHandle.html)。

显式 [flush](https://doc.rust-lang.org/std/io/struct.BufWriter.html) 用于在 rename 前检查缓冲写入错误，
不等于文件/目录 fsync。正常失败会清理本次临时文件；进程被杀、断电或清理错误仍可能留下部分
临时文件，加载时忽略，后续提交使用不同的排他名称，不从残留文件恢复数据。

## 查询行为

- **最近复盘：** 按用户扫描，最多保留请求数量的引用，对小结果集排序后再复制源码。公共 limit
  仍为 1～50，教师页面请求 20。保持时间倒序及同时间记录的原始顺序，不假设时间戳/文件顺序单调。
- **全量历史：** 仍按原有最新优先顺序返回全部匹配记录，复制全部返回源码，没有新增导出上限。
- **进度/教师总览：** 单次遍历聚合次数、最新自动反馈与最早完成时间，不复制源码或逐实验排序。
  未知/停用实验仍计入总次数与活跃时间，进度以当前五个实验为准；相同最新时间仍采用首条输入。
- **权限：** 教师/管理员守卫、学生归属与 CSRF 不变，评语不改变自动验收。聚合不含提交源码，
  已授权的历史/复盘接口仍返回源码。

设总记录数为 n、用户匹配数为 m、页大小为 k：最近页仍扫描 n 条，最多做 `O(m log k)` 堆操作，
选择空间为 `O(k)`，尚未增加用户索引。聚合仍扫描 n 条，实验目录大小固定，每个学生只保留少量
累计状态；每次重算结果，不引入独立缓存失效机制。

## 仍然存在的限制

- 加载仍同时持有完整输入字符串和解码记录，没有文件大小上限。所有本地记录仍驻留内存，
  没有新增保留上限；共享指针增加逐记录开销，读请求可能延长旧快照
  寿命，不能把某个基准的写入峰值下降当成全局内存或课堂容量保证。
- 写入仍复制 `O(n)` 指针索引并编码/重写整份 JSON；固定编码缓冲避免整文件分配，但不是追加
  持久化或固定延迟。
- 未新增文件/目录 fsync、崩溃恢复或跨进程锁，也无法在进程故障下原子发布磁盘和内存。
  请求取消后的完成保证不涵盖进程被杀、panic、运行时退出或断电；慢/卡住的 I/O 会保留该 Store
  的写锁及阻塞线程，可能拖延运行时关闭，没有新增加载/写入期限或全局队列限制。多个 Engine 或独立
  Store 不应同写一个文件；加载后不监视外部修改，应保留备份，不要编辑运行中 Store 的文件。
- PostgreSQL 查询与模式未变，读取失败策略以上述规则为准；仍获取原字段（包括源码），没有新增 SQL 聚合或数据库
  性能承诺。数据库评语写入失败仍返回错误，不转写可能过期的本地副本。
- HTTP/网络、浏览器、真实 PostgreSQL、内核及断电行为需另行验收。
  [2026-09-09 PostgreSQL 专项验收](acceptance.md)覆盖迁移、评语并发与按归属读取历史提交，
  不代表数据库性能或崩溃恢复已验收，也不是新的独立隔离环境。

## 复现本地基准

修改前构建已有 `mainline_bench` release example，复制到新临时目录并记录 SHA-256 及源码归属；
修改后运行：

```sh
node scripts/bench-learning-store.mjs <新输出目录> <冻结的旧 mainline 基准二进制>
```

脚本拒绝覆盖输出，以锁定依赖、离线构建的新二进制与旧二进制运行同一公共程序。30 个合成学生、
1 千/1 万/5 万条记录及 5 万条大源码，三轮共 72 次。场景轮换，每个场景的前后执行顺序逐轮交换，
公共门禁有排序回归测试。

预加载后开始计时，每次测 100 次最近页、30 次总览或 10 次写入；写入 nearest-rank p95 实际为
十次样本的最大值，不是可靠服务尾延迟。进程 CPU/RSS 包含准备、加载和清理，没有 fsync、清空
缓存或绑核；文件系统回写和共享主机负载可能主导写入尾延迟，应保留单次结果并区分暖查询与磁盘行为。

回归覆盖快照共享、旧读者不变、旧 JSON、写入/rename 失败、并发评语/追加、归属/排序/limit，
以及相对旧算法的差分聚合，还覆盖等待写锁/线程池排队/rename 后取消、旧版本重试、全部记录
编码前已流式输出、短写/中断和显式 flush 错误。外部 PostgreSQL 回归仍需显式配置后运行。

首次加载基准需先用与候选完全一致的 `learning_load_bench` example，在旧版库上构建并冻结二进制，
记录库和测试程序的源码归属，复制到构建输出目录之外，再运行：

```sh
node scripts/bench-learning-load.mjs <新输出目录> <冻结的旧 learning_load_bench 二进制>
```

四个数据集轮换五轮，共 40 个测量进程，每对执行顺序逐轮交换。脚本在被测进程之外生成合成文件，
全部读取结束后校验字节未变，只清理自己创建的临时数据。刚写入的文件仍处于操作系统页缓存中，
所以这里是 Store/进程冷启动，**不是冷磁盘**。每次记录最近 20 条的首读耗时、一次热读，以及
单线程异步运行时中 2 ms 定时器的最大延误；汇总为五次观察的中位数/范围，不是请求分位数。
进程 CPU/RSS 包括加载、查询、总览校验和退出，不包括数据生成。定时器用于暴露执行器阻塞，
不能解释为生产 HTTP 健康检查延迟或调度保证；退化的原型数据单独保留。

冷加载回归覆盖排队/解码后取消、并发首读与写入、文件缺失和路径错误、整文件 UTF-8、旧/未知
字段、非法/尾随 JSON 不部分发布、成功结果复用，以及失败后的重试。

首轮[沿链路抓虫](functional-network-bug-hunt-01.md)补充了路由级损坏/修复、no-store 与权限检查、
关闭连接池故障注入（不是真实 PostgreSQL 验收）、新文件权限、临时符号链接保护和 rename 失败清理回归。
