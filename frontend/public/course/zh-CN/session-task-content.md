## 命令契约

`SessionTaskContentWorkspace`选择可信配置中的专用任务命名空间及同一权限域、工作区的
Artifact 空间。两者必须不同且不是系统命名空间。这是配置，不是可由客户端反序列化的路由；
构造配置不会安装或接管数据库。

| 命令 | 返回结果与约束 |
|---|---|
| `create_session_content_task` | 按已校验清单创建私有手动 Draft，使用调用方指定的任务 ID，从修订 1 开始 |
| `get_session_content_task` | 返回任务/清单及按清单顺序排列的已校验字节，或不存在可见任务 |
| `replace_session_content_task` | 在预期修订的 Draft 上一起替换标题、标签和有序引用 |
| `transition_session_content_task` | 按已有生命周期和预期修订转移状态，完整保留清单 |

每条命令都从当前账户世代和经审计的活跃成员资格派生所有者。教师或工作区管理员身份不允许
读取其他成员的私有任务。创建和编辑允许零至 32 个可选文本项；相同清单作为无变化请求拒绝，
仅修改元数据也是实际编辑，会让同一个 Task 修订增加一次。

标题、文件名、语言及精确修订引用仍以[内容清单契约](task-content-manifest.md)为准。
文件名和语言只是标签；原有手动工作区不接纳目录定义。两种工作区都不执行内容、不接纳二进制附件，
也不授予共享访问；固定的评估策略是元数据，不是已经执行的验收规则。

## 0.5.5 收录的目录内容命令

**2026-10-08 后续进展，源码 0.5.4，Unreleased** 新增独立的强类型
`SessionCatalogTaskContentWorkspace::from_definitions(namespace, scope, artifacts, &catalog)`。
它先执行相同的可信命名空间/工作区检查，再保留不可变的 `TaskDefinitionCatalog` 快照，
不需要 `TaskProvider` 或证据评估器。

源码 0.5.4 上的 **2026-10-11 未发布多包跟进**允许该构造器接收显式组合的元数据目录，无须改变
工作区或命令。不同包、准确版本及同包互不重叠条目保留完整引用；重复引用在配置工作区之前拒绝。
组合限定 1–256 个输入句柄和最多 256 个展平定义，嵌套输入也遵守同一上限。四条命令仍要求完整
配置定义及原当前授权/文本检查，不需要提供器，也不选择浮动最新版。

源码 0.5.4 上独立的 **2026-10-11 未发布评估绑定跟进**允许目录定义同时具有两项评估引用，或
明确同时不绑定。同一冻结目录可以混合两种形式；无绑定 Task 仍含 `Some(TaskDefinition)`，
不进入手工模式。两个可空 JSON 字段仍必须存在；同一引用下任一方向的绑定变化，均由原完整
定义检查作为 `InvalidRecord` 拒绝。命令继续核验旧新准确文本、Task 修订及当前 Session，
不派发评估或 Review。Schema 3 与旧已绑定编码不变；新双 null 记录需要新读取器，无须迁移，
也不保证旧二进制降级兼容，详见[定义契约](task-domain-boundary.md)。

| 命令 | 目录专属契约 |
|---|---|
| `create_session_catalog_content_task` | 从配置目录精确查找 `TaskDefinitionRef`，以完整定义及所给文本清单创建私有 Draft |
| `get_session_catalog_content_task` | 只读取完整已存定义仍与配置快照一致的目录任务 |
| `replace_session_catalog_content_task` | 原子编辑 Draft 的标题、标签和有序文本引用，保留原定义 |
| `transition_session_catalog_content_task` | 沿用生命周期/修订检查，同时保留定义和清单 |

创建时未知引用在数据库操作前返回 `UnknownDefinition`。对所有者可见的已存任务，缺少定义、
目录中没有相应条目或完整定义不一致均返回 `InvalidRecord`。手动工作区拒绝目录记录，目录
工作区也拒绝手动记录；两者都不重新解释记录，也不把手动任务提升为目录任务。
清单标题独立于定义的展示标题，保留证据 Schema/评估策略的明确成对选择，但不执行这两项契约。

两种工作区复用同一认证源事务内容执行器，以及下文的授权和字节检查。继续使用已有 Schema 3，
不迁移数据库。新包装类型不能传入旧手动命令、C2-N HTTP 适配器或 C2-P–W 草稿发布流程；
这些入口仍仅支持手动任务。元数据/工作区组合本身不挂载 HTTP，也不连接浏览器保存。

源码 0.5.4 上独立的 **2026-10-11 未发布 [C2-Y HTTP 适配](catalog-task-content-http.md)**
通过 `CatalogTaskContentHttpState` 显式接收目录工作区。其 `/platform/v1/catalog-tasks`
命令只选择准确配置定义引用，完整定义、旧新文本及当前 Session 检查仍处于本认证源同一事务。
有绑定和无绑定定义都保留目录 Task 身份，不执行评估。旧手动 HTTP 和 C2-P–W 路径不变；
C2-Y 不接正常应用/OpenAPI/SDK/浏览器，不签发 Session、不迁移记录，也不自动组合路由。

源码 0.5.4 上独立的 **2026-10-11 未发布 [C2-Z 目录发布尝试](session-catalog-task-draft-publication.md)**
另行消费 C2-O 计划及准确配置引用，不属于已发布标签。准备不做 I/O 并冻结完整定义；显式推进
先逐项发布 Artifact，再调用 `create_session_catalog_content_task`。最终事务仍派生当前所有者
并重读真实 blob，确认要求预期清单与冻结的完整 `Some` 定义，有绑定/无绑定目录身份都不变，
不执行评估。旧手动 C2-P–W 入口保持不变；新尝试没有检查点/日志/观察/恢复、HTTP、签发或
浏览器连接，各次独立写入之间不保证原子性。

源码 0.5.4 上独立的 **2026-10-11 未发布 [C2-AA 目录观察](session-catalog-task-draft-observation.md)**
通过 `get_session_catalog_content_task` 读取一个准确未知 C2-Z Task 目标，不属于已发布标签。
已有当前定义/字节验证先于与尝试的完整冻结定义及计划有序文本比较。类型化损坏不能变成
有效差异或不可见；Task 缺席仍不检查 Artifact 命名空间。这条只读分支不收编确认、不解除
尝试未知状态，也不授予重试或公共访问。

## 授权与锁顺序

存储操作借用持久认证源拥有的同一事务。源身份和登记表的锁先于 Task 元数据及任务头。
任务写入前，守卫固定 Artifact 命名空间的身份，并按统一的 Artifact/修订顺序核验所有相关
精确引用。读取完成检查后恢复清单原顺序。

替换会检查旧项与新项的并集，包括被移除的内容。坐标相同而摘要不同的引用不能合并，避免
正确旧摘要掩盖伪造新摘要。只改文件名或删除全部内容也不能跳过旧内容检查；即使清单为空，
选定的 Artifact 存储命名空间也必须有效。

每项必须匹配精确引用、所有者、声明长度和 SHA-256，且是最多 256 KiB 的有效 UTF-8 文本，
除制表、换行和回车外不得包含控制字符。变更逐个核验并释放字节，不返回负载；读取只保留
将要返回的有界有效内容。通用 Artifact 发布仍是独立操作，所发布的字节未必适合作为任务文本。

修改任务及 outbox 后，适配层再次检查旧新内容，并重读完整预期的任务/清单。共享守卫随后
重新核对所有原始命名空间身份、账户世代、经审计成员资格和精确 Session，使用新的数据库时间
确认会话有效。只有确认提交后才返回结果；检查失败会回滚尚未提交的 SQL 写入。

## 存储与结果限制

Schema 3 与既有 Schema 2 手动任务、输入及目录适配层仍然隔离。每种格式都要求显式安装到
各自全新的命名空间，不能互相接管。可信 `TaskContentStore` 本身仍不是授权接口；其仅在 crate
内部可见的借用事务方法用于组合，不暴露带版本配置的私有底层句柄。

沿用十秒命令期限及已有语句、锁等待超时。接近提交时取消、超时或丢失确认，不代表已经回滚。
没有命令回执、自动重试或结果对账；编辑失败不会删除独立发布的 Artifact 修订。
字节检查不能阻止同 UID 在核验后修改文件；最终授权也不能保证任意延迟的提交期间 Session
始终有效。命名空间与记录检查不抵御特权数据库管理员，也不是全历史审计。

## 验证及下一边界

独立的0.5.3 收录的 [C2-P 流程](session-task-draft-publication.md)完成显式 Artifact 发布步骤后才调用
本创建命令。确认进度只保存在内存，不写入本事务或 Schema。C2-M 仍派生当前 owner 并重读
真实 blob；先前发布或 C2-O 值检查都不是可复用授权，也不形成跨步骤原子性。

默认 API/形状测试和显式临时 PostgreSQL 用例覆盖此内部边界。精确选择脚本为
`scripts/test-session-task-content.sh`，实际执行数量及限制见[项目进度](project-status.md)。
接入 CI 选择不等于已运行远端 CI，更不是已部署系统验收。
多包用例 `session_task_content/catalog_composition.rs` 将精确 runner 库存增至 32 条，检查组合
定义经过 Schema 3 的行为，不放宽手动模式隔离、私人所有权、完整定义及文本/修订检查。
独立用例 `session_task_content/catalog_assessment_binding.rs` 将当前库存增至 33 条，覆盖
有绑定/无绑定混合目录、显式 null 持久化及既有内容命令对绑定漂移的拒绝；库存数量不证明执行。

[C2-N](task-content-http.md)现为手动命令定义独立构造的 HTTP 准入层；正常应用尚未挂载，也不
签发会话或发布内容。浏览器链路仍需明确的安全登录/安装、有界内容发布与清单映射，再接保存、
读取、冲突及结果不确定处理。本地编辑器 ID 和下载 JSON 不是服务端身份或保存确认。迁移、共享、
Review 权限及执行仍是独立工作。
