# 事件流恢复

事件中心和 eBPF 断点面板是尽力而为的最近历史视图，不是持久订阅或“恰好一次”的审计日志。

## 协议与访问

- `GET /ws/events` 仍通过 WebSocket 文本帧发送原始 `EventRecord` JSON，没有新增消息封装、
  控制事件、游标、序列字段或子协议。
- Engine 按已认证的会话用户建立独立实时队列，不接受客户端指定订阅用户。其他用户的流量
  不再覆盖当前订阅的排队事件；原始 Event JSON、认证要求和恢复关闭码保持不变。
- 握手现在除了会话认证，还执行已有的 Origin/Referer 来源检查。浏览器会自动发送 Origin；
  原生客户端需发送配置允许的 Origin，可通过 `CYANREX_CORS_ORIGINS` 或默认前端地址确定。
  缺少来源时返回 `403`，除非管理员显式启用 `CYANREX_ALLOW_MISSING_ORIGIN`；禁止的来源仍拒绝。
  这是安全修正，旧的原生客户端可能需要调整，不建议在局域网开启缺少来源的豁免。
- JavaScript SDK 仍只返回 WebSocket URL，不代替调用方管理重连或历史恢复。

## 服务端边界

服务端在完成握手前建立订阅。当前用户的广播接收器发生 lag 时，以关闭码 `1013` 和原因
`event stream lagged; reload /events` 结束连接，不再静默跳过。该信号仅表示可能存在缺口，
不代表精确的当前用户丢失事件数。

每个活跃用户只有一个有界通道，生产 Engine 当前配置为 1,024 个槽位。同一用户的连接共享
不可变事件及每条事件的一份惰性 JSON 缓存，每个 socket 仍独立构造、发送数据帧；没有消费者
请求时不会提前序列化。向没有订阅者的用户发布不会创建队列。最后一个连接关闭或取消时清理
用户条目，并通过代次检查避免旧连接清理刚重建的新队列；订阅本身不会延长注册表寿命。
新订阅只接收实时事件，仍需通过 HTTP 获取历史快照。

容量是**每个活跃用户**的限制，不是全局内存预算。总队列内存随活跃用户数和载荷大小增长，
已消费事件还会保留 JSON 表示。本轮没有增加连接数/活跃用户准入上限；历史、设置、未读锁、CPU
和持久化资源仍然共享。这只消除了跨用户挤占队列，不等于完整资源隔离或学生安全沙箱。
旧的 `EventBus::subscribe()` 全局服务接口保留兼容；`/ws/events` 不再使用它，无全局接收者时
发布路径跳过对应载荷复制。

单次数据发送最多等待 5 秒。超时直接释放 socket 和订阅，不在可能只写出一部分的数据帧后追加
关闭帧，因此客户端也可能观察到异常关闭 `1006`。关闭帧最多等待 1 秒。这些限制针对异步发送，
不包括任意序列化 CPU 耗时，也不保证及时发现完全空闲的失联连接。本轮未增加心跳或活动会话撤销。

## 浏览器行为

两个消费者共用恢复逻辑：

1. 先建立 WebSocket，再携带凭据和当前筛选条件读取 `/events` 快照。
2. 快照读取期间最多缓存 200 条匹配事件，按插入顺序合并快照和实时记录；重复内容按出现次数
   处理，不使用无限增长的去重 Set。
3. 断线、请求失败或缓存溢出时，废弃旧连接和旧请求，持续提示可能缺失，并使用随机退避重试。
   初始等待 500–750 毫秒，最多 30 秒；只有稳定接收 30 秒后才重置连续失败的退避。
4. 握手和快照分别限制为 10 秒，最多保留一个有效连接、一个请求和一个等待/超时计时器。
   重连、切换筛选、删除事件或离开页面都会作废旧请求，迟到响应不能覆盖新数据。
   快照返回 `401`/`403` 或 WebSocket 关闭码为 `1008` 时停止自动重试；浏览器不暴露握手
   失败的 HTTP 状态，因此握手失败仍按退避重试。

事件中心保留 200 条记录。断点面板从最近 200 条内核事件中选取当前调试会话，最多显示 50 次命中，
原来无限增长的已见事件 Set 已移除。恢复成功后仍保留缺口提示，因为无法证明缺失记录已全部补齐。
持续过载时可能一直处于恢复状态，直到负载下降。

快照读取要求 no-store、禁止重定向，同时保留 Cookie 会话。异常 JSON、不符合 Event 结构及非文本
实时帧会被丢弃并持续提示可能缺失，但不单独触发重连。因界面筛选而排除的有效事件不算数据缺口。

断点状态绑定 Engine、调试会话、运行报告中归一化的已插桩行集合；切换时立即隐藏旧视图，不等待
订阅副作用。快照与实时筛选都要求内核断点事件、精确会话和声明过的正整数行；空集合不订阅。
继续采用 200 条恢复/50 次命中展示上限，以及按重复次数处理重叠。编辑器/文档更换或销毁时清理
所属高亮与回调，不展示文档范围外的命中行。清空请求断点只为后续运行准备，不卸载已有程序的探针。

Engine 追踪解析要求非空会话和完整的正十进制数字；零、小数、数字前缀、溢出及空行号会被拒绝，
允许正常追踪后缀的空白分隔。共享日志中的会话标记/行号列表并不认证内核事件生产者。
本轮证据与限制见[沿链路抓虫 06](functional-network-bug-hunt-06.md)。

## 历史、导出与未读操作

事件页按 Engine、导航和筛选绑定历史及连接/缺口状态。非法或倒置时间范围会停止历史查询、导出
和删除，不抛页面异常或静默扩大查询。切换筛选立即隐藏旧行；相对窗口每秒清理过期展示，不额外
请求快照或已读。刷新相同范围保留缺口提示；只有当前快照成功才可显示为空，恢复期间禁用删除。

导出捕获本次查询/格式，阻止重复派发，输入或导航变化时取消浏览器等待；20 秒期限包含响应体。
MIME 必须匹配 JSON/CSV，文件名安全且对应格式，下载激活后释放对象 URL。导出仍是独立的全量
历史查询，不是展示的 200 条记录的原子快照；本轮不新增文件内容校验、CSV 公式净化或总字节上限。

删除仍先审阅并输入确认短语，固定时间上界，不把可见数量当服务端删除范围。只有准确的 `ok: true`
及非负安全整数 `deleted` 才刷新视图；失败/超时保持结果不确定，不清空旧行，不自动重试。
离页只取消等待，不撤销删除；明确的会话/权限拒绝与传输不确定分开提示。

有效历史/实时投递后，1.2 秒防抖调用现有全账号已读接口，包括筛选与展示之外的记录；界面明确
说明该范围，接口仍无逐条 ID/截止时间。已读请求串行执行，筛选/导航变化取消计时器及等待；失败
明确显示，只有手动重试或新视图上下文才重新尝试。侧栏校验未读数量，最多等待 10 秒，完成后
等 4 秒再轮询；不可用显示 `?` 而非零。已读/删除确认会触发新读取并作废旧徽标响应。浏览器确认
本身不能证明存储成功，服务端确认策略见下文。复现见[沿链路抓虫 07](functional-network-bug-hunt-07.md)。

### Engine 读取失败与查询校验

历史、JSON/CSV 导出与未读 HTTP 接口现在使用可失败读取。已配置存储的建表、查询或行解码失败，
返回通用 `503`，不冒充空/部分历史、零未读或成功下载。异步读取等待（含模式初始化和连接池等待）
最多 10 秒，失败不关闭后续持久化；短暂故障修复后可重新读取，取消等待也不破坏存储。历史 SELECT
不跨请求缓存预编译语句，避免列类型修好后仍困在旧结果类型计划中。这影响历史 SQL 的计划复用，
不影响写任务缓存，也不声称改善性能。

此前写入/设置/旧服务读取已锁定降级时，这些 HTTP 读取仍拒绝成功，须确认存储健康并重启 Engine；
非法数据库 URL 也视为不可用。重启不自动合并易失事件。显式纯内存实例保持有界易失读取；旧不可失败
EventBus 帮助函数为兼容仍保留尽力回退，但 HTTP 不再使用它们。

历史/导出对非法或空分类/严重度/日期、未知或重复字段、负数或溢出时间窗、反向有效区间及不支持的
导出格式返回通用 `400`。`since_minutes=0`、历史默认/上限条数、分类大小写兼容与 JSON/CSV 成功格式
不变；两条路由仍忽略旧 `username`，历史忽略 `format`，导出忽略 `limit`，均不能指定他人身份。
成功读取/下载与处理器生成的查询/存储错误均为 `Cache-Control: no-store`；失败导出不带附件头。
认证中间件仍先控制访问。

期限约束协作式异步等待，不包括认证、响应序列化、任意 CPU 工作，也不证明 SQL 已取消。读取仍无
写队列屏障或快照/实时原子衔接。见[沿链路抓虫 10](functional-network-bug-hunt-10.md)。

### Engine 变更确认

HTTP 标记已读和删除必须确认选定存储的变更后才返回成功。配置非法/不可用、写队列屏障失败、
此前已降级或写入未确认均返回通用 no-store `503`，不以纯内存修改冒充确认。明确的建表/查询错误
不清空未读/历史，也不关闭持久化，修复后可重试；原有屏障/存储超时仍可能锁定降级，需检查存储和
易失事件后重启，不自动对账。显式纯内存实例继续易失操作；旧不可失败服务帮助函数保持兼容回退。

服务层协作式等待最多 10 秒，包含账号准入。准入前取消不派发；SQL 已交接后，后台任务继续持有
账号顺序直到缓存发布完成，即使调用方取消或已收到超时。因此 `503`、超时或丢失响应表示**结果未
确认，而不是回滚**：先核实当前状态，再手动重试，不自动重试。SQL 或本地发布可能在响应后完成。
这不是后台任务整个生命周期、认证/序列化的期限，不保证进程退出排空或数据库已取消语句，也没有
增加外部写入者/多 Engine 协调。

成功 JSON、会话所有权、CSRF、全账号标记已读及无筛选删全部保持不变。删除在排队前冻结校验后的
相对时间边界；非法/重复/未知参数和非法时间区间统一返回 no-store JSON `400`，成功确认也不缓存。
零匹配删除及已经全部已读仍是有效成功。SQL 删除数量包括未缓存行，保留剩余行已读标志；内存删除
在取得全部记录/未读/容量锁后才变更，纯内存等待取消不会留下半更新。
见[沿链路抓虫 11](functional-network-bug-hunt-11.md)。

### 事件保留设置

`GET /settings/events` 读取已配置存储，不以可能陈旧的运行时缓存代替。缺行表示正常的
500/DropOldest 默认值；非法持久上限/策略、解码/查询错误、此前降级或服务读取等待达到 10 秒均
返回通用 no-store `503`。读取失败可重试，不关闭持久化，也不缓存默认值；该读取不会把外部写入
同步进运行时策略，旧发布帮助函数仍按自身缓存尽力运行。

`POST /settings/events` 确认写屏障和同一策略/裁剪事务后，才发布本地设置/历史/未读/容量变更。
明确 SQL 错误保留内存、可修复后重试；屏障失败或此前已降级不能静默保存或裁剪内存。
它共用上面的 10 秒调用方期限与已交接任务取消语义：未确认不等于回滚，须核实后重试。
成功及处理器错误均不缓存；JSON 语法、超大请求体、内容类型和字段/类型错误保留
400/413/415/422，使用通用 JSON。上限仍截断到 50..50000，未知请求字段不能覆盖会话所有权。
显式纯内存设置仍为易失状态。见[沿链路抓虫 12](functional-network-bug-hunt-12.md)。

## 不保证的部分

### 持久化顺序与保留策略

SQL 健康时，已读、筛选删除、替换和保留设置先经写队列屏障等此前事件入库；按账号准入阻止同账号
后续发布抢先执行。已交接 SQL 的调用方即使取消，该序列仍会完成；其他账号仍能发布。纯内存路径在
等待锁时取消保持旧状态。设置/裁剪及替换各自使用事务，失败不发布新内存状态；变更清除容量缓存，
让 DropNew 立即使用释放的名额。同时间戳保留队列顺序，SQL 历史用时间戳和行 ID 排序。

队列仍为 2,048 格、批次 64 条。队列满/关闭不再逐事件另起 SQL 任务，而是警告并锁定内存降级直到
Engine 重启。屏障与选定的建表/设置/变更阶段分别最多等待 10 秒；不能证明已派发 SQL 停止或回滚，
也不是整个后台任务的统一期限。旧服务帮助函数仍可确认易失变更，HTTP 已读/删除/设置使用上面的单独策略。故障后
重启前应检查存储健康和易失事件；不自动恢复或对账。普通历史/未读读取没有新增屏障或原子衔接。

DropNew 冷发布现在先检查 SQL 保留行数，再改变历史、未读或实时队列；本地已接受但可能未入库的
事件也占名额，不受写任务一秒计数缓存过期影响。按账号串行初始化与预留，发布前取消不占名额；
删除、替换与设置在原有屏障后重新计算容量。仅冷启动或缓存失效的 DropNew 账号新增计数查询，
应用等待最多 10 秒；失败沿用锁定的易失降级。恢复仍须检查易失事件并重启，不自动对账。
DropOldest 与纯内存准入不变。计数是单 Engine 元数据，不能协调其他进程直接写 SQL。

后台写任务不再持有生产者句柄。最后一个生产者克隆退出后，运行时仍存活且 SQL 健康时会排空
队列（含最后不足一批的记录）并退出；存储已降级则丢弃待写事件并拒绝持久屏障确认。
这没有新增进程退出钩子、整个写任务的期限、丢失提交回执恢复或持久交付保证；运行时终止、SQL
停滞与写入重试歧义仍不在保证内。

见[沿链路抓虫 08](functional-network-bug-hunt-08.md)、[第 9 轮](functional-network-bug-hunt-09.md)、
[第 10 轮](functional-network-bug-hunt-10.md)、[第 11 轮](functional-network-bug-hunt-11.md) 和
[第 12 轮](functional-network-bug-hunt-12.md)：52 项 PostgreSQL 回归使用临时 Schema、真实 SQL 和受控
队列/锁，CI 显式选取这些忽略测试。
冷缓存重建使用同 Schema 上的新 EventBus，不模拟进程终止。仅可给 `CYANREX_TEST_DATABASE_URL`
配置一次性测试库，绝不能使用部署数据库：

```bash
cargo test --manifest-path engine/Cargo.toml --locked --lib services::event_bus::tests -- --ignored --test-threads=1
```

### 仍有的重放限制

只能恢复仍处于保留窗口内的最近历史。保留策略、筛选条件、其他内核流量或 Engine 重启可能导致
记录已不可恢复；PostgreSQL 是异步持久化，HTTP 快照也可能落后于内存广播。

现有协议没有事件 ID 或游标，只能按完整内容和出现次数处理快照与实时流重叠。完全相同的事件、
数据库时间精度归一化仍有歧义，因此不是原子快照衔接，也不保证恰好一次。全量导出行为不变。
若需要完整重放，应单独设计带版本的游标和持久化契约，而不是无限扩大客户端缓冲。

## 验证

`frontend/tests/breakpointLifecycle.browser.mjs` 与 `breakpointSafety.browser.mjs` 分别使用实际 hook
及生产 Monaco，检查会话/行号筛选、文档清理、缺口恢复与显式卸载；均为可选隔离浏览器测试。
`engine/src/routes/ebpf/ringbuf.inc.rs` 中的追踪解析回归为纯函数测试，不启动真实采样器。

真实握手及隔离回归在 `engine/tests/routes_tdd/events_ws.inc.rs`；前端状态机回归在
`frontend/tests/eventStream.test.mjs`，已纳入前端质量门禁。
`engine/src/services/event_bus/subscriptions/tests.rs` 覆盖共享事件/JSON、用户隔离、取消、最后连接
清理、旧代次清理竞态、并发发布与重连，以及旧全局接口和 DropNew 语义。
可选的 `frontend/tests/eventStream.browser.mjs` 使用真实生产页面和模拟 HTTP/WebSocket，检查
缺口提示、快照合并、筛选切换与窄屏布局；它不是浏览器到 Engine 的完整网络验收。

`node scripts/bench-event-stream.mjs <新输出目录>` 运行串行 release 压测：32 个订阅者的定速
分发、小通道突发，以及真实 TCP 客户端停止读取，均使用用户级队列。保存源码指纹和不可覆盖的结果目录。
压测使用本机回环上的真实 WebSocket 处理器，不包含认证、EventBus 历史、数据库、浏览器渲染或
内核 eBPF；定速分发是正确性检查，不代表最大吞吐能力。

`node scripts/bench-event-fanout.mjs <新输出目录> [旧 mainline 基准二进制]` 串行对比当前全局与
用户分发路径，包括惰性 JSON 缓存，要求匹配数据帧的字节数完全一致。故意扩大通道避免用丢数据
换吞吐，不能据此推断生产内存；可选的旧二进制用于无订阅者前后对照，其源码归属需另行确认。
此基准包含服务与数据帧构造，不包含网络交付。历史报告保留原始测试程序和源码指纹。
