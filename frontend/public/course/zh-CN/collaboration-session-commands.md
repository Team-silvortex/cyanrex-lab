# ADR-007：会话授权的协作事务

日期：**2026-09-27**。状态：**C1-F 内部组合，收录于源码版本 0.4.6**。
承接[持久认证源](collaboration-auth-source.md)、[身份生命周期命令](collaboration-identity-lifecycle.md)
及[策略审计](collaboration-policy-audit.md)。不切换在线 AuthService、路由或部署。

## 本轮交付

[认证源适配器](../../engine/src/services/auth_service/durable_source/session_commands.rs)把会话核实、
操作者解析、来源账号核实、注册表变更及审计放进**同一连接、同一 PostgreSQL 事务**。
不是先拿一个独立 Session 快照，再调用另一个自行提交的存储接口；不接收第二连接池或调用方指定的 actor。

| 入口 | 请求内容 | 服务端检查与变更 |
|---|---|---|
| `bind_session_account` | token 单独传入；命令 ID、Workspace、准确目标账号坐标 | 从会话解析当前管理者，核实来源代次，绑定并审计，不自动授予权限 |
| `apply_session_policy_command` | token 单独传入；命令 ID、已核对修订、期望策略 | 解析当前管理者及目标来源账号，带修订和最后管理者保护地修改策略并审计 |

两者要求在同一数据库/Schema 中显式安装认证源 Schema 1、身份 Schema 2、权限 Schema 2；作用域
必须匹配来源固定的 authority 及既有 legacy Workspace。不隐式安装、引导、导入或升级。合成测试
用真实注册返回的账号 ID，在审计启用前显式准备初始管理者；这不是新增生产引导 API，也不授权接纳旧账号。

适配器用规范 token 查询持久且未过期的会话/账号，按准确 username/代次解析已审计注册表中的身份。
操作者必须是活动、未退役 Human，且有当前有效的显式部署 Grant。用户名、teacher 角色、调用方
构造的 PrincipalRef、旧回执或缓存 Session 都不能替代；仅注册但未绑定的账号不能自行绑定或升级为管理者。
目标也必须匹配当前来源账号；策略检查不读取目标密码/TOTP，身份/权限审计不写入 token 或其摘要。

## 事务与锁顺序

命令先对认证源元数据取 `FOR SHARE`，再取得注册表身份/权限元数据、authority 写锁，之后才访问
账号、会话、身份和策略子行，全部持有至提交或回滚。这扩展了注册表“元数据先于 authority”的顺序，
也保护尚不存在的键。认证源注册/登录/退出使用 `FOR UPDATE`，会等待已进入事务的命令；退出先
提交后，后续命令不能复用该会话。不进行共享锁升级。

[注册表组合助手](../../engine/src/services/collaboration_identity_store/session_adapter.rs)及提取的
身份/策略修改助手仅 crate 内可用，参数是借用的 SQL 事务。返回的只是**待提交回执**，不能自行提交。
已有可信适配器接口继续用自己的事务/提交包装同一实现，命令摘要格式与回执语义保持不变。
认证源适配器在修改/审计之后再次核实目标坐标和准确会话，再请求 COMMIT；只有提交确认才返回。

注册表锁等待后和请求提交前都检查数据库实时时间；审计等待期间过期的会话会被拒绝，未提交修改
回滚。这不是持续授权，也不保证延迟的 COMMIT 一定在墙钟到期前完成。来源/策略撤销按事务顺序
生效，退出不能撤销已经提交的命令。继续使用十秒调用、两秒锁等待、五秒 SQL 上限。

[认证源维护规则](../../.github/instructions/durable-auth-source.instructions.md)与
[注册表维护规则](../../.github/instructions/collaboration-store.instructions.md)记录了锁顺序和
待提交回执归属；不得在已经先锁注册表的路径里反向获取认证源锁。

## 重放、来源代次与最后管理者

重放已有命令 ID 仍须当前 Session 和管理权。沿用 actor/作用域/完整请求摘要、修订冲突和准确 ID
去重；重放只返回历史，不恢复授权、不证明当前状态，本适配器还要求目标来源代次仍存在。
同名重建不能选中旧 Principal 或继承 Grant；自行撤权后，原调用方不能借回执重放恢复管理权。

回归暴露了组合层的最后管理者缺口：注册表仍将“来源账号已删除”的第二名管理者计数，导致最后一个
来源匹配的管理者能够撤销自己；同名新账号也不能充当该旧身份。现在适配器在**新撤权命令的同一事务内**，
核对至少一名剩余的已审计活动管理者仍匹配持久来源账号，否则策略和回执一起回滚。
候选枚举上限 10,000；超限或状态不一致明确失败，不猜测备用管理者。

这只保证来源账号存在且代次一致，不证明有人掌握其凭据或已有活动会话。独立的可信注册表命令
仍是沿用注册表检查的准备层工具；本适配器没有悄悄将它们变成认证接口或封锁它们。
特权 SQL/DDL 可以绕过协议，完整生命周期接入必须在在线切换前关闭这些独立写入路径。

## 仍未开放

- 账号注册、Principal 及初始策略的统一引导事务。
- 账号删除、全部会话撤销和身份退役的统一事务。
- 改密码/TOTP、凭据对账及紧急管理者恢复。
- 会话授权的审计历史/普通资源 API、HTTP/CSRF/UI 接入及有界公开准入。
- 真实账号迁移、旧运行时写入封锁、经过审查的切换/回退及部署验收。

本轮只提供绑定和策略命令，不提供容易被误认为完整生命周期的半套 Retire/删除操作。
在线教学/教师权威流程、会话降级、API/SDK、内核执行及运行服务不变。已有注册表退役仍不撤销旧
Session，普通持久认证源退出也不退役 Principal。

取消、超时或提交响应丢失**不证明回滚**。保留准确命令 ID 和请求对账，仅在仍有有效管理者会话时
显式重试，不换新 ID、不把历史权限当作当前授权。提交前故障测试不证明提交竞争时的恢复能力。

## 验证

[集成测试](../../engine/tests/durable_collaboration_tdd.rs)与
[故障注入](../../engine/tests/durable_collaboration/faults.rs)新增 16 条显式 PostgreSQL 用例和
一条默认关闭连接池用例。缺接口、漏 CI 选择和“无来源管理者仍被计数”均先观察失败后实现/修复。
覆盖显式启用、准确来源代次、不隐式授权、当前管理权/重放、过期/退出/同名重建、跨域、最后管理者、
并发重放、缺审计、抑制写入、延迟提交失败、取消、退出与命令两种顺序、等待后过期及写后来源复核。

本地使用独立 PostgreSQL 16、私有 Unix Socket 和合成账号，**114 条数据库测试全部通过**：
新增组合层 16 条、此前认证源/注册表 76 条、旧认证 22 条。完整默认 Rust 测试 **334 通过、172 忽略**；
上述 114 条另行显式执行，其余 58 条忽略测试未在本切片运行。新增 CI 步骤的 16 条准确选择命令
也在本地逐项通过。`quality-gate.sh --format-only` 通过 **77 条公共测试**及格式、文件长度、版本/
文档同步、API/SDK 契约和工具检查。未运行浏览器/前端构建、真实内核/局域网、联网依赖审计或部署/
迁移/恢复验收；工具检查不代表实际制品验收。

[CI](../../.github/workflows/ci.yml)逐项列出并按准确名称执行默认忽略用例；
