# 项目进度状态

核对日期：**2026-10-26**。产品版本为 **0.6.5**，公共 API 兼容基线仍为 **0.3.0**。
本版在 0.6.4 文本发布／Session 页显示信息保存上增加 Task 绑定连接器、严格 HTTP 及默认关闭的
`--task-text-publication`，不含正文保存或浏览器 TLS 验收；见[0.6.5 报告](../../reports/releases/0.6.5/README.md)，旧制品和分日期证据保留原范围。

Cyanrex 是自部署的**合作与教学平台**。Task 描述要完成的工作；代码只是可选 payload，
不是平台的组织中心。笔记、配置和代码可以共用文本编辑能力，不要求执行、自动评估或 Run。
eBPF 教学保留为首个受支持领域，现有教学流程继续兼容。

主线已具备显式低权限平台宿主和有界私人任务后端；正常浏览器仍编辑本地草稿，
没有把通用 Task 保存到该后端。共享协作、可靠通用执行和已部署局域网验收仍待后续完成。

## 当前运行边界

目前有三条应用路径并存，认证和存储方式不能互换。

| 路径 | 源码已实现 | 边界 |
|---|---|---|
| 教学应用 | 现有浏览器认证、课堂、五个实验、反馈、执行和教师部署管理 | 沿用既有 AuthService 与教学存储；旧 attempt 不是通用 Task 或 Run |
| 本地任务编辑器 | 可选文本 payload、受控编辑器、确认导入及本地 JSON 导出 | 草稿仅在页面内存；没有通用服务端保存、自动保存或浏览器持久化 |
| 显式平台宿主 | Linux 明文／原生 TLS 回环宿主、受限 Session、私人任务、显示信息保存及可选 Task 绑定发布 | 原初始化存储；没有正常应用／文本保存／SDK 切换或局域网监听 |

另有可显式组合的 Rust 存储、HTTP 适配、草稿发布帮助层和文件交付组件。
存在这些组件，不代表正常应用已经挂载它们。
[架构地图](architecture-map.md)负责模块职责，[平台链路](platform-network.md)区分已连接能力和缺边。

### 教学与部署

原教学应用保持教师权威。单人使用时，用户同时是教师，也负责部署管理。
密码／TOTP、Cookie Session、CSRF、学生限制和邀请接入属于既有实例权威。

Linux、WSL2 和 Docker 启动路径继续支持。SSH 工具管理明确选择的预装包，
不是自动裸机安装。启动器目标选择、健康观察、包控制文件检查和页面级部署诊断已有实现。

本地 Engine 仍同时承担控制和特权 Linux 执行。共享内核限额不隔离学生，
注册远程编译工作节点也不授予远程 eBPF 加载能力。
当前运行与验证条件见[安全指南](security.md)、[运行参考](runtime-reference.md)和[测试指南](testing-guide.md)。
[历史验收记录](acceptance.md)仅保留 2026-09-09 的检查点。

### 本地任务内容编辑

`/tasks/new` 持有任务草稿，`/editor` 打开同一容器，eBPF 工作台独立保留。
草稿可以没有 payload，也可以有最多 32 个文本项，每项至多 256 KiB。

父任务草稿持有文件名、语言标记和文本。导入预览、确认和修订／代次检查，
防止过期回调覆盖较新的编辑。多文件导入先经确认，再原子修改草稿；JSON 导入导出也有上限。
导出文件不是服务端提交；离开页面可能丢失未保存内容。

14 种已安装编辑能力配置与合法便携语言标记独立。
合法未知标记导入导出时原样保留，使用纯文本编辑。
JS／TS 及已配置 JSON／HTML／CSS 提供器有浏览器本地辅助；
Rust、Python 和 C／C++ 不意味着已接入 rust-analyzer、Pyright 或 clangd。
目前没有项目文件系统或外部 LSP 传输。

界面支持英语、简体中文、西班牙语、日语和韩语。
英中项目及课程正文与界面翻译分开维护；韩语界面不代表已有韩语课程正文。
操作见[任务内容编辑](editor.md)和[本地文件导入](local-text-file-import.md)。

## 私人平台宿主

0.6.5 源码保留显式 `cyanrex-platform serve-loopback` 和 `serve-loopback-tls`，核对低权限身份、
私有格式 3 输入、原目录／五标记／Artifact 根，不构造教学 AppState。

两种 CLI 保留 0.6.4 已启用的非绑定文本路由；0.6.5 增加默认关闭的 Task 绑定路由，共用同一原存储：

| 方法与路径 | 已实现命令 |
|---|---|
| POST `/platform/v1/session/login` | 有界既有账号密码／TOTP 登录，确认后投影专用 Cookie |
| GET `/platform/v1/session` | 新鲜的当前 Session 状态 |
| POST `/platform/v1/session/logout` | 准确 token 退出；确认成功后清除 Cookie |
| GET `/platform/v1/task-index` | 当前所有者的有界私人任务元数据页 |
| GET `/platform/v1/tasks/{task_id}` | 重开本人任务，支持空内容及已核验的有序文本 |
| POST `/platform/v1/tasks` | 以严格版本／Task ID／标题请求创建空手工 Draft |
| PUT `/platform/v1/tasks/{task_id}/content` | 以预期修订和已有本人准确文本引用替换手工 Draft 清单 |
| POST `/platform/v1/text-artifacts` | 创建私人固定规范文本 Artifact，只返回确认后的元数据 |
| POST `/platform/v1/tasks/{task_id}/text-artifacts` | 显式启用：针对完整本人手动 Draft 基线发布，不修改或挂接 Task |

私人索引只是元数据，不证明每个内容文件仍可读；重开会另行核对准确引用内容。
创建不要求 payload 或代码。换版可修改标题、标签、顺序或引用，不发布新 Artifact 字节。
这些命令不挂载任务状态、目录创建、评估或执行。

默认 CLI 仍是八路由／七响应通道；原构造器仍是七路由／六通道且不启用发布。
只有 `with_task_text_publication_capacities` 或 `--task-text-publication` 才选择九路由／八通道，
全部八容量验证后才拆分同一原存储 Arc。严格 HTTP 固定完整 Task／清单，新文件工作前复核当前所有权。
两个文本连接器各有四个真实 worker（合计八个），全局仍最多 16 连接，不保证 32 请求并发。
完整连接池写入／读取和文件分发路由仍独立。

原生 TLS 增加私有证书／密钥检查、准确 IP SAN 匹配、有界握手工作和 Secure Cookie。
可选服务通知报告已验证的 Ready 和排空前 Stopping。
两种模式都不提供 DNS／局域网宿主、已安装服务、自动重启、代理后端或完整浏览器 Task 流程。
仅有明文回环监听，也不代表 Cookie 安全部署方案已经确定。

0.6.4 收录的 `--session-ui` 默认关闭，七个固定资源／五语言界面，专用 Session 连接显式每页 20 项
私人列表及惰性纯文本／空 payload 重开。严格核作用域／修订／引用／摘要，读取限制仍为索引
128 KiB、内容报文 50 MiB、16,384 帧及解码后 32 × 256 KiB。窄化的手动 Draft 标题／显示标签
保存不改引用／顺序／字节／条数：一次 64 KiB PUT、严格 HTTP 200 元数据回执（128 KiB／4,096 帧），
不代表新鲜正文读取。保存及 dirty／未知离开确认默认取消；十秒只限制等待，不抢占解析／服务端。
失权／上下文变化／pagehide 清私人 DOM并隔离本地工作，不跨 Session 恢复／重放，明确丢弃才可继续。
不接原文保存、新 Artifact、Task 创建／Run、正常 Next 草稿／SDK、新 API 或权限；未知不证明回滚／
重试权。Cookie 不按端口隔离，本机旧 NSS 仍阻塞真实 TLS 浏览器验证。

配置与准确契约从[平台专题索引](reference-index.md)进入。
[回环宿主](platform-loopback-host.md)、[TLS 宿主](platform-loopback-tls-host.md)
和[清单换版](platform-task-replace-connection.md)分别说明运行条件与事务限制。

## 合作平台基础能力

### 身份与当前权限

另行组合的后端已有稳定身份、经审计的成员／部署策略、持久 Session、账号生命周期命令、
显式初始化和只读对账。准备层认证包括有界密码工作、固定 Argon2 参数和逐账号 OTP 原子消费。

不可信资源命令从当前 Session 推导所有者。账号代次、经审计的活跃成员关系、
原认证源／存储绑定以及末尾新鲜的 Session 到期复核都在命令事务内完成。
接收 owner 参数的直接存储是可信基础设施，不认证该 owner，也不是公开权限接口。

显式宿主没有替换教学登录或迁移已有用户。
新 Workspace 所有权不会自动授予其他所有者内容或其他实例的部署控制权。

### 任务与领域定义

手工 Task 不要求领域定义。目录 Task 保留完整准确的冻结定义，定义和 payload 可以独立选择。
不带提供器的元数据目录可有界组合多个领域／包版本，明确选择两项评估绑定齐全或两项都没有。

类型化评估仍要求准确的证据 Schema 和策略引用。
查到定义、payload 合法或 Run 成功都不等于 Task 通过验收。
通用分配、依赖编排、跨用户验收和自动规则执行尚未实现。

### Artifact 与 Review

Artifact 存储支持私人不可变修订、摘要绑定引用和事务元数据／事件。
通用连接池发布／读取 API 仍独立于原绑定宿主；后者单独选择的文本命令沿用原存储绑定。

[原绑定文本发布](platform-text-artifact-connection.md)始于 0.6.4；0.6.5 增加 Task 绑定连接器、严格 POST
及显式宿主开关。两者均固定文本规范并核延期后的准确 head，不接浏览器正文保存或修改 Task。
组合角色的原登录／Task／行锁权限及三项 Artifact INSERT 已足够；新开关不增授权或旧载荷字节核验。

任务内容存储原子更新 Task／清单／outbox 元数据。
现有文本换版在延迟写入前后核对完整旧新引用联合，包括已移除的内容，
并保留不可变 Artifact 文件和先前 Review 历史。

Review 支持针对准确 Artifact 目标／证据的修订化私人人工意见。
它不提供跨用户审阅者授权、通用任务验收、自动评估或 AI 审阅。
完整浏览器保存仍需审阅浏览器认证／传输接入，以及客户端冲突／未知结果处理，
不能仅靠增加一个编辑器按钮完成。

### 草稿发布与恢复

内部导入／规划、仅创建发布步骤、检查点、不可变意图、日志化派发和只读观察，
作为相互独立的能力已有实现。手工与目录路径分别保留自身定义、身份和结果规则。

Unreleased [浏览器侧内容保存尝试](task-draft-publication.md#未发布的浏览器侧既有-draft-保存尝试)
冻结草稿和既有手工 Task 基线、本地计算摘要，再交出单次 Artifact／清单描述，分别记录 pending 结果。
给定确认只证明一致性；不接 fetch、Session／Origin 配置、界面保存或持久恢复。
完成只针对冻结尝试，不自动清除当前本地编辑器 dirty 状态。

这些帮助层不形成整份草稿事务；后续步骤失败后，已确认前缀可能仍保留。
元数据相符不是历史回执。读取意图或检查点不会重建已丢弃尝试，
也不授权重试或根据不可见删除文件。

### 大文件分发

文件链已有严格清单、私有独占暂存、上传逻辑额度、本地回执、分块日志、
整文件字节核验和 Published 元数据。当前发布权限与独立准确接收授权共同约束分享和访问。

显式清单／分块 HTTP 组合及受控客户端，连接元数据、有序块、已验证拼装和宿主选择的保存。
进度和协作式取消是单调用观察。真实 Source／HTTPS 夹具以一次性原生对端测试该链路。

它仍与正常应用交付及回环 Task 宿主分开。
用户保存对话框、SDK 接线、部署后的局域网分发、持久续传／恢复、
物理磁盘策略和桌面点对点互传尚未完成。集中分发仍是首个交付目标。
参阅[文件分发](large-file-distribution.md)和[专题索引](reference-index.md)。

### 执行与集成

教学运行时有本地租约／配额／超时，以及签名 Runner Agent 协议，
支持注册、作业、探针和只编译诊断。Runner Agent 是计算工作节点，
不是 AI 身份、通用 Task 编排或远程内核沙箱。

AI 连接配置与显式选择的 SDK 工具适配，辅助可信宿主工作。
模型传输、密钥、批准和信息披露仍由宿主负责。
目前没有自主 AI 参与者、委派服务、模型传输或可执行插件运行时。

资源 outbox 已存在，但通用持久业务事件投递、游标重放、多 Engine 协调、
持久 Run 和经验证的伙伴集成仍待建设。

## 安全与兼容规则

- 产品版本、API 基线和存储 Schema 独立演进；当前版本不自动安装 Schema，也不认证运行实例。
- Task Schema 2 与内容 Schema 3 需要各自显式安装的命名空间。
  准备层认证要求 Source Schema 2；不兼容旧格式被拒绝，不自动迁移。
- 原绑定操作核对原存储和当前权限，不使用连接池降级或首次目标收编。
  元数据匹配不证明物理身份或历史连续性。
- 写入成功要求确认 COMMIT。取消、超时、断连或交付丢失可能留下未知结果，
  不证明回滚，也不授权盲目重试或补偿。
- 文件系统与 SQL 校验不是一个原子事务、进程硬期限或针对同 Unix 身份／root 的隔离。
  已派发阻塞工作按真实生命周期持有工作额度。
- 教学产品的教师权威不等于通用平台所有私人内容的权限。
  TLS 不增加分享策略、租户隔离或局域网验收。
- 原教学契约与公共 0.3.0 API 基线继续兼容。
  专用平台路由不加入生成的公共 SDK／OpenAPI 表面。
- 更新源码依赖不会修补正在运行的二进制、镜像或生成资源；
  运维仍需重新构建并部署受影响组件。

这些规则也约束下一阶段开发。
具体威胁边界见[安全指南](security.md)，
[能力成熟度](capability-maturity.md)分别记录当前实现评分，不合并为一个全项目完成百分比。

## 下一阶段决策点

近期主线是完成**私人且不以 payload 类型为中心的任务流程**。
原绑定宿主提供了有界服务端入口，还不是完整浏览器产品；建议按此顺序推进：

1. 以浏览器契约接通已审阅的 Task 绑定入口，包括 Cookie 安全 Origin／客户端信任及分开的发布／Task 更新结果。
   保留当前权限与私人文件归属，不直接挂载旧连接池路由，也不从本地草稿 ID 推断权限。
2. 只经单独审阅的契约把可选显示信息保存页进一步接到文本发布。
   保留独立本地草稿、未保存编辑、预期修订、冲突及取消／未知状态。
   本地导出和成功元数据 PUT 必须继续作为不同操作。
3. 用真实认证／存储验证浏览器到服务端全链、竞争编辑、权限拒绝、
   重启行为和未知交付，再称私人保存已完成。
4. 单独增加分享／审阅者授权及定版验收，验证不要求 teacher／student 角色、
   也不强制 Run 的非教学协作流程。
5. 在明确的信任、凭据、部署和兼容决策下推进受保护局域网、
   分发界面和桌面交换；回环 TLS 不能代替它们的验收。

自动恢复／重试、存储迁移、通用 Run 调度、AI 委派和可执行插件需要另行审阅设计，
不应成为接通私人内容流程时的附带改动。上述顺序不承诺日期，也不隐含新版本。
